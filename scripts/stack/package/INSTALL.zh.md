# 安装和测试说明

安装包：{{PACKAGE}}　版本：{{VERSION}}　出包时间：{{CREATED}}　一键部署入口：stack {{ENTRY_VERSION}}

{{RELEASE_NOTE}}

这是一个**测试版**离线安装包。解压到一台 Windows 机器上，改一处配置，双击「开始.cmd」，就把下面四样按顺序起起来：

| 顺序 | 服务 | 缺省端口 | 是什么 |
|---|---|---|---|
| 1 | 数据库 | 8009 | SurrealDB，只给本机的后端和 rs-server 用 |
| 2 | 后端 aios-database | 8022 | 模型树、模型生成、增量更新这些接口；它的根路径就是 plant-ui 网页版 |
| 3 | rs-server | 9098 | 数据服务：元数据网页、提资、孔洞这些接口 |
| 4 | plant3d-web | 3100 | 三维查看的网页（nginx 提供构建好的页面，接口转给本机的后端） |

**装好起来以后不会自动初始化任何库，也不会自动生成模型。** 要哪个库的模型，在 plant3d-web 里初始化，或者在模型树的节点上手动生成；也可以用命令行，见第 5 节。

目标机上不需要装 Rust、Node、git，也不需要管理员权限（只有在防火墙的弹窗里点「允许」要管理员）。

---

## 1. 机器要求

- Windows 10 / 11 或 Windows Server 2019 及以上，64 位。
- 自带的 Windows PowerShell 5.1（系统里本来就有，不用装）。公司用组策略锁死了 PowerShell 执行策略、或者开了「受限语言模式」的机器上，入口跑不了（这类机器没有试过）。
- 内存：四个服务空着跑不到 1 GB。初始化大的库时后端会用到几个 GB，建议 16 GB 以上。
- 磁盘：解压后约 560 MB；数据库的数据和生成的模型放在安装目录下的 `data\`、`work\`，初始化的库越多占得越多。
- E3D 工程目录要在这台机器上读得到（本地盘最好；后端对它只读）。
- 这四个端口没被别的程序占着：8009、8022、9098、3100。被占了就在 `stack.toml` 里换（第 7 节）。
- 浏览器：新版的 Chrome 或 Edge。
- VC++ 运行时已经随包放在 `bin\` 里，不用另装。万一启动时还是提示缺 `VCRUNTIME140.dll` 一类，运行一次 `redist\VC_redist.x64.exe`。

## 2. 安装

### 装之前先看这几条

- **先停掉这台机器上已有的旧版。** 旧的离线包用的也是 8009 / 8022 / 3100 这几个端口。端口冲突时入口会说出是哪个进程占着，不会动它，但也什么都不起。
- **解压的位置**：一个普通的、能写的文件夹，路径短一点（安装文件夹自己的路径短于 180 个字符），不要带双引号和百分号，不要放在 `Program Files` 下面。带空格、带中文的路径可以。
- **起、停、看状态用同一种方式开窗口**：都普通双击，不要有时「以管理员身份运行」。用管理员窗口起的服务，普通窗口核对不了它（入口会告诉你换同样的方式再来，不会动它，记录也不丢）。
- **只放在信得过的内网里测。** 缺省的做法是后端、rs-server、plant3d-web 监听所有网卡，后端的接口没有登录保护，配置向导也在里面（第 7 节）。

### 步骤

1. **解压**到一个文件夹，例如 `D:\plant-stack`。
   如果 zip 是从浏览器或聊天工具里下载的，解压前先右键 zip → 属性 → 勾上「解除锁定」。
2. **生成你的配置**：双击 `开始.cmd`（文件名显示成乱码的话用 `start.cmd`，是同一个东西）。
   第一次它**什么都不起**，只是照 `stack.default.toml` 生成一份 `stack.toml`，然后提示你去改。
   （也可以自己把 `stack.default.toml` 复制一份、改名成 `stack.toml`。不要直接改 `stack.default.toml`：换新一版时它会被盖掉。）
3. **改配置**：用记事本打开文件夹里的 `stack.toml`，只改最上面 `[project]` 这一节：

   | 项 | 填什么 |
   |---|---|
   | `e3d_root` | E3D 工程根目录，它下面是各个项目的文件夹。写成 `D:/AVEVA/Projects/E3D3.1` 这样（用正斜杠） |
   | `name` | 项目名，就是工程根目录下那个文件夹的名字 |
   | `code` | 项目编码（整数） |
   | `e3d_version` | `e3d31` 或 `e3d210` |
   | `mdb` | 用哪个 MDB；`ALL` 是全部 |

   其余的项都已经按包里的东西填好了，一般不用动。用记事本保存时不要改编码。
   **先把这一节改对，再起。** 第一次起的时候这几项会写进后端的配置，以后再改 `stack.toml` 不会自动生效（第 7 节）。
4. **起**：再双击 `开始.cmd`。
   窗口里会一步一步地说在干什么：预检 → 数据库 → 后端 → rs-server → plant3d-web，每起一个查一个，最后给一张状态表和几个地址。
   第一次起大约一分钟以内。看到「全部起好」就可以关掉这个窗口，服务留在后台。
   - 干净机器上第一次起，杀毒软件要先把几个程序扫一遍（后端有两百多 MB），预检可能报「后端程序问版本没有答完」：再双击一次「开始」一般就过了。
   - 第一次起时 Windows 防火墙可能弹窗问要不要允许 `aios-database.exe`、`rs-server.exe`、`nginx.exe` 联网：别的机器也要访问就点「允许」；只在本机用，点哪个都行。服务器版的 Windows 一般不弹窗、直接拦，要别的机器访问得手工放行 8022、9098、3100。
   - 哪一步没过，窗口里会说：是哪一步、看到了什么、日志在哪、下一步怎么办。改好之后再双击一次「开始」，已经起好的不会重复起。
   - 窗口的**最后一行是英文**（批处理文件只能用英文）：`up finished. Everything is running.` 是全部起好；`not everything is running` 是有服务没起——往上找中文的那几段，最常见的是「先不起 rs-server」（第 6 节），这时 plant3d-web 和后端已经能用了。

想先检查一遍、不起任何服务：在这个文件夹的地址栏里输入 `cmd` 回车，然后运行 `stack doctor`。

## 3. 起、停、看状态和日志

| 做什么 | 双击 | 命令行（在安装文件夹里开 cmd） |
|---|---|---|
| 起 | `开始.cmd` / `start.cmd` | `stack up` |
| 停 | `停止.cmd` / `stop.cmd` | `stack down`（先看会停哪些进程、不真停：`stack down -WhatIf`） |
| 看状态 | `状态.cmd` / `status.cmd` | `stack status` |
| 检查一遍 | | `stack smoke` |
| 只检查不起 | | `stack doctor` |
| 全部用法 | | `stack help` |

- `stack status` 给一张表：每个服务的状态、端口、进程号、起的时间、内存、版本；不正常的会说原因和下一步。
- `stack smoke` 分三层查：各服务在跑并通过检查（包括 plant-ui 首页、rs-server 的接口）→ 模型树有根 → 取到一个模型。没有初始化过任何库时，第三层会跳过（它不会为了检查去生成模型）。也可以点名一个节点：`stack smoke -Node 23736/1`，在这个节点上按需生成一次再取；节点所在的库还没初始化时它缺省不做，要再加 `-Force`。
- 停只停这一套自己的进程，从不按进程名停；别的程序占着同样端口的，它不会动。连带收子进程（nginx 的工作进程）时只认确实是它生的。
- **初始化跑着的时候不要点「停止」**：停是直接结束进程，后端正在写的东西会留下半截。等它做完（`stack status`、运维页看得到）再停。
- 机器重启、注销账号，服务都会停，要再双击一次「开始」。远程桌面请「断开」，不要「注销」；不要通过远程命令行会话去起。
- 起和停要用同样权限的窗口（都普通、或者都「以管理员身份运行」）。

日志都在安装文件夹下面：

| 位置 | 内容 |
|---|---|
| `logs\backend\`、`logs\database\`、`logs\rs_server\`、`logs\frontend\` | 每个服务自己的输出，每起一次一个文件 |
| `logs\stack\` | 「开始」「停止」这些命令自己打印过的内容，按天一个文件 |
| `work\backend\logs\` | 后端自己写的日志 |
| `work\nginx\logs\` | nginx 的访问日志和错误日志 |

日志不会自动清理：每起一次多几个文件，nginx 的访问日志一直长。测久了手工删掉旧的就行（服务停着的时候删）。

数据也都在安装文件夹下面：

| 位置 | 内容 |
|---|---|
| `data\surreal\` | 数据库的数据（初始化过的库、生成的模型记录） |
| `data\rvm-check\` | 「核对」（RVM 比对）的产物，每次核对一个子文件夹 |
| `work\backend\` | 后端的配置（`DbOption.toml`）、网格文件、缓存 |
| `work\rs-server\` | rs-server 的配置和运行文件 |

### 出了问题，带回来什么

- `logs\stack\`（入口自己说过的话，带时间和退出码）；
- `logs\<服务>\` 里最新的那个文件；`work\backend\logs\`；
- `run\state.json`（入口记着起了哪些进程，里面没有账号口令）。

**不要带** `work\backend\DbOption.toml` 和 `work\rs-server\DbOption.toml`：里面有数据库的账号口令。服务自己的日志里可能出现数据库的账号名，整个 `logs\` 不要随手往外发。

## 4. 打开界面

在装的这台机器上：

| 界面 | 地址 |
|---|---|
| plant3d-web | http://127.0.0.1:3100/ |
| plant-ui 网页版 | http://127.0.0.1:8022/ |
| 后端的运维页 | http://127.0.0.1:8022/ops.html |
| rs-server 的元数据网页 | http://127.0.0.1:9098/metadata |
| rs-server 的接口说明 | http://127.0.0.1:9098/api/docs |

从别的机器打开：把 `127.0.0.1` 换成这台机器的名字或 IP（防火墙要放行，见第 2 节）。

- plant3d-web 的接口走的是同一个地址下的 `/api`，由 nginx 转给本机的后端，所以换机器、换端口都不用重新构建前端。地址以 `/api` 开头的一律转给后端，包括以 `.json`、`.png` 结尾的。
- plant-ui 网页版首次打开要下载约 95 MB 的程序文件，局域网里要等一会儿。
- plant-ui 网页版里**直连数据库**的功能（房间归属、房间详情这些）只能在装的这台机器上用：数据库只监听本机。
- 换了新一版之后页面看着还是旧的：按 Ctrl+F5 强制刷新一次。（这一版起，页面用的 JSON 配置文件不再让浏览器长期缓存。）

## 5. 模型初始化：缺省不做，要的时候再做

### 不初始化的时候能做什么

- **模型树能看**：模型树是直接读 E3D 库文件出来的，不用初始化。
- **能在节点上手动生成模型**：在模型树的节点上生成，几秒钟就能看到这个节点的模型；后端重启之后要重新生成。后端刚起来的头十来秒（它在做启动）节点上还生成不了，稍等再点。
- **先在节点上生成、以后再初始化同一个库也可以**：这个包里的后端会在初始化之前，把按需生成留在数据库里的东西清掉。
- 后端每次启动会在后台做一件事：给全部设计库预建一份「房间参照模型」，房间树、按房间查询要用它。这不是库的初始化，也不生成构件模型；样例工程（29 个设计库）大约 8 秒。大的工程会久一些，这段时间机器会忙，rs-server 也要等它做完才起（第 6 节）。不要它：在 `stack.toml` 的 `[backend.env]` 里写 `AIOS_SPATIAL_COMPUTE = "0"`（房间相关的功能就不可用了）。

### 「初始化一个库」是什么

把这个库的全部元素解析进数据库，并生成这个库的全部模型。做完之后这个库的模型存在数据库里，后端重启也在，以后可以做增量更新。
第一次初始化任何一个库时，后端会把系统库和字典库（样例工程是 17 个小库）一并处理，这一步不能单独关；连同一个小的设计库大约 15–30 秒。大的库要几分钟到更久，内存也用得多。

### 三种做法

1. **在 plant3d-web 里**：打开「模型生成」对话框（按节点 / SITE 重新生成，或按库初始化更新），勾上要的库，点「初始化 / 更新所选」。做完可以在界面里核对。
2. **命令行**：在安装文件夹里开 cmd，运行

       stack init 7997
       stack init 7997 8000

   库号用空格隔开。它会等做完，逐个库报结果；已经初始化过的库不重复做；哪个库没成，会把后端给的原因说出来。
   初始化完，在浏览器里打开 `http://127.0.0.1:3100/?show_dbnum=7997` 可以直接把这个库的模型整库显示出来。
3. **起的时候顺手做**：在 `stack.toml` 的 `[init]` 里把 `dbnums = []` 改成点名的库号，例如 `dbnums = [7997]`。以后每次「开始」起完服务，会把点了名、还没初始化的库初始化掉。

`[init]` 里的 `auto_new` 不要改成 `true`：改了以后后端一启动就把所有没初始化过的库全部初始化。

大的库初始化超过 10 分钟时，「开始」或 `stack init` 会报超时退出——**初始化还在后端里照常跑着，没有被打断**（看运维页 `http://127.0.0.1:8022/ops.html`）。嫌它报得早：在 `stack.toml` 里加一节 `[timeouts]`，写 `init_sec = 3600`。

## 6. rs-server

- 它排在后端之后起：入口等后端健康、数据库里的「库版本记录」和后端一致，才起它。全新的库：后端做完启动的时候自己写这条记录，样例工程十来秒；入口最多等三分钟。
- 入口关掉了它的「自动升级」。不关的话，它一发现库版本对不上，就会自己去让后端把库清掉重建。现在它只是等着；库版本对上之后自己恢复。
- 它的运行目录是 `work\rs-server\`，配置是那里面的 `DbOption.toml`（第一次起的时候按后端的配置生成：连同一个数据库、同一个项目）。

### 窗口里说「先不起 rs-server：后端的库版本还没对上」

这时 plant3d-web、后端、plant-ui 网页版都已经起好、照常能用，只是 rs-server（元数据网页、提资这些接口）没起；「开始」的退出码是 4，窗口最后一行是英文的 `not everything is running`。入口会接着说是下面哪一种情况：

| 入口说的 | 意思 | 怎么办 |
|---|---|---|
| 库是新的，后端的启动还没做完 | 等得到。大工程第一次起，三分钟可能不够 | 过一会儿再双击「开始」，它只把 rs-server 补起来。每次都等不到：`stack.toml` 加一节 `[timeouts]`，写 `storage_version_sec = 600` |
| 后端的启动已经做完、现在闲着，但它管的库的模型面还没就绪 | **光等不会有**，入口也不会白等。版本记录要等第一次初始化完成的时候才写。配了 `watch_dbnums`（只让后端管几个库）的新库就是这样 | 先初始化要用的库：`stack init <库号>`，或在界面里做；做完再双击「开始」，它会把 rs-server 补起来。在 `stack.toml` 的 `[init] dbnums` 里点了名的，「开始」会自己初始化，初始化完顺手把 rs-server 也起起来 |
| 后端正在忙（有库在初始化）或者正在做库的升级 | 等得到 | 等它做完再双击「开始」；进度看运维页 |
| 库里已经有数据，却没有版本记录 | **等不到**，入口也不会白等。这样的库多半是别的版本的后端用过的数据目录，或者版本记录还没写上的时候初始化失败过 | 下面三种办法选一种 |
| 库里的版本记录比程序要的旧 | **等不到**。这份数据是老一版的后端建的 | 下面三种办法选一种 |
| 后端在设置模式 | 后端的配置还没填完 | 打开 `http://127.0.0.1:8022/` 按向导填完，再双击「开始」 |

等不到的时候，三种办法：

1. **用不着 rs-server**：什么都不用做。不想每次「开始」都看到这段话，在 `stack.toml` 的 `[rs_server]` 一节里写 `enabled = false`。
2. **库里的东西可以重来**（初始化过的库可以再初始化）：`停止` → 把 `data\surreal` 文件夹改个名留作备份 → `开始`。全新的库后端自己会写版本记录；然后再初始化要的库。备份确认用不着了再删。
3. **要留着这个库**：在后端做「升级」。浏览器打开运维页 `http://127.0.0.1:8022/ops.html`，页面顶上有一条数据库架构版本的提示，点里面的「升级数据库」。
   它会把这个 MDB 里的**全部设计库**（不只是初始化过的那几个）逐个清空、重新解析、重新生成模型；库多、库大的工程要很久、很吃内存。全部做完后端才写版本记录；做完再双击「开始」。
   配了 `watch_dbnums`（只让后端管几个库）的，这条路走不通：后端只有把整个 MDB 的设计库都升级过才写版本记录。

**不用另外配置就能用的**：元数据网页和它的接口（`/metadata`、`/api/metadata/*`）、孔洞数据的接口、接口说明页。这几样出包前在开发机上请求过；它别的只读数据库的接口按理也一样，没有逐个试。

**要另外配置才能用的**（没配的时候这些功能用不了，但不影响它起来，也不影响别的功能）：

| 功能 | 要配什么（都在 `work\rs-server\DbOption.toml` 里） | 没配时的样子 |
|---|---|---|
| 登录、从普华系统跳转登录 | MySQL 的普华库：`puhua_database_ip`、`puhua_database_user`、`puhua_database_password` | 登不上；`/get_user` 回 401 |
| 项目地址表 | MySQL 的全局项目库：`ip`、`port`、`user`、`password` | 回「无法连接到数据库」 |
| 把元数据推给数据中心（各专业的「提资」推送） | `plat_url`（平台地址），再加一行 `plat_ukey = "平台令牌"` | 启动日志里写着「平台令牌: 未配置」 |
| 接数据中心的回执和回调 | 对方平台要能访问到这台机器的 9098 端口 | |

改完保存，`stack down` 再 `stack up`。这份配置里有账号口令，不要发给别人。

plant-ui 网页版找 rs-server：入口在 `web\config.json` 里替它写好了 rs-server 的地址，缺省是 `http://<这台机器的名字>:9098`。别的机器解析不了这台机器的名字时，在 `stack.toml` 的 `[rs_server]` 里写 `public_url = "http://<这台机器的 IP>:9098"`，再「开始」一次。

## 7. 常见的改动

- **换端口**：改 `stack.toml` 里对应那一节的 `port`。
- **只让本机访问**：`[listen]` 里 `loopback_only = true`。
  缺省是和现在各处一样的做法：后端、rs-server、plant3d-web 监听所有网卡，同网段的机器都能打开，后端的接口没有登录保护（配置向导、初始化、清理模型、库升级都在里面）；数据库用的是出厂的缺省账号口令，但只监听本机。只适合放在信得过的内网里测试。
  这一项对 plant3d-web（nginx）每次起都生效；对后端和 rs-server，只在第一次起（生成它们的配置）时生效，起过之后再改要照下面「注意」做。
- **不要 rs-server**：`[rs_server]` 里加一行 `enabled = false`。
- **只让后端管几个库**：`[backend]` 里 `watch_dbnums = [7997, 8000]`。

**注意**：后端的配置（`work\backend\DbOption.toml`）只在第一次起的时候按 `stack.toml` 生成，以后以它为准。所以第一次起过之后再改 `stack.toml` 里的 `[project]`、端口、`watch_dbnums`、`loopback_only`，入口会提醒「两边不一样」，但**不会**替你改。要让改动生效：

1. `stack down`
2. 把 `work\backend\DbOption.toml` 和 `work\rs-server\DbOption.toml` 挪走（或删掉）
3. `stack up`

换了项目之后，原来那个项目已经初始化的数据还留在 `data\` 里（按项目编码分开放），不会混。

**后端的配置向导页**（`http://127.0.0.1:8022/setup.html`）可以用：在里面改的东西存在 `work\backend\DbOption.toml` 里，留得住。点「重启」之后后端换了一个进程；入口下一次运行「开始」「状态」「停止」时会把它认领回来（会说一句「认领了后端的进程…」），照常管它。在向导页里改了监听端口的话，`stack.toml` 里 `[backend]` 的 `port` 要改成一样的。

## 9. 换新一版

程序、页面和数据都在同一个安装文件夹里。换新一版时**原地覆盖**，不要另起一个文件夹：

1. 双击 `停止.cmd`，等它说停完。
2. （建议）把 `data\surreal` 文件夹拷一份留底。新后端一旦把库升级过，旧后端就读不了它；没有自动回退，要退回去靠的就是这份留底。
3. 把新的 zip 解压到**同一个文件夹**，同名的文件全部覆盖。
   你的 `stack.toml` 不在安装包里，不会被盖掉；`stack.default.toml`（缺省配置）会换成新的，想知道新一版多了哪些可配的项就看它。
4. 双击 `开始.cmd`。

`data\`（数据库、核对的产物）、`work\`（各服务的配置和缓存）、`logs\` 不在 zip 里，覆盖时不会动：初始化过的库、以前核对的产物都还在。

要知道的几件事：

- **后端和 rs-server 的配置只生成一次。** 新一版配置模板里新加的键到不了已有的配置；「开始」会把缺的键名列出来，要不要照模板抄进去由你定。
- **旧文件不会被清掉。** 新一版里已经没有的文件，覆盖之后还留在文件夹里，不影响使用。
- **退回上一版**：停止 → 把上一版的 zip 解压回来覆盖 → 把第 2 步留底的 `data\surreal` 换回去 → 开始。没有留底又已经被新后端升级过的库，旧后端读不了，只能从头初始化。
- 浏览器里页面看着还是旧的：Ctrl+F5。

一定要换一个文件夹的话：把旧文件夹里的 `data\`、`work\` 和 `stack.toml` 搬到新文件夹再起。这时「开始」会提醒 `work\backend\DbOption.toml` 里「核对」的产物目录（`[rvm_check] work_dir`）还指着旧位置，照它给的提示改那一行。

## 10. 卸载

1. 双击 `停止.cmd`，等它说停完。
2. 把整个安装文件夹删掉。

它没有装成 Windows 服务，没有写注册表，没有开机自启。安装文件夹之外只留下两样小东西，可以不管，也可以手工清掉：

- `%LOCALAPPDATA%\gen-model\writer-locks\` 下的锁文件（后端用它防止两个后端同时写同一个库；后端退出后就没用了）；
- 第一次起时如果在防火墙弹窗里点过「允许」，Windows 防火墙里会留下那几条放行规则。
