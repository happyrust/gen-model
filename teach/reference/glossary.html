B · 课 02：ref_rev 反向引用级联

B1 · 术语表

术语含义
ref_revSurrealDB 图边表。in=引用方、out=被引用方，边 id 是两端复合主键（重复写幂等）。记住：存的是正向边，反着查。
反向引用 back-refE3D 原生的存储型逆指针（SPBREF/SCBREF/TABREF/GOBREF/HDBREF/DBREF）。离线解析取不到 → 才要自建 ref_rev（ADR-003）。
DependencyCascadeclassify_attribute_effect_with_meta 的属性效果分类之一，也是进不进 ref_rev 的唯一门槛——和「哪些变更要级联」共用同一份定义。
进索引的属性curated 清单：CATR SPRE SPREF PRTREF SPCO SCOM DESP GMREF TMPL…；A2 兜底：schema att_type == ELEMENT 的引用属性。OWNER 故意排除（层级归 owner 图管）。
引用闭包（传递）load_ref_reversal_closure 的逐跳 BFS 结果，产出 HashMap<被引用方, [引用方…]>。必须是传递的，否则会断在没有交付单元的目录中间体上。
最小交付单元 MDU默认 BRAN/HANG/SUPPO/EQUI；delivery_unit_types 可整体取代、append_delivery_unit_types 可追加；WORL/WORLD/SITE/ZONE 恒被拒。
生成根交付单元根（最近的 MDU 自身或祖先）或正常颗粒根（significant owner）。一个变化元素归一到恰好一个根，同一根一批次只生成一次。
direct / cascaded同一交付单元上的两种命中计数：元素自己被改 vs 被引用关系带出来。两者都会置 will_generate，但分开计数便于预览时区分。
搬迁 moved_out / moved_inOWNER 变化跨了交付单元：旧根与新根两端都要重生成。
CascadeExpand读 ref_rev 失败时登记的持久待办；下次 drain 由 expand_live_reverse_cascade 补出 RegenRoot。级联不丢，只是推迟。
四类模型工作regen_root / transform / delete_cleanup / cascade_expand，按 (dbnum, action, target_refno) 去重，at-least-once：模型失败不回滚数据与水位。
ref_rev_rebuild全量重建用的暂存表；全部扫完写完后单事务换表，重建失败不会把线上索引搞成半空。
TABITETable Item，表项（TABGRO 表组 → CTABLE/TABLE → TABITE 一行）。noun hash 0x4F3C0B8，在 parse.rs 里全名 TABITEM。五个几何标志全 false、graphics_behaviour=0，自己完全不产生几何。
SPCO / SCOM规格元件 / 目录构件。SPCO 不在 MDU 集合里 ⇒ 级联走到它必须继续上溯，不能止步。
wnoevtwant-no-event：属性被写时要不要广播变更事件。值在 dabacon 字典里，不在二进制里。
applied_sesno某 dbnum 已成功落库并生成的会话号上界。写 ref_rev 失败不阻塞它推进。

B6 · 四条路径（一屏记住）

【写】落库之后 · 推水位之前 op ─┬ Deleted → DELETE pe:X->ref_rev（只清，不再插） └ Add/Modified → 读后态 att_map → 逐属性判 DependencyCascade → 去重 / 排自引用 → DELETE 全部旧出边 → INSERT RELATION 失败 ⇒ 只记 warning，不阻塞数据批次与 applied_sesno（下次触及整体重写而自愈） 【查】落库之前（此时索引仍是前态） seeds = 本窗口所有「影响模型」的变更元素 逐跳 [frontier]<-ref_rev ≤ 8 跳 / ≤ 50000 引用方 / 500 个一批 ⇒ HashMap<被引用方, [引用方 …]> 【用】build_unit_rollup 的止步规则 referrer → resolve_change_unit（post 态；解析不出则回退 pre 态） ├ 命中交付单元 → cascaded += 1，【止步】不再向上穿透 ├ 命中普通根 → 还有上层引用者？有 → 继续压栈；无 → cascaded += 1 └ 没有根 → 还有上层引用者？有 → 继续压栈；无 → 什么都不做 ⇒ will_generate 的单元产出 RegenRoot（按 (dbnum, action, target) 去重入库） 【坏】写与读的策略是不对称的 写失败 → warning，可自愈 读失败 → 保留所有 direct 根 + 每个受影响元素落一条 CascadeExpand 待办 下次 drain：expand_live_reverse_cascade 补出 RegenRoot 冷导入 → rebuild_reverse_index：全量写 ref_rev_rebuild 暂存 → 单事务换表

D · 课 03：批量模型生成
