DB_Noun 类型描述符速查

PDMS/E3D 里每一种元素类型（EQUI、PIPE、ELBO…）在内存中对应一个 DB_Noun 对象。它不是元素本身，是元素类型的描述符——回答"这类东西是不是图元、怎么画、能不能改"。

证据基线：/Volumes/DPC/reverse/core.dll · MD5 099b9237a64002e46b918c18841f547a · 15,330,816 B · imagebase 0x10000000

版本警告 本页所有偏移量来自 E3D 2.1 / PDMS 12.1.1 的 core.dll。 学习记录 0003 记录的是 E3D 3.1，偏移完全不同（见第 6 节）。 字段号（dabacon field ID）两个版本一致，偏移量不一致——跨版本移植请用字段号，不要用偏移。

1. 一句话对象模型

DB_Noun = 类型描述符，全进程每种类型一份，通过 hashValue 在全局字典里索引。元素实例（DB_Element）通过 type() / actualType() 指回自己的 DB_Noun。

DB_Element 实例 DB_Noun 描述符（每类型一份） ┌──────────────┐ type() ┌────────────────────────────┐ │ /VESSEL-1 │ ──────────► │ hashValue = <EQUI 的 hash> │ │ (一个具体设备) │ │ primitive? graphics? … │ └──────────────┘ │ psOwner/psNext/psFirstMember│ ← 类型层级，不是元素层级 └──────────────┬─────────────┘ │ (hash, fieldId) ▼ dabacon 数据字典（外部文件）
易错点 psOwner / psNext / psFirstMember 挂在 DB_Noun 上，描述的是类型之间的层级（WORL→SITE→ZONE 这种 schema 关系），不是你数据库里某个具体设备的父子关系。要遍历实例树请用 DB_Element 侧的 API。

2. 取值机制：数据不在二进制里

所有"这类元素是什么性质"的问题，最终都走同一个原语——按 (类型 hash, 字段号) 去 dabacon 数据字典现查：

BOOL __thiscall DB_Noun::internalGetField(DB_Noun *this, int fieldId, bool *out)
{
  v4 = *((_DWORD *)this + 28);          // 0x70 baseType 指针
  v8 = *(_DWORD *)(v4 + 116);          // baseType->hashValue (0x74) = 字典主键
  a2 = 0;
  sub_1084F1A5(&v8, &fieldId, &a2, &v6);  // FORTRAN dabacon 查字段
  DB_Noun::setErrorFromFortran(this, v6);
  *out = a2 & 1;
  return v6 == 0;
}

?internalGetField@DB_Noun@@IBE_NHAA_N@Z @ 0x10457890（bool 版，101 B）

注意主键取法：不是直接用 this->hashValue，而是先取 0x70 的 baseType 指针、再读它的 hashValue。对普通类型 baseType == this，两者等价；对 UDET（用户自定义类型）才分叉——这也正是 isUDET() 的判据。

confirmed 类型语义不编译在 core.dll 里，而是 dabacon 字典里的数据。改字典就能改行为，不用换 DLL。core.dll 只实现"怎么问"的逻辑。

3. 两条互相独立的懒加载链

常用属性不会每次都查字典，而是首访时批量灌进对象、之后读缓存。有两条链，各有各的标志位和加载函数，互不触发：

链标志位加载函数覆盖字段
主链0x78 dataLoadedReadData() @ 0x10457D00层级指针、画法、权限位等 ~20 个
DAB 链0x79 dabLoadedReadDataDab() @ 0x10454F50目前只见 primaryList (0xA4)
 
// 主链：绝大多数访问器长这样
int DB_Noun::psOwner(DB_Noun *this) {
  if ( !*((_BYTE *)this + 120) )   // 0x78 dataLoaded
    DB_Noun::ReadData(this);
  return *((_DWORD *)this + 38);     // 0x98
}

// DAB 链：注意标志位和函数都不一样
bool DB_Noun::primaryList(DB_Noun *this) {
  if ( !*((_BYTE *)this + 121) )   // 0x79 dabLoaded
    DB_Noun::ReadDataDab(this);
  return *((_BYTE *)this + 164);     // 0xA4
}

6. 三个陷阱

陷阱 1 isValid() 的语义是反的： 
BOOL DB_Noun::isValid(DB_Noun *this) { return *((_DWORD *)this + 29) == 0; }
它在 hashValue == 0 时返回真。按字面"有效则真"去用会全盘反掉。语义上它更接近 isNull／"未解析出类型"。 ReadData() 里正是 hashValue == 0 这一支走 "Unknown Element Type"。
陷阱 2 0xA4 夹在几个层级指针（0x98–0xA8）中间，但它不是指针，是 primaryList 布尔，而且走 DAB 链。按"层级指针区"整块解释会解释错。
陷阱 3 偏移不能跨版本线性平移。2.1→3.1 的差值不是常数：早期字段差 24 B，中段 44 B，尾部到 56 B——说明中间有多处增删。想跨版本只能认字段号。

8. 复现命令

本页数据全部由 ida-bridge headless 会话产出，可原样重跑：

# 1. 起桥 + 挂已分析好的库
ida-bridge server start
ida-bridge supervisor start-idalib --idb /Volumes/DPC/reverse/core.dll.i64

# 2. 查方法清单（SQL 走的是 IDA 索引，不用写 IDAPython）
ida-bridge exec <client-id> --sql \
  "SELECT name, start_ea FROM funcs WHERE name LIKE '%DB_Noun%'"

# 3. 反编译单个访问器
ida-bridge exec <client-id> -c "
import ida_hexrays, ida_name
ida_hexrays.init_hexrays_plugin()
print(str(ida_hexrays.decompile(ida_name.get_name_ea(0,'?psOwner@DB_Noun@@QBEHXZ'))))"

# 4. 用完记得放开，否则 IDA GUI 打不开同一个库
ida-bridge supervisor stop <client-id>
注意 ida-bridge 默认永不自动保存。只读查询零风险；要落库改动必须显式 ida-bridge supervisor save <client-id>。
