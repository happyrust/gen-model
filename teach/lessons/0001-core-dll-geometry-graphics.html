几何体如何被识别，关联模型如何被生成

读懂 core.dll 两件事：① 它怎么判断"哪些元素是几何体类型"；② 它怎么把"设计元素 → 目录几何 → 图形"这条关联模型链跑出来。全部结论都配 地址 反编译 证据，并用一个弯头(ELBO)端到端举例。

预计 15–20 分钟 · 目标：D:\AVEVA\Everything3D3.1\core.dll（32 位）· 工具：ida-pro-mcp（会话 core31-retrace）

1. 一张图看全貌：三层架构

core.dll 本身不做像素/网格渲染，它是"编排层"。真正干活的分给两个外部库：几何数学给 libgeom，绘制给 sgl5NET。

先记三个词 DB_Noun＝元素"类型描述符"（schema 对象）；SPREF＝设计元素指向目录构件的"规格引用"；GMSET＝目录里装 3D 图元(SCYL/SBOX…)的"几何集"。全课围绕这三个词展开。

2. 第一问：怎么判断"几何体类型"

关键结论：类型判定是数据驱动的，不是给每种类型写死 if。E3D 里每种元素类型都是一个整数 noun 码（如世界 NOUN_WORL），由字典库(dabacon schema)描述成一个 DB_Noun 对象。要不要当几何体、按哪种画法，全看这个对象上的标志位。

2.1 是不是"图元"？—— DB_Noun::primitive()

0x58da280

bool DB_Noun::primitive(DB_Noun *this){
  bool v2 = 0;
  DB_Noun::internalGetField(this, 659518, &v2);   // 读 schema 布尔字段 #659518
  return v2;                                     // 字段号本身来自字典库
}

它不判断"BOX 还是 CYL"，而是去问 schema 里的一个布尔字段 #659518：这个类型是不是几何图元。字段值由字典库决定 —— 这就是"数据驱动"。

2.2 按哪种画法？—— DB_Noun::graphicsBehaviour()

0x58d9760

int DB_Noun::graphicsBehaviour(DB_Noun *this){
  if(!*((BYTE*)this + 96)) DB_Noun::ReadData(this);  // 首次访问才从字典懒加载
  return *((DWORD*)this + 45);                        // 返回 this+0xB4 的"图形行为"枚举
}

返回一个枚举（缓存在对象偏移 0xB4），告诉后续图形代码"这种类型应当怎样表示"。上层就是按这个枚举分派不同画法。

2.3 其它分类器（都挂在 DB_Noun 上）

方法返回含义
primitive()bool是否几何图元（字段 #659518）
graphicsBehaviour()int图形行为枚举（决定画法，this+0xB4）
geomset()bool是否 GMSET 目录几何集类型
extrusion()bool是否挤出(extrusion)类型
isPointsetPoint()bool是否点集中的点(P-point)
hashValue() / findNoun(int)int / noun*按 noun 码定位类型描述符
小例子 · 两种元素的判定

一个 BOX（设计图元）：其 noun 的 primitive() 返回 true，graphicsBehaviour() 给出"实体图元"画法 → 直接用自身几何。
一个 EQUIPMENT（容器）：primitive() 返回 false → 它自己不是几何体，几何来自其成员（NOZZLE 等）或目录引用。

已确认（反编译实测） primitive() 读字段 #659518、graphicsBehaviour() 返回 this+0xB4 枚举、以及 geomset()/extrusion() 等分类器均在 core.dll 内实测存在。

3. 回顾：图形刷新链（上节课）

类型判完、几何进了段之后，靠这条链把画面刷新出来：

void DLL_PMLCommand::GraphicsUpdate(){ int sel = -1; FZXUPD(&sel); }   // PML 命令 "GRAPHICS UPDATE"

4. 第二问：关联模型怎么生成

"关联模型" = 把一个设计元素、它引用的目录几何、以及设计参数组合起来，生成实际图形。分四步理解。

4.1 关联的载体：SPREF 规格引用

设计元素通过 PSPREF/FSPREF 属性（在 core.dll 里是 ATT_PSPREF/ATT_FSPREF，类型 DB_Attribute）指向目录构件（catalogue component）。这就是设计侧与目录侧的"关联"。

已确认 字符串/符号 PSPREF、FSPREF、?ATT_PSPREF@@3QBVDB_Attribute@@B、?ATT_FSPREF@@… 在 core.dll 内实测存在。

4.2 目录侧：SPCO → GMSET → 图元

目录构件（SCOM/SPCO）带一个几何集 GMSET（DB_Noun::geomset()）。GMSET 里是一组 3D 图元，定义"这个构件画成什么样"以及碰撞包围体：SCYL 圆柱SBOX 方盒SSPH 球LCYL…

AVEVA 官方文档 "A GMSET is a grouping of 3D primitive elements … It specifies the dimensions, orientation and obstruction geometry of each primitive."（GMSET 文档）每个图元有 OBST（碰撞级别）、LEVEL、CLFLA、TUFLA 等标志，其中 CLFLA/TUFLA 控制"单线(中心线) / 双线(实管)"两种表示是否绘制。

4.3 参数化：DESPARAM / PARA[n] 驱动尺寸

GMSET 图元的尺寸不是常数，而是引用设计参数。设计元素的 Desparam（PARA[]）把值灌进去，图元才有真实尺寸。官方例子：

NEW GMSET /GSE1
NEW SCYL  PAXI -Y  PDIS (PARA[5])  PDIA (PARA[2])  PHEI (-2*PARA[5])  OBST 2
NEW SCYL            PHEI (PARA[6])  PDIA (PARA[4])                     OBST 2
NEW SCOM  GTYP ELBO  ...  /GSE1     // 构件(generic type=ELBO) 引用几何集 /GSE1
PARAM 20 19 5 ...                    // 组件参数：填进 PARA[1..n]

来源：AVEVA Constructing 3D Geomsets / Creating Catalog Components。

4.4 图形容器：FZ3SGL 建"视图 + 段"

sub_5297141 · trace 标签 fm3dcanv/FZ3SGL

GLVCRE(&view, ...);                 // sgl5NET：创建视图
HPUTI1(elem, ATT_view, &view);      // 视图句柄存回元素属性
GLVSIZ(&view, w, h);                // 视图尺寸
GLSVCR(&view, 140,140,1,1);         // 创建段(display list)
FQGVCO(elem, ctx);  GLVSEG(&view, ctx);   // 绑定段到视图
GLSVSE(&view,{0,2000}); GLSVSA(...); GLSVBO(&view);  // 段范围/包围盒

几何最终装进这些 SGL 段（每个可绘制对象一段），随后 GLUPDA 一次性刷新。

合理推断（实测+文档） core.dll 引入的 sgl5NET 只有"视图/段管理 + GLUPDA"，没有逐三角推送 API，core 里也无逐图元 facet 调用 → 图元→facet 的三角化在 FORTRAN 几何引擎(DBPRIM/SMODUL)与 sgl5NET 内部，两侧以图形元文件(metafile)交换（含 FACET/FRAME/ZCOORD 的令牌字典由 sub_5621F20 解析）。精确三角化算法不在 core.dll。

5. 端到端例子：一个弯头 ELBO 上屏

把上面两问串起来。假设模型里有一个弯头组件（generic type = ELBO）：

  1. 取类型：由元素拿到它的 DB_Noun。问 primitive() → false（弯头不是原生图元），问 graphicsBehaviour() → "目录构件"画法。
  2. 找关联：读元素的 SPREF(PSPREF/FSPREF) → 定位到目录构件 SPCO（GTYP=ELBO）。
  3. 取几何集：从 SPCO 跟到它的 GMSET /GSE1（geomset()==true），里面是两段 SCYL（弯头两臂）。
  4. 灌参数：把元素 Desparam 的 PARA[2],PARA[4],PARA[5],PARA[6] 代入 SCYL 的 PDIA/PHEI/PDIS → 得到真实尺寸的两段圆柱。
  5. 看画不画：按 LEVEL/CLFLA/TUFLA 决定用"实管(双线)"还是"中心线(单线)"表示。
  6. 三角化：libgeom 算方向/位置/圆弧，几何引擎把参数化 SCYL 展开为 facet（metafile FACET 令牌）。
  7. 装段：FZ3SGL 已建好视图与段（GLVCRE/GLSVCR/GLVSEG），facet 进入该元素的 SGL 段。
  8. 刷新：GLUPDA flush → 屏幕出现弯头；RIO_OutputListener::SendUpdate 通知其它视图重绘。
关键直觉 弯头的"形状"不存在设计元素里，而是"目录形状模板(GMSET) + 设计参数(PARA[])"在绘制时现场展开出来的。改一个 PARA 或换一个 SPREF，形状随之变。

7. 落到 gen-model：你该怎么做

  • 类型判定：不要为每种 noun 硬编码；像 core 一样用元数据表（你已有 all_attr_info.json/字典）标注"是否几何 / 画法类别"，代码只按标志分派。
  • 关联模型：复刻 SPREF → SPCO → GMSET → PARA[] 展开图元 这条链（对应 src/fast_model/cata_model.rs / prim_model.rs）；draw 与否看 LEVEL/CLFLA/TUFLA。
  • 增量更新：对齐 core 的"标记脏 → 只重建受影响元素的段 → flush"模型（对应你的增量管线）。
