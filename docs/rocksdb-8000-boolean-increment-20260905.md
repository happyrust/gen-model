# AMS 8000 设备布尔挖孔实测

2026-09-05，继续使用真实 RocksDB 测试实例（18049 / 18050，命名空间 `rocks8000_20260905`）和独立 AMS 项目副本。设备为 `/1-LNR-Q005-PJ`（24384/24776）。本轮不修改共享原始项目。

## 用例与证据

在设备下添加临时 BOX `/CODEX_ROCKS8000_BOOL_BASE`（24384/26292），尺寸 1000 × 1000 × 400 mm，局部位置 E1500。其下添加 NBOX `/CODEX_ROCKS8000_BOOL_CUT`（24384/26293），高度 600 mm，贯穿母体。所有证据位于 `output/rocksdb-8000-20260905/equi-increment/`。

| 会话 | 用例 | 验证结果 | 证据目录 |
|---|---|---|---|
| 293 | 无孔基线 | 体积 400,000,000 mm³；与 RVM 一致 | boolean-baseline |
| 294 | 新增 300 × 300 贯穿孔 | 自动增量未及时发布，模型仍为实心；判失败 | boolean-hole-observed |
| 294 | 重启测试服务后独立检查生成结果 | 体积约 364,000,000 mm³；孔内射线穿透；通过 | boolean-hole-regenerated |
| 295 | 孔宽 300 → 500 mm | 自动增量通过；体积约 340,000,000 mm³ | boolean-widen-observed |
| 296 | 孔中心沿局部 E 移动 150 mm | 自动增量通过；体积不变，孔位置探针通过 | boolean-move-result |
| 297 | 删除 NBOX，填回孔洞 | 自动增量通过；恢复 400,000,000 mm³，射线命中材料，UI 孔洞消失 | boolean-filled-result |
| 298 | 删除临时母体 BOX | 自动发布收敛；仅剩原始 BOX，数量及网格边界与 RVM 一致 | boolean-restored-result |

初次挖孔的失败现场：RVM 体积约 363,999,639.5 mm³，PlantMesh 仍约 400,000,000 mm³；孔内探针在 RVM 中命中 0 次，在 PlantMesh 中命中 2 次。模型发布凭证仍在 293，目标已是 294。该失败与上一轮的模型发布停滞一致，不能用重启后的成功替代自动增量验收。

重新生成后的孔洞、扩孔和移动都使用真正的布尔烘焙网格（96 个索引），而不是用负体单独显示来模拟挖孔。网格哈希随扩孔和移动改变。Plant UI 中已实际观察到贯穿孔和孔洞位置变化。

## 对比方法

`compare_equi8000_boolean.py` 读取生产 `.mesh` 文件，用模型接口的实例变换和世界变换得到几何；独立读取 E3D 导出的 RVM 世界面片。转到母体局部坐标后比较：

1. 有向三角面累加得到的封闭体积，对照 RVM 和解析体积 `(1000×1000 - 孔宽×300)×400`。
2. 沿局部 Z 穿过孔内部、孔两侧材料及远端材料的射线命中数量。孔内部应为 0，材料应为 2。
3. 移孔时增加原孔边界附近的材料探针，避免仅凭体积不变误判通过。

通过样本中 PlantMesh 与 RVM 的相对体积误差小于 `1e-6`，设定容差为 `1e-5`。这覆盖矩形贯穿孔的体积和选定穿透路径，尚不代表圆孔、盲孔、相交多孔或全部曲面拓扑已验证。

## 脚本

- `scripts/equi8000_boolean.py`：solid / hole / widen / move / fill / restore，E3D SAVEWORK 真正保存到独立副本。
- `scripts/equi8000_live.py`：capture 保存数据库、API、RVM 证据；capture-now 保留尚未收敛的现场。
- `scripts/compare_equi8000_boolean.py`：指定阶段、孔宽、孔中心偏移；断言失败时返回非零。

脚本当前绑定本次测试对象引用号；阶段目录拒绝覆盖，重跑需使用新的证据目录并更新对象引用号。此轮增加了测试脚本，没有修改布尔生成算法。
