# PDMS 增量更新系统文档

## 概述

PDMS增量更新系统是一个实时监控和处理数据库文件变化的核心组件。该系统能够自动检测数据库文件的修改，并执行相应的增量更新操作，确保数据的一致性和实时性。

## 系统架构

### 核心组件

1. **IncrementInfo** - 增量更新信息结构体
2. **AiosDBManager** - 数据库管理器，负责执行增量更新
3. **PdmsWatcher** - 文件监控器，监测文件系统变化
4. **PdmsIO** - 数据库IO操作接口

### 主要功能模块

- **文件监控模块**: 实时监控指定目录中的数据库文件变化
- **增量检测模块**: 比较文件会话号与数据库记录，确定需要更新的范围
- **数据更新模块**: 执行实际的数据库更新操作
- **模型同步模块**: 处理几何模型和变换的更新
- **远程同步模块**: 通过MQTT协议进行跨地区数据同步

## 核心数据结构

### IncrementInfo

```rust
#[derive(Debug, Default, Clone)]
pub struct IncrementInfo {
    /// 元素的引用编号
    pub refno: RefU64,
    /// 数据库编号
    pub db_no: i32,
    /// 元素的属性映射
    pub attr: NamedAttrMap,
    /// 子元素的引用编号列表
    pub children: RefU64Vec,
    /// 元素的操作类型(增加/修改/删除)
    pub operation: EleOperation,
}
```

该结构体包含了增量更新所需的所有信息，包括元素标识、属性数据和操作类型。

### 操作类型判断方法

- `is_modified()`: 检查元素是否被修改
- `is_deleted()`: 检查元素是否被删除  
- `is_added()`: 检查元素是否为新增

## 主要功能流程

### 1. 系统初始化 (`init_watcher`)

#### 流程步骤:
1. **目录扫描**: 遍历所有监控目录中的数据库文件
2. **文件过滤**: 根据配置过滤需要处理的数据库类型和编号
3. **会话号比较**: 比较文件最新会话号与数据库记录的会话号
4. **增量检测**: 识别需要进行增量更新的文件
5. **压缩包生成**: 为启用MQTT功能的文件生成CBA压缩包
6. **批量更新**: 执行所有检测到的增量更新操作

#### 关键配置:
- `manual_dbnums`: 手动指定的数据库编号列表
- `exclude_dbnums`: 需要排除的数据库编号列表
- `CHECK_DB_TYPES`: 支持的数据库类型列表

### 2. 实时监控 (`async_watch`)

#### 监控机制:
- 使用异步文件系统监控器监测文件变化
- 过滤只关心数据内容变化的事件类型
- 实时扫描变化文件的数据库头部信息
- **直接与数据库比较**，不依赖本地缓存
- 自动触发增量更新流程

#### 重要改进:
- **移除缓存依赖**: 不再依赖 `watcher.headers` 缓存数据
- **实时数据库查询**: 每次都直接查询数据库获取最新会话号
- **统一过滤逻辑**: 使用 `should_process_database()` 方法统一处理文件过滤

#### 事件处理:
```rust
// 监控的事件类型
notify::EventKind::Modify(notify::event::ModifyKind::Data(_))
| notify::EventKind::Modify(notify::event::ModifyKind::Any)
| notify::EventKind::Create(notify::event::CreateKind::File)
| notify::EventKind::Remove(notify::event::RemoveKind::File)
```

### 3. 增量更新执行 (`execute_incr_update`)

#### 更新流程:
1. **文件解析**: 打开PDMS IO对象并解析数据库文件
2. **元素收集**: 收集指定会话号范围内的增量元素
3. **数据库更新**: 将元素数据更新到数据库中
4. **模型处理**: 执行相关的几何模型和变换更新

### 4. 模型更新处理 (`process_model_updates`)

#### 更新类型:
- **几何体更新**: 当元素的几何属性发生变化时
  - 新增操作: 直接生成新的模型数据
  - 修改操作: 删除旧的inst_relate数据，重新生成模型
  - 删除操作: PE已加删除标记，无需额外处理

- **变换更新**: 当元素的变换属性发生变化时
  - 更新该元素及其子树中所有有inst_relate的节点的world transform

#### 批量处理:
- 使用HashSet收集需要处理的refnos
- 分批执行数据库操作，避免SQL语句过长
- 优化查询，直接获取有inst_relate的几何节点

## 数据库操作

### 会话号查询

系统提供两种会话号查询方式:

1. **按文件名查询** (`query_latest_sesno_by_file_name`)
2. **按数据库编号查询** (`query_latest_sesno_by_dbnum`)

### 批量数据更新

- 使用分块处理机制，每次处理200个JSON对象
- 支持批量SQL执行，提高更新效率
- 错误处理和回滚机制确保数据一致性

## 远程同步机制

### MQTT同步 (需要启用mqtt功能)

#### 同步条件:
1. 文件发生实际的增量更新
2. 文件属于配置的地区数据库范围
3. 文件哈希在数据库中不存在相同记录

#### 同步流程:
1. 生成文件的CBA压缩包
2. 计算文件哈希值
3. 检查是否为新的变化
4. 发布MQTT同步消息
5. 在本地数据库记录同步信息

### 防重复机制

系统通过以下机制避免重复同步:
- 文件哈希比较
- 地区标识检查  
- 时间戳排序
- 本地记录验证

## 技术实现细节

### 会话号(Session Number)机制

会话号是PDMS增量更新的核心概念，用于标识数据库中元素的版本：

- **递增性**: 每次数据修改都会产生新的会话号
- **唯一性**: 同一数据库中的会话号是唯一的
- **连续性**: 会话号通常是连续递增的整数

### 文件监控实现

```rust
// 监控事件过滤
let data_changed = matches!(
    event.kind,
    notify::EventKind::Modify(notify::event::ModifyKind::Data(_))
    | notify::EventKind::Modify(notify::event::ModifyKind::Any)
    | notify::EventKind::Create(notify::event::CreateKind::File)
    | notify::EventKind::Remove(notify::event::RemoveKind::File)
);
```

### 数据库查询优化

#### 会话号查询优化
```sql
-- 按数据库编号查询最新会话号
math::max(array::flatten([
    SELECT VALUE sesno FROM dbnum_info_table WHERE dbnum = {dbnum}
]));
```

#### 批量inst_relate查询
```sql
-- 获取子树中所有有inst_relate的节点
array::distinct(array::flatten(
    select value [
        if record::exists(type::thing('inst_relate', record::id(id))) { [id] } else { [] },
        array::flatten(
            select value if record::exists(type::thing('inst_relate', record::id(in))) { [in] } else { [] }
            from [pe_keys]<-pe_owner<-(?)<-pe_owner<-(?)<-pe_owner<-(?)
            where record::exists(in.id) and !in.deleted
        )
    ] from [pe_keys]
))
```

### 内存管理策略

1. **分块处理**: 使用`JSON_CHUNK_COUNT = 200`控制批处理大小
2. **流式处理**: 避免一次性加载大量数据到内存
3. **及时释放**: 处理完成后立即释放大对象的引用
4. **缓存策略**: 合理使用头部信息缓存减少重复解析

## 故障排除

### 常见问题及解决方案

#### 1. 文件监控失效
**症状**: 文件修改后没有触发增量更新
**原因**:
- 文件权限问题
- 监控目录配置错误
- 文件系统不支持

**解决方案**:
```bash
# 检查文件权限
ls -la /path/to/database/files

# 验证监控目录配置
grep "watch_dirs" config.toml

# 测试文件系统事件
inotifywait -m /path/to/database/dir
```

#### 2. 数据库连接超时
**症状**: 查询数据库时出现超时错误
**原因**:
- 网络延迟过高
- 数据库负载过重
- 连接池配置不当

**解决方案**:
```rust
// 增加连接超时时间
let db_config = DatabaseConfig {
    timeout: Duration::from_secs(30),
    max_connections: 10,
    ..Default::default()
};
```

#### 3. 内存溢出
**症状**: 处理大文件时系统内存不足
**原因**:
- 批处理大小过大
- 没有及时释放内存
- 并发处理过多

**解决方案**:
```rust
// 减小批处理大小
const JSON_CHUNK_COUNT: usize = 100; // 从200减少到100

// 增加内存释放点
drop(large_data_structure);
```

#### 4. MQTT同步失败
**症状**: 远程同步消息发送失败
**原因**:
- MQTT服务器不可达
- 认证信息错误
- 网络防火墙阻拦

**解决方案**:
```bash
# 测试MQTT连接
mosquitto_pub -h mqtt.server.com -t test -m "hello"

# 检查防火墙设置
iptables -L | grep 1883

# 验证认证信息
mosquitto_sub -h mqtt.server.com -u username -P password -t "#"
```

### 性能调优建议

1. **数据库优化**:
   - 为会话号字段创建索引
   - 定期清理过期数据
   - 使用连接池管理数据库连接

2. **文件系统优化**:
   - 使用SSD存储数据库文件
   - 调整文件系统缓存大小
   - 避免在监控目录中进行大量IO操作

3. **网络优化**:
   - 使用本地网络进行MQTT通信
   - 启用数据压缩减少传输量
   - 配置合适的QoS级别

4. **应用程序优化**:
   - 调整批处理大小
   - 使用异步IO操作
   - 合理设置线程池大小
