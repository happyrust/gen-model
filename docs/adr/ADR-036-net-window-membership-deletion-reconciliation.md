# ADR-036：净窗口用目标成员关系收口索引删除候选

状态：已接受（2026-08-19）

引用：ADR-001、ADR-011、ADR-017、ADR-021、ADR-031、ADR-032。

## 背景

`ams8000_0001` 的窗口 `236..=236` 删除了 `STRU 24384_26201`。逐会话参照臂得到
`Modified 24384_26199 + Deleted 24384_26201`，生产净窗口只得到父 ZONE 的
`Modified`；目标索引遍历仍可见 STRU 的旧物理记录，但目标 OWNER 成员表已不再列它。
批次因此把水位推进到 236，却把已删 STRU 留在持久层。

## 决策

1. ADR-031 的单一净窗口路径不变，逐会话回放仍只作诊断参照。
2. 双根差分仍是普通新增、修改和索引删除的候选来源；仅对
   `Modified.children_changed` 的 `old - new` 成员候选增加目标会话成员关系仲裁。
3. 同窗口在其他 OWNER 的 `new - old` 中重新出现的成员是搬迁，不判删除。其余候选
   若在目标会话不再由有效 OWNER 包含，则根及基版本中仍随它不可达的子树合成
   `EleOperationDetail::Deleted`。
4. 元素、OWNER 或成员块仲裁失败阻断窗口。补出的删除与父修改进入同一 staging
   journal，与水位原子提交。
5. 已经错误提交的窗口使用停服维护命令纠正重放；纠正前后水位相等，不通过回退水位
   伪装成未执行窗口。

## 后果

- `NetWindowOutcome` 增加 `membership_deleted` 证据计数。
- 索引存在不再被泛化成成员关系存活；该规则只作用于成员净减少候选。
- 维护重放是显式停服操作，不构成 ADR-011 的第二个在线消费者。
