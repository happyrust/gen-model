# ADR-098：名称口径是 gen-model 里按需算出的另一种认身份的读法，不落库；增量管线内部仍按参考号

状态：**已接受**（2026-11-10 用户确认：五条决定出自当天前三轮问答的 13 条共识；第四轮又定了它们的边界——基准会话号「另记一个提资时的会话号」、
没有真实名字的单元「结果里完全不出现」、有名成员「各判各的」、自动命名的成员「和无名成员一样处理」、提资读取清单「脚本扫出、收进仓库」、其余开放问题「都按建议」；
发布票之前又向用户确认了两处，都没有改动决定，见 D2 和「后果」第三条）。
**未实施**；实施按方案 §14 的切片推进（票 #133–#139，以及 #99、#113、#100），落地时在本文追记。

## 背景

需求是：提资（把最小交付单元的数据交给数据中台）过的单元，如果只是参考号变了、属性和模型都没变，再次提资时视为未修改。
用户另外要一条按名称作唯一参照的增量数据提取接口，原话是「如果名称一致，就认为是同一个构件，不看 refno」。

今天认身份只有参考号一种办法。单元被删掉后同名重建，增量记成「旧的全删、新的全加」，新单元整个重新生成；
提资那边按参考号查不到版本记录，把它当成首次提资，旧参考号则进了待删除列表。

#92 的定稿把「比内容」放在 rs-server（新做一个内容指纹），并分两步做：#99 先做引用按目标名称比，#113 再做单元换了参考号的情形。
但 rs-server 只看得到库里的当前状态，上一次提资时的内容它读不回来；按会话把当时的内容读回来、在两个会话之间做差、把元素归到单元，
这几样都在 gen-model。

## 决定

**D1　身份按名称认定，判定放在 gen-model。** 同一个库里，E3D 存的 `NAME` 原文整串相同（带前导斜杠，只去首尾空白，区分大小写），
就是同一个构件，不看参考号。别的库里的同名元素不配对，只提示。同一个库的同一侧万一出现重名，这些元素不配对，并报出来。
同名但类型不同也不配对。配对、比内容、给类别都由 gen-model 做；rs-server 的提资和 plant-ui 的提资预览来取结果。

**D2　没有真实名字的东西不认身份。** 没有 `NAME` 的元素，以及名称以 `/Copy-of-`、`/Copy-(数字)-of-` 开头的元素（自动命名），不出行。
前缀是可配置的清单。交付单元自己没有真实名字的，整个不在结果里；rs-server 对这些单元保持今天的做法：有的根本不发，
其余按版本记录的状态加指纹判断（方案 §2.3）。
用户做后一个选择时没有采纳「按参考号认、照样给类别」的建议，看到的数是开发库里自动命名的 EQUI 937 个、BRAN 589 个。
当时对 rs-server 今天做法的转述与代码不完全相符。发布票之前，把读代码更正后的事实告诉用户（名字含 Copy-of 的只有设备不发，
BRAN 和支吊架照常提资；没有名字的工艺 BRAN、设备、工艺支吊架不发，其余专业照常发），用户维持这个选择。

**D3　没有真实名字的成员上卷到所属的有名构件；有名成员各判各的。** 无名成员和自动命名的成员不出行，但它们的增、删、改让所属的有名构件判为修改；
只是换了参考号、内容和顺序都没变的不算。成员按顺序比，不带成员自己的参考号。一个有名构件只看自己的属性、名下没有真实名字的成员、
以及下面有哪些有名成员和它们的顺序；按单元汇总时，属于这个单元的行里有一行不是未修改，单元就算修改。
用户一开始选的是「无名成员的变化一律忽略」，看到后果（无名弯头改了角度而管线算未修改，提资会跳过）之后改成了上卷。

**D4　按需算，不落库；管线内部仍按参考号。** 结果只有新增、删除、修改、未修改四类，另标是否换号、是否从未提资；改名记成旧名删除加新名新增。
它每次按需算出来，只进进程内缓存。底层是「同一个库的任意两个会话之间按名称对比」；缺省以上一次提资为基准。
基准记在 rs-server 的版本记录上：提资成功时另记一个「提资时的会话号」，旧记录没有这个数时退回用记录上已有的那个会话号。
单元之外的变化（上级移动、同库里被引用对象改名）计入修改。
现有的增量处理、任务回执、模型落库和接口都不动：换了参考号的构件，内部仍按新参考号重新生成、落库。
「模型没变」按生成器要读的属性判，不为此重新生成几何。

**D5　与 #92 定稿的关系。**
- 沿用：基准是上一次提资；引用类属性按目标的名称比，换成另一个名称的对象算实质变化；纯元数据按三条判定（属性字典的变化类为 0、生成器不读、提资不读）
  加 `CACHID`、`SPAMAP` 两个戳；`NAME`、`DESC`、全部 UDA 算实质；成员按顺序比。「提资不读」用的清单由 rs-server 用脚本扫出、gen-model 收进仓库，
  到位之前只认两个戳。
- 改了：判定从 rs-server 挪到 gen-model；rs-server 不新做内容指纹，现有的「状态 + 指纹」判断留给名称口径不覆盖的单元，两条路径并存；
  #92 分成两步的两种情形（引用换号、单元换号）由同一套比较覆盖；出行的粒度从单元细到每个有名构件；
  存量版本记录的过渡不再按「提资后有没有被写过」分两种处理，记录上有会话号的拿它当基准去比内容，没有的按已修改处理。

## 选项与取舍

- **判定放在 rs-server（#92 原来的分工）**。指纹只能回答相同还是不同，给不出逐个构件的类别和变化摘要；
  要覆盖「引用按名称比」「成员按顺序比」，等于在 rs-server 里把 gen-model 已有的读法再造一遍。
- **把结果落成表（用户最初说的「后处理」）**。那是模型面的第二份持久事实，与 ADR-079、ADR-081 相悖；
  跳过清单或纯元数据清单一改，表里的结果就全部作废。
- **改造管线，让它直接按名称认身份**。模型记录以参考号为键，换了号的构件必须按新参考号重新生成；让管线跳过它们，库里就没有新参考号的模型。
- **无名成员一律忽略**。用户一度选过，会漏掉无名管件的改动，见 D3。
- **给无名成员按「属主 + 类型 + 序号」认身份并出行**（RVM 对拍的做法）。前面的兄弟一增删，后面的序号全部漂移，会成片误报。
- **没有真实名字的单元按参考号认、照样给类别**。起草时的建议，用户没有采纳，见 D2。
- **基准只用版本记录上已有的会话号**。那是单元子树最后一次写入的会话，不是提资当时的会话；要看子树之外的东西时会每次都判修改。
- **跨库配对**。不同库里的同名元素可以同时存在，配不出一对一。
- **两侧各生成一遍几何再比**。贵，而且换号的构件现有管线本来就要重新生成一遍。

## 后果

- 省的是提资，不省模型生成。
- rs-server 里两条路径并存：有真实名字的单元按名称口径的类别跳过或重发，其余单元照旧。没有真实名字的单元享受不到「仅参考号变化不重发」。
- 提资按别的类型记版本记录的单元（工艺、仪控的支吊架是 ZONE，电气接地和一部分电缆支架是 STRU）不属于 gen-model 的最小交付单元，
  不在结果里，继续走原来的判断。这一条是按决定推出来的（方案 §3.3 的 P4）。发布票之前就这个缺口问过用户，用户的决定是：
  先按现在的方案开票；做到「以上一次提资为基准」那一片（#137）时先数出这类单元有多少，再决定补不补；在那之前它们按今天的办法判断。
- 版本记录多一个字段，rs-server 每次提资成功都要写它。
- 无名子件在提资内容里用参考号当编码；单元换号后，中台上留着旧参考号编码的子件。用户的决定是不为此重发，也不做标记。
- 目录库的内容变了而名称没变，看不出来。
- gen-model 的增量照旧按 refno 口径把被改动的单元标成 `Modify`，纯元数据的改动也会标。对名称口径覆盖的单元，rs-server 不能再把这个状态当作必须重发的依据。
- 规则改了不用迁移数据：没有落库的结果。

## 回退

接口是只读的，不落库。下掉接口，rs-server 对所有单元切回原来的「状态 + 指纹」判断即可，没有数据要清；版本记录上多出来的那个字段留着不用。
