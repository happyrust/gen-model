# ADR-040：房间失效必须覆盖有效几何与中间层拓扑变化

## 状态

已接受（2026-08-20）。补充 ADR-010、ADR-011、ADR-017；引用 ADR-001、ADR-033。

## 背景

房间增量原先只把世界包围盒变化作为几何触发源，因此内部网格、布尔结果或对称位姿
发生变化但 AABB 不变时不会重算归属。海工层级中的 `CWALL/CFLOOR` 搬迁也不会改变
其子 `PANE` 的 AABB，却会改变面板所属房间。另有房间结构枚举故障被实现成窗口硬失败，
与 ADR-010 的派生数据降级口径矛盾。

## 决策

1. 定向模型更新的输入已经由工作计划收窄到实际重写/变换目标，因此全部有几何的目标
   都保守进入房间失效集；AABB 变更集继续独立计算，普通全量/维护刷新仍只按 AABB 触发。
2. 暂存窗口在任何 journal 写回前把保守房间目标写入既有恢复检查点。该策略也保证
   “几何已写、房间任务未写”后的重试仍能产生同一目标集，不依赖前后几何再次不同。
3. 直写定向更新的房间任务、AABB 指针与空间 epoch 同事务；仅有效几何变化也必须推进 epoch。
   关闭房间增量只抑制 `RoomRecalc*`，不得抑制空间/启动重建失效信号。
4. `project_hd` 下 `CWALL/CFLOOR` 的 OWNER 变化按房间构建的固定两层语义枚举直接子
   `PANE`，与直接搬迁 PANE、改名房间目标合并去重。
5. 结构面板枚举失败保留其余有效工作并推进数据窗口，同时在同一尾事务把
   `room_build:main` 标记为 `rebuild_required`。该标记是持久的启动全量重建兜底，只有
   成功的全量房间重建可以清除；它不承诺当前进程内自动全量重建。

## 后果

- 同 AABB 的真实几何变化不再静默遗留旧房间关系；代价只落在定向增量目标上。
- 海工中间容器搬迁可由现有 `RoomRecalcPanel` 收敛，无需新增队列表或消费阶段。
- 结构枚举故障不再饿死 DESI 水位，但 `/health` 与控制台会持续显示待全量重建状态。
