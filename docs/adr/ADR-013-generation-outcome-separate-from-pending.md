# ADR-013：生成结果与待重试任务分离

状态：Accepted（2026-07-29）

> **2026-08-05 修订（ADR-017）**：稳态窗口内的生成不再经 durable pending——工作清单在进程内、attempts / 死信在控制面记录、生成结果随窗口提交单元写回。本 ADR 的按需生成判定顺序、pending 保护与 revision 收口规则在按需 / 派生 / 房间路径上继续有效。

生成根以 `refno` 为身份；`model_update_pending` 只保存仍需执行或重试的工作。最近一次成功的模型生成结果单独持久化，并用于区分“从未生成”与“已成功生成但没有可绘制几何”；按需判定顺序固定为：durable pending → 现有模型实例 → 最近成功结果 → 首次生成。

成功生成、生成结果写入与 revision-safe pending 收口必须形成同一个原子状态变化；新的 pending 总是覆盖旧结果的可复用资格。首次按需生成也必须先写入 pending，再经共享执行器完成；不得存在没有 pending 保护的第二条生成路径。`force` 跳过实例与成功结果复用，明确新增一个 revision，但仍使用相同 pending、根锁与收口规则。

解析或生成失败不得写入成功结果，也不得删除对应 pending；只有查询成功且确认目标不存在时才能对外返回 `not_found`，依赖读取失败与确定性生成失败必须保留为不同错误类别。

## Considered Options

- 在 `model_update_pending` 保留成功终态：拒绝，因为它把“仍需工作”和“已经成功”混为一个领域概念。
- 仅依赖实例计数：拒绝，因为零实例无法区分“从未生成”和“成功生成但结果为空”。
