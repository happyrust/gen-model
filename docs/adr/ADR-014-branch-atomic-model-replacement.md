# ADR-014：模型关系按 BRAN 原子替换

状态：Accepted（2026-07-29）；2026-08-05 起被 ADR-017 部分取代

> **2026-08-05（ADR-017）**：稳态增量路径的原子边界由单 BRAN 升级为整窗口——本 ADR 末段预留的 revisit 条款由「窗口执行期间持久层零可见」这一隔离需求触发。BRAN 级事务仍是写回内部与基线 / 全量路径的实现单位，本 ADR 第二段「删除成功与生成失败不得混淆」的纪律继续有效。

“模型生成失败时保留旧显示”的原子边界是单个 BRAN，而不是整个生成根。每个 BRAN 的旧模型关系删除与新关系写入必须在同一事务中完成；任一步失败时该 BRAN 回滚到完整旧版本，生成根继续保留 durable pending，允许其他已经成功的 BRAN 暂时使用新版本并在重试后最终收敛。

已确认删除或已不存在的 BRAN，其目标关系集为空，事务成功删除旧关系即完成清理；仍存在但属性、世界变换、HPOS 或数据库查询失败的 BRAN 不得删除旧关系，必须把当前生成标记为失败。实现不得以统一 `continue` 混淆“删除成功”与“生成失败”。

不采用生成根级 staging/swap，因为它要求同时版本化实例、关系与空间数据，复杂度与当前需求不相称。若观看端将来明确要求整根快照一致，再以该需求为依据升级原子边界。

## 2026-08-05 增补：保留旧显示只保到「生成失败」为止

「生成失败时保留旧显示」此前被实现读成了「凡是这一轮没写出来的行都别动」。于是 `save_instance_data(replace)` 的删除集只覆盖本次产物，上一版画得出、这一版画不出的元素（参数改到不再产生几何、分支尾部不再有隐含直管段）旧行永久留着——模型里已经没有它了，库里还有。

现在的口径是：**生成与写入都成功之后，以产物为准**。定向重生成收尾时把生成根子树里「仍挂在根下、却不在本轮产物里」的行清掉（`data_interface::helper::prune_roots_stale_model_rows`），连同它们的房间归属边与空间树条目。生成或写入任一失败则一行不清——那才是本 ADR 要保留旧显示的场景。

搬走或被删的元素不走这条路：清理的候选来自 `query_deep_visible_inst_refnos`，那是对 `pe` 的活子树查询，它们早已不在根下，归 `delete_inst_relate_subtree`（`DeleteCleanup`）。

代价明确记在这里：这个差集分不清「真的不画了」与「本轮生成没做出来」。生成层有多处静默 `continue`（目录查不到、参数解不开），命中时那一行会从「陈旧」变成「消失」。接受它的前提是「生成成功 ⇒ 产物完整」。这条前提哪天被证伪，正确的修法是让生成层为「这个元素现在没有几何」发一个显式信号，而不是把删除集缩回本次产物。

清理的任何一步查询失败都不删并上抛，调用点降级为告警：漏查一部分子树会把还在用的行当成陈旧行，而少清一轮只是旧行多留一会儿。

清理不含 `inst_geo`——内容寻址的共享节点，写入路径上不做单边回收，理由见 `data_interface::helper::render_cascade_delete`。
