- **ADR-021**（水位必须有数据支撑，回退默认整库重建）：回退与幽灵水位走整库

- **ADR-009**（OWNER 变更是搬迁）：净修改必须继续给出 old/new owner 两端，
  交付单元归并的「两端都重生成」语义不变。

## 背景

### 成本结构：为不需要的历史付三遍钱

现行 `IncrementPipeline::collect_changes` 逐会话回放：对窗口内每个 (refno, 会话)
触达付「3 次记录解析 + 1 次全属性 diff」（`get_refno_operation_status`：latest +
prev + owner 三场解析）。同一 refno 被 N 个会话改过就付 N 遍，成本
O(会话数 × 每会话触达)：

- 250206（SYST 家族）单趟 collect 实测 5 分多钟（`manual_update.rs` 注释留档）；
- 1112 的 175 会话积压窗口 ≈ 35 万 op、百万级记录解析；
- ams8000 全窗口回放 10.8s、amssys 4.6s（2026-08-13 实测，debug）。

下游还要为中间态再付两遍：`fold_window` 事后折叠掉约 31% 语句；
`retain_finally_live_adds` / `restore_finally_live_deletes` 两个终态补丁把临时
Add / 假删除擦掉——都是在解析钱已经付完之后扔结果。

### 语义问题：逐会话回放在历史窗口上有系统性盲区

2026-08-13 用生产 B+ 点查逐 refno 仲裁（证据
`docs/evidence/2026-08-13-session-index-diff-net-changes.md`）：

- ams8000 全窗口：回放折叠净集与生产点查仲裁的两端状态有 **154 条**分歧（漏报存在 67、
  孤儿 Modified/Deleted 腿误报 86、误判 1）；
- amssys（SYST）全窗口：**818 条，占回放净集 43%**（孤儿 Deleted 腿 653 为主）。

分歧由点查仲裁**列出**；其主体成因是结构性的（删除类判据的独立性另由 core.dll
键集差与 T11b 佐证，不靠同源点查自证）：临时 Add 被终态对账剔除后，同一 refno 的
Modified/Deleted 腿成为孤儿；跨会话删除依赖「owner children 包含性」推断
（issue-019 家族）；存在漏报则来自认领扫描的口径缝隙。补丁只在窗口终点 == 文件
最新会话时生效，历史窗口全裸奔。

### 已验证的替代

`session_index_diff::collect_net_changes`（2026-08-13 落地，CONTEXT.md
「会话索引差分」）：取窗口两端会话页里的索引根做双根差分，纯文件、与会话数
解耦。存在性口径与生产点查**逐字对齐**（同键子指针首见者胜、路由不看 flag、
键范围路由——三条规则均由真实 ams8000 逼出并钉成回归测试），四个 live 窗口
点查仲裁零分歧，15–34×（debug）。

## 算法来源与正确性边界

### 来源定位：与 core.dll 同思想（live 实证），gen-model 是纯文件重实现/加速

core.dll 的会话区间差分 `DB_DB::elementsChangedBetween`（`0x58ffc50`，
`elementsChangedSince` 转发进来）**本身就是一次双根 B+ 索引表归并差分**——
2026-08-13 的 live 逆向（`docs/evidence/2026-08-13_reverse-core-dll-index-leaf-report.md`，
core.dll 3.1，SHA `3c1f…417d`，符号系二进制自带 MSVC 修饰名、非人工猜名）证实：
三个枚举器（变化 `0x58ffb20` / 删除 `0x5900250` / 新建 `0x5901010`）同构，都构造
一个 `DB_IndexTableCompare`（`0x5a18b20`），经 dabacon 比较引擎 begin `sub_5B026C0`
（opcode 266）取**同一主索引表（id `13387743`）在窗口两端会话的两个根**、advance
`sub_5AFFCB0`（opcode 270）按 refno 键归并两棵 B+ 树：仅次树 = inserted(2)、
仅首树 = deleted(3)、键同 loc 异 = modified(1)。这与 gen-model
`session_index_diff`「取窗口两端会话页里的索引根做双根差分」是**同一算法思想**，
现在**有 live 证据背书**，不是凭空创新。

**实现差异（据实标注）**：核内比较器是「先定位到两个会话、再比较系统表根」；
gen-model 直接吃 copy-on-write 会话页各自携带的索引根、并做**共享子树整枝剪枝**
（IO 正比于变更量而非变化元素数）——殊途同归，都靠「同一 B+ 索引在两会话的两个
根」判存在性。故本 ADR 现在**可以**说 gen-model 与 core.dll「同源 / 同思想」，
但仍**不宣称逐指令复刻内核代码**（核内比较器每条目仅携带 refno + `(pgno, offset)`，
共享子树剪枝是 gen-model 自有的文件层加速）。

分工写死，不许互相顶替：

- **core.dll 仍是属性语义与桶语义的唯一权威**（ADR-002 / ADR-004 / ADR-009
  不变）：什么算 `Modified`、OWNER 变化算 `Moved`、成员差分只对
  `primaryList` 做——继续以逆向结论为准，本 ADR 一个字不动。
- **索引差分只回答「窗口两端谁在场、记录搬没搬位置」**，不回答「这次变化落进
  哪个桶」：桶语义仍由净修改两端版本的 `diff_ele_data` 产出（决策 2），再喂
  `classify_operation_impact`。core.dll 侧的存在性 / 增删改判定亦全由 refno 键
  归并给出、与 flag 无关（见风险节 flag 条与验收 5）。

### 正确性契约

1. **端点存在性的判定基准是生产 B+ 点查可达性**（外部
   `pdms_io::search_latest_refno`，core.dll B+ 搜索的逆向复刻，与差分**同源**——
   都不看 flag），不是「在树上出现过」。三条路由规则（同键子指针首见者胜、路由
   不看 flag、键范围路由）存在的唯一理由就是与点查逐字对齐，均由真实 ams8000 的
   反例逼出并钉成回归测试。**「路由 / 存在性不看 flag」另有核内权威背书**：
   core.dll 的变更检测比较器每条目只携带 refno + `(pgno, offset)`，存在性 / 增删改
   判定全由 refno 键归并给出、不读 flag（live 逆向 report §6 / C1）。
2. **净三态由两端 leaf `(pgno, offset)` 集合差定义**：目标在场而 base 不在
   = 净新增，base 在场而目标不在 = 净删除，两端都在且 `(pgno, offset)` 不同
   = 净修改；两端同 loc（原样重写）不算变化。
3. **净修改的语义仍走 core.dll 口径**：用 base 与终稿两个版本记录做
   `diff_ele_data`，产出与回放同源的 `ModifiedElement`（属性差量 + children
   两端 + old/new owner）。索引只负责选出「该 diff 谁」，不参与「diff 出什么」。
4. **形状前提可证伪**：追加模型被破坏（ADMIN 压缩 / 回卷）时差分响亮拒绝，
   转 ADR-021 整库重建，不给静默错答案。
   非根索引页不可读、子页层级不下降与重复指针、越界残留同列为**点查不可达的
   回收页残留形状**：容忍、跳过整枝并计数（`unreadable_child_pages` /
   `level_anomalies`），与生产点查 `filter_index_data` 的口径逐字对齐。
   索引根页不可读仍是硬错误。
   （修订 2026-08-18：cea58087（08-14）曾把前两种形状升为整窗硬错误；08-17
   实测它们是真实 dabacon 文件的常态——当前 ams8000 与 07-24 备份都必现——
   升硬错误等于净口径在一切真实库上失败，遂回退为容忍 + 记账。点查到不了的
   分支本就不参与触达集，跳过不损「触达集完整」的证明。）
5. **正确性据以成立的是三重对拍 + core.dll 机制背书，各自的独立性必须分清**——
   - **差分 ≡ 生产点查**（四窗口逐 refno 仲裁零分歧）：这是**同源**验证（点查与
     差分走同一棵索引、同样不看 flag），只证差分忠实复刻了点查遍历；flag / 存在性
     的**机制层**语义不由它证，而由下述 core.dll live 逆向证；
   - **差分 ≡ 回放折叠**：在 fold 不盲的 refno 上是**跨结构独立**交叉验证（回放
     读会话变更记录、不经索引叶 flag）；live 全窗口 154（ams8000）/ 818（amssys）
     分歧——生产点查只是**同源判定基准**（与差分同看一棵索引），用来**列出并归类**
     分歧，**不**独立证明它们全是回放旧口径盲区；真正独立于 gen-model 的机制权威是
     core.dll `DB_IndexTableCompare` / `elementsDeletedBetween` 的键集差（report
     §4 / §4.5），它确认 **Deleted 判据站在净路径**这一侧；其余临时态孤儿腿结合
     端点记录 / 夹具逐类归因，**不是无条件等价**。**注**：现有 A/B 的删除腿是空跑
     （窗口内被删元素在基线本就无行），删除等价仍须 T11b 存量库结果层直证；
   - **净修改负载与回放逐桶相等**：`db8000_session_pairs` 性质 i 覆盖全部案例
     窗口（Modified 负载逐桶相等；样本为各窗口**实际 Modified 条目**，当前以
     多触达为主，**非** test binary 计数）；**live 单触达 Modified 样本本轮为 0**，
     单触达等价尚缺 live 直证；
   - **core.dll 机制层背书**（live 逆向，report §4 / §4.5 / §6 / §5）：核内变更枚举
     确为双根 B+ 归并、删除即集差（键在旧根不在新根，kind=3，**非墓碑**）、变更检测
     **全链路**（页取 + begin + 双根归并）不读 / 不按 flag 过滤、`0x80000001` 是页内
     键哨兵——**独立于上述对拍**地闭合了「双根差分 / 删除 / flag 不进变更检测链路」
     这几处机制语义（flag 在链路外是否另有功能未闭合，见风险节）。
   四者合起来仍**不是**「逐指令复刻了内核算法」：本路径与 core.dll **同思想**，
   但共享子树剪枝是 gen-model 自有的文件层加速。任何把本路径描述成「逐指令实现了
   `elementsChangedBetween`」的说法仍是错的。

## 决策

### 1. 触达集与净三态由会话索引差分给出

增量窗口执行体（`execute_one_dbnum` → `apply_with_precollected`）的收集阶段改用
`collect_net_changes`。逐会话回放 `collect_changes` 退出执行主路径，保留为诊断
工具（逐会话取证、探针对拍）。

### 2. 输出形状兼容：合成每 refno 恰一条的 `EleOperationData`

净收集器产出与现行完全相同的 `BTreeMap<sesno, Vec<EleOperationData>>`，每个
refno 恰一条、挂在其 last-touch 会话下：

- 净新增 → `Add(终稿 EleData)`（终稿记录一次解析）；
- 净删除 → `Deleted`；
- 净修改 → `Modified(ModifiedElement)`：base 版本由 `NetEntry::base_loc` 直读
  base 端旧记录页、终稿版本按 `loc` 解析，各一次，**一次 diff** 合成三命名空间
  属性差量 + `children_changed(old, new)` + old/new owner。

页到 last-touch 会话反查失败会使整窗失败，不产出残缺操作集。终稿（Added /
Modified 的目标版本）解析失败按**与回放同口径**跳过该条 + 计数
（`unparseable_finals`）+ 聚合警告：这类记录多是字典缺项的系统记录，回放路径对
同一批记录同样以 `None` 操作落空、从未入库，跳过与回放行为等价。Modified 的 base
版本解析失败保留保守降级为 Add 的口径并随回执警告。执行侧把错误收口为批次
Failed，预览按 dbnum 显示错误，两者都不自动切换回放收集。
> **2026-08-18（ADR-031）**：原句「运维仍可显式关闭净收集开关后重试」已失效——
> 开关退役，生产回退 = `git revert` 单路径提交。`CollectionMode` 一并删除。

> 2026-08-18 修订：cea58087（08-14）曾把终稿解析失败升为整窗硬错误。08-17 实测
> ams8000 的 `16192_1` 必现 `MNUM not exist in attr_info_map`，该硬门会让每个含
> 系统段的窗口整批打死，而回放口径下这批记录本就不入库——回退为跳过 + 记账，
> 回归钉在 `an_unparseable_final_is_skipped_counted_and_aggregated`。

于是模型计划（`build_model_update_plan` / 交付单元归并）、`ref_rev` 维护、
MySQL 同步、渲染（`render_persist_statements`）的输入形状**零改动**；
`fold_window` 在净路径上没有可折叠的输入，两个终态补丁构造性消失。

收集器统一返回 `CollectedWindow`：除操作流外还携带冻结范围内从会话页映射读取的
`session_sesnos`、`warnings` 与 `CollectionMode::{Replay, Net}`。会话清单升序去重，
与有没有元素操作无关，因此空保存、自抵消与稀疏会话都保留；预收集、崩溃重放和
`IncrFileSuccess` 必须原样传递。两种模式的第一条 warning 固定自报口径，
`merged_sesnos` 只能由该会话清单经 `previous_observed` 过滤产生，保存时刻继续按
同一序号清单平行写入。Replay 的会话映射与操作流必须由同一个已打开的 `PdmsIO`
产生；口径 warning 即使在后续模型计划或 attempt 准备阶段失败也必须随错误回执透出。

「两个 EleData → ModifiedElement」的 diff 逻辑目前内联在 vendor
`get_refno_operation_status` 里。**优先方案**：在 pdms-io 提取为纯函数
`diff_ele_data(prev, latest) -> ModifiedElement`，回放与净路径共用（判定只有
一处权威）；vendor 流程走不动时允许 gen-model 复刻，但必须附「与回放产出的
ModifiedElement 逐字段相等」的对拍测试钉住不漂移。

### 3. 纯文件判定的分界

窗口**内**判定（谁动了、动成什么样）只读文件；窗口**起点**仍是库的承诺
（ADR-001 水位）；跨库级联仍走 ref_rev（ADR-003，单文件解不出全局反向引用）。
这条分界写死：净收集器本体不得出现任何数据库访问（`session_index_diff` 已有
源码断言，合成器同款）。

### 4. 灰度与同谓词（**已被 ADR-031 取代**）

> 本节整体被 ADR-031 决策 1/3 取代：开关与环境变量退役，「同批次不换口径」由结构
> 保证而非冻结快照保证（specs/003 T17 因此 CANCELLED）。下文保留为历史记录。

- `DbOptionExt` 新增 `net_window_collection`（默认 off），环境变量
  `AIOS_NET_WINDOW` 压过配置（认 on/off 家族取值，认不出回落配置——与
  `startup_autorun` 同一条纪律）。
- 预览与执行体读**同一个**开关、走同一个收集器（ADR-011：判定只能有一处）。
  开关只在批次冻结点取值一次，同一批次内不换口径（**规范决策**）。
  **实现缺口（翻默认前补，见 tasks）**：当前 `AIOS_NET_WINDOW` 由每次收集实时
  读取，尚无「批次冻结时取一次快照」的实现——规范上不允许同批次换口径，但代码
  层还没钉死，需补冻结快照 + 同批次 env 变化不换臂的回归测试。
- 对拍期收官（fixture + live A/B 全绿、生产窗口试运行一轮）**且过验收 5 的
  证据门（(a) 机制闭合 或 (b) 结果层残余风险接受）**后翻默认值为 on，再一个
  周期后移除开关与回放收集的执行路径接线。

### 5. 明示的行为变化（口径升级，非回归）

1. **「改了又改回」不再触发 regen**：净 diff 给出的是精确差集。「宁多勿漏」
   原则的挂名处不变——未知属性仍保守触发（`classify_operation_impact` 不动），
   变的只是不再把「没有净变化的元素」当成变化。
2. **「加了又删」不再留墓碑行**：现行回放会先建记录再立墓碑，留下一行从未
   发布过的 pe 墓碑垃圾；净路径两端都不在场，什么都不写（`NetOp::Cancelled`
   在计划层本来就是这个语义，数据层就此对齐）。
3. **「删了又建」判净修改**（回放折叠措辞是 Added）：落库语义等价（全量
   覆盖 + owner 边重插），模型侧照样整根重生成。
4. **逐会话明细退出预览主口径**：预览的变更清单本来就是净变化（spec
   §预览结构）。**会话页清单口径尚未落地（tasks T12）**：灰度期 `merged_sesnos` /
   会话保存时刻**仍来自净 op keys**（「有净变化的会话」），会**少列自我抵消的
   会话**，翻默认值前由 T12 改为会话页清单直接给出。需要逐会话归属时用诊断工具。
5. **`pe.sesno` 戳 last-touch 会话**（与现状一致，来源从 op 流换成索引条目
   记录页的会话反查）。

## 代价与风险

- **每 refno 两次记录解析（净修改）**：base + 终稿。对比回放的「每触达 3 次」
  仍是量级级省——收益随窗口内会话数线性放大，单会话窗口约打平。
- **中间态消费者盘点**（实现前逐个核对）：`sessions_merged_after`（批次回执）、
  `window_net_states`（datacenter overlay，净态直接更准）、
  `reconcile_plan_final_presence`（净路径天然满足，可短路）、MySQL 同步
  （吃 range_eles 形状，兼容）。发现新的逐会话依赖时，要么改读会话页清单，
  要么明确降级并写进回执。
- **崩溃重放**：固定区间重放在净路径下同样确定（diff 基准是文件版本，不是
  库态），ADR-001 幂等语义保持。
- **文件被压缩/回卷**：差分器对追加模型破坏响亮拒绝；该形状本来就该走
  ADR-021 的回退→整库重建，不落在本路径。
- **叶条目 `flag`：变更检测全链路不以它作门已 live 证实，链路外语义未闭合**：
  core.dll 的**变更检测全链路**（页取 `sub_5AEE4E0` + begin `sub_5B026C0` + 双根
  归并 `sub_5AFFCB0`）**不读、也不按 `flag` 过滤 / 跳过任何条目**——比较器每条目
  只携带 refno + `(pgno, offset)`，存在性 / 路由 / 增删改全由 refno 键归并给出，
  `sub_5AEE4E0` 里的位运算只作用于页缓存描述符（live 逆向 report §4.5 / C1，
  agent-4 一致性审查后的有界补查）。这从**核内权威侧**证实了本路径「路由与存在性
  都不看 flag」的口径，与生产点查同款、四窗口 live 零分歧。**仍未闭合（有意收口，
  展开 dabacon 叶写 / 查会触 mass-decompile 红线）**：raw 叶数据元素内 `flag` 的
  存在 / 字节偏移 / 位宽 / 取值枚举 / 写者未逐位逆向（真实文件取过证的只有 0 与 1，
  回归单测另覆盖 2 / 3，`flag_histogram` 仍全量透出实际分布），**以及 `flag` 在
  变更检测链路之外是否另有可见性 / 过滤门同样未闭合**（report C3 / C4）。**可断言
  的仅是**：净窗口判定所依赖的权威变更检测链路不以 flag 作门，故翻 on 不受其阻断；
  **不得**泛化成「flag 在 core.dll 所有路径都无功能 / 功能上否定它是可见性门」。
- **删除在索引层的表达形式已 live 闭合（机制层，高置信）**：core.dll 侧删除
  **不是**墓碑 flag，而是**双根归并的集差**——键在首（旧）根、不在次（新）根即
  deleted（kind=3，live 逆向 report §4 / B3）。与 gen-model「base 有、target 无
  → Deleted」（`session_index_diff.rs:17-20`）逐字同构，核内背书。`is_start_page`
  的**起始哨兵行为**亦有核内背书：`0x80000001`（核内以 `-2147483647` 识别）是
  **页内键哨兵**（非代码字节常量，`bin_search` 零命中），在归并里作键空间边界
  （内页最左子树、叶层非数据，report §5 / D1·D2）——与 gen-model 处理一致。
  **仍未知**：该哨兵条目的底层原始字段 / 位定义未逐位展开，但其行为已由核内归并
  逻辑背书、不影响判定，不要按名字额外附加官方页头语义。
- **兜底**：开关保留一个发布周期；`net_changes_probe.py --verify` 可在任意
  现场窗口即时审计两套口径的分歧并归因。

## 验收

> **2026-08-18**：验收 1–3 继续有效；**验收 4 与验收 5 已被 ADR-031 取代**——单路径
> 之后没有「翻不翻默认」这个决定，两道门失去守卫对象。倍数门降为记录项、SYST
> `250206` 改为上线后现场复测、T13 降为登记在案的覆盖缺口，逐条理由见 ADR-031
> 「门的重定级」。下文两节保留为历史记录，**不得**据其继续宣称存在阻断门。

1. **纯单测**：合成器 diff 逐字段对拍回放产出（`net_window.rs` 现有 3 条
   `diff_ele_data` 纯单测 + 1 live + 源码断言）；**合成器 `collect_net_window` 的
   Add/Deleted/Modified 三形状 + 失败降级纯单测尚缺**，翻默认前由 tasks T20 补
   （可注入缝 / 纯构造层）；既有差分核心 11 条不动。
2. **夹具**（CI）：`db8000_session_pairs` 增加「引擎净收集输出 ≡ 回放收集输出
   （按存在性归一）≡ 台账」断言；issue-019/020 现有性质 a–h 全绿不回归。
3. **live A/B**：同一真实库同一窗口，net 与 replay 各走一遍完整执行（解析 →
   计划 → 落库 → 水位），断言库终态等价 + 模型计划等价（净口径差异按第 5 节
   清单归因），计时入 `docs/evidence/`，用例记 live 台账。
4. **性能门**（如实标状态，未达不得伪绿）：**纯差分**阶段 ams8000 实测 15–34×
   （debug）；但**含终稿合成的引擎级净收集**目前只有 debug 8.8×、A/B probe 4.4×，
   故「≥20 会话**完整收集**阶段 ≥10×」**尚未达门**；250206（SYST）单趟 collect
   从 5 分钟级降到 30 秒内为**目标值、未实测**。三项证据由 tasks T18 补齐；若
   release / 代表形态实测仍不达 ≥10×，**必须回到本 ADR 决策**，不得翻 on 伪绿。
5. **翻默认值的证据门**（只挡默认值，不挡灰度）：`net_window_collection`
   由 off 翻 on 之前——

   **机制层：核心问题已由 live IDA 闭合**（2026-08-13
   `docs/evidence/2026-08-13_reverse-core-dll-index-leaf-report.md`，core.dll 3.1，
   SHA `3c1f…417d`，符号系二进制自带、非猜名）：① 双根 B+ 归并差分为核内既有算法
   思想（`DB_IndexTableCompare` opcode 266 / 270，主索引表 `13387743`）；② 删除 =
   集差、**非墓碑 flag**（键在旧根不在新根，kind=3）；③ 变更检测**全链路**（页取 +
   begin + 双根归并）**不读、不按 flag 过滤 / 跳过条目**（report §4.5 / C1，agent-4
   有界补查）；④ `0x80000001` 是页内键哨兵、作键边界。这四点**不再是**翻 on 的机制
   门——权威变更检测链路本身不以 flag 作门。**仍未闭合的机制未知项**（不阻断翻 on，
   仅登记）：raw 叶内 `flag` 的存在 / 字节偏移 / 位宽 / 取值枚举（report C3），
   **以及 `flag` 在变更检测链路之外是否另有可见性 / 过滤门**（report C4，降级为
   未闭合）——可断言的只是「净窗口所依赖的权威链路不以 flag 作门」，**不得**泛化为
   「flag 全无功能 / 功能上否定它是可见性门」。

   **结果层：翻 on 仍需补齐真实缺口**（下列为实打实的门，非机制悬案）——
   - **删除等价的存量库 A/B**（tasks T11b）：现有 live A/B 起点是「当前文件基线」，
     窗口内被删元素在基线本就无行、删除语句落空（墓碑归一实测 0 条），**未覆盖
     「存量库中删除会话早于窗口起点」**；需真实存量库补一轮删除等价直证；
   - **Added 独立夹具**（tasks T13）：净新增三方断言的独立录制夹具到位；
   - **批次口径冻结快照**（tasks T17）、**会话页清单口径 T12**、**SYST 性能实测
     250206 < 30s**（tasks T18）落地。

   走上述结果层门即可翻 on；**无需**再等 `flag` 位编码逆向（已判定不影响正确性）。
   默认 off 下的诊断、探针 `--verify` 审计与灰度试运行不受此门阻断。

   **qualifier 维**：core.dll 变更粒度含 `(attribute, qualifier)` 维
   （`attributeModified(elem, attr, qual)`，report §3 / §8.5），gen-model
   `ModifiedElement` 按属性名聚合会丢 qualifier。**翻 on 不阻断的理由**是：这是
   `ModifiedElement` / 回放口径与净路径**共享的既有输出形状限制**，非本次切臂新增
   （两条路径同样丢 qualifier，切臂不引入回归）；**但不等于无条件安全**——是否需要
   扩展输出形状承载 qualifier 待评估（tasks T19），不得据此认定它无风险。
