# ADR-023：启动重扫修复无数据支撑的应用水位

- 状态：Accepted
- 日期：2026-08-14
- 修订：ADR-021「数据支撑不进入入队门」的绝对限制

## 决策

1. `dbnum_watermark` 记录 `confirmed_empty_baseline_sesno`。只有一次成功的全量基线明确解析为合法空库时，该值才等于本次建立的 `applied_sesno`；非空基线清除此值，增量推进后旧值因不等于新水位自然失效。
2. 启动重扫遇到 `file_latest_sesno == applied_sesno > 0` 时执行一次 `pe` 存在性探针。零行且没有与当前水位匹配的空基线凭据，按 `applied=0` 的首次导入形状入队；扫描本身不删数据。
3. `file_latest_sesno > applied_sesno` 的普通候选仍在 worker 冻结点检查数据支撑，避免为全部启动候选增加扫描查询。
4. 生产根配置和缺省值把 `startup_autorun` 翻为 `true`，使启动发现的未解析库、回退重建批次和追平幽灵水位实际执行。显式配置或环境变量 `false` 仍保持挂起契约。
5. 预览、手动入队、自动重扫和 worker 共用同一空基线凭据与幽灵水位判据；查询失败必须出现在回执或启动日志中。

## 理由

ADR-021 只在已经存在增量窗口时检查幽灵水位，因此“水位恰好追平文件、数据却为零”的库不会形成批次。直接对所有零行库入队会让合法空库每次启动都全量重解析；水位绑定的空基线凭据提供了区分二者所需的最小持久事实。

## 后果

- 已有水位行没有该字段，按“未获得空基线豁免”处理；只有零行库会受影响。
- 每个已追平的非零水位候选在启动重扫多一次 `LIMIT 1` 存在性查询。
- 显式关闭 `startup_autorun` 的测试和运维配置继续只发现、入队、挂起。
