# ADR-035：监控链路分成「观察收集」与「观察分析」两层

状态：已接受，尚未实施。落地计划与实施顺序见
`docs/plans/2026-08-19-watch-observation-analysis-split-plan.md`。

日期：2026-08-19

关联：ADR-011（两条路径合流、发现即入队）；ADR-016（监控目录解析与项目数据域）；
ADR-021 / ADR-023（水位必须有数据支撑、启动重扫修复）；ADR-025（严格初始化阶段与
清单）；ADR-028（抽取树文件身份）；`src/data_interface/increment_manager.rs`
（`async_watch` / `sweep_dirs`）；`src/data_interface/batch_scheduler.rs`
（`DiscoveredBatch`）；`CONTEXT.md`「文件观察 (File Observation)」

## 背景

共享盘上 OS 原生事件对其他主机的写入不可靠，所以增量发现从来不是推送，而是两层
轮询：`PollWatcher` 每 30s stat 一遍目录树比 mtime（`AIOS_WATCH_POLL_SECS`），周期
对账每 300s 整面重比「文件最新会话号 vs 应用水位」（`AIOS_WATCH_RECONCILE_SECS`）。
前者决定发现延迟，后者决定最终一定会发现——事件只送达一次，处理途中失败（2026-08-06
现场：数据批次执行中 SUL_DB 连接抖动）那次变更就永久没人管了，而 E3D 那头不会为了
配合我们再保存一次。

想把对账间隔调短时撞上了墙：一轮重扫在网络盘上可能分钟级，而它就 `await` 在
`async_watch` 的事件 select 循环里，扫多久事件就积压多久。占空比是 `T / (T + 间隔)`，
间隔调短等于直接抬高它，把 30s 那层的发现延迟拖长——为了让兜底路径快一点，把主路径
搞慢了。

根因不是间隔选得不好，是**收集与分析是同一个函数**。一轮 `sweep_dirs` 里：

- 整棵目录树被走**三遍**（`catalogue_manifest_for_dirs`、
  `collapse_watch_dir_families`、主循环），每遍都对每个候选库真开文件读头；
- 主循环的 `WalkDir::sort_by` 每次比较现调 `metadata()`，在共享盘上是 O(n log n)
  次网络 stat；
- 每个在范围内的库还要 `get_latest_sesno` 读文件、`scan_and_check_file` 写观察落
  库、`discover_batch` 查水位——没有任何变化的一轮，依旧会对几百个库发出几百次
  upsert；
- 事件分支里有一句 `sleep(250ms)` 手搓防抖，因为没有队列可以合并。

而进队列的 `DiscoveredBatch` 携带 `project/dbnum/db_type/phase/epoch_id/intent/
applied_sesno`——它**已经是分析成品**。也就是说今天的「收集」实际上把分析全干完了，
这才是间隔调不动的原因。

## 决策

1. **收集层只产文件观察**：`{ path, mtime, size, seen_at, origin }`，只 stat，一行
   文件头不读、SUL_DB 不碰。文件变化与周期全集轮产出同一种观察，区别只在覆盖面。
   排序需要的 `size` 顺手就在 stat 里拿到，`sort_by` 那个网络 stat 风暴随之消失。
2. **观察队列是进程内按 path 聚合的 map**，同 path 只留最新一条，不落库。观察描述
   状态而不是发生过的事，因此天然可合并——一次 SAVEWORK 打出的一串变化塌成一轮
   分析。
3. **分析层是独立 task，同一时刻单飞**。收集层塞完观察就回去听，再不被任何重活
   阻塞。
4. **观察显式带 `origin` 与「是否全集」**，分析层不做推断。只有全集轮才有资格做
   「这个文件不见了」这类需要全集视野的判定。
5. **阶段纪元由分析层安装**。词表对它的定义是「一次完整候选扫描安装的可重建版
   本」，切开之后那次扫描发生在分析层。
6. **分析层本期不缓存读头结果**。三遍遍历合成一遍已经把文件头 I/O 砍到 1/3，先拿
   实测耗时再决定要不要用缓存换掉一道保护。
7. **入队判定口径一字不改**。同一份观察集合喂进去，产出的 `DiscoveredBatch` 必须与
   今天逐字一致：范围门、F6、`ScanGate`、水位比对、park 判定全部原样搬过去。
8. **自动重跑与间隔默认值本期都不动**，理由见「结果 / 约束」最后一条。

## Considered Options

- **只把 `AIOS_WATCH_RECONCILE_SECS` 调短**：一行配置，最省。但占空比直接上升，主
  路径变慢；而且连败预算数的是轮次，调间隔等于顺手把故障容忍窗口从 25 分钟砍到
  5 分钟——从后门改了失败策略，且没有任何东西会提醒改的人。
- **只做微优化不分层**（合并三遍遍历、去掉 stat 风暴、观察没变就不写库）：能拿到
  大部分 I/O 收益，改动也小得多。但分析仍然坐在事件 select 循环里，「分析不阻塞
  摄入」这条拿不到，间隔依旧不是自由参数——只是痛得慢一点。
- **取消周期对账，改成「失败的事件进重试队列」**：那要求抓得到失败。进程被 kill、
  机器断电、那一轮 `await` 卡在掉线的共享盘上永远回不来——这些都没机会入队；重试
  队列自身也要落盘、也会写失败。对账不需要知道任何失败，它只问当前差多少，一条
  逻辑兼容所有故障模式。
- **观察队列落 SurrealDB**：能跨重启保住顺序与历史。但观察是派生态，下一轮全集轮
  就能把它整个重建出来；再加一层持久化是重复投保，还多出一处「表与文件系统不一致
  时以谁为准」的规则。

## 结果 / 约束

- **「文件观察」进词表**（`CONTEXT.md`），与「登记文件身份」「应用水位」三者互不
  替代：观察是某一时刻看见的文件系统事实，登记身份是系统认可的身份，水位是已落库
  的承诺。
- **收集层从此禁止读文件头、禁止碰 SUL_DB。** 这是本 ADR 唯一的硬边界；破了它，
  「间隔是自由参数」这个全部收益当场归零，而且不会有任何测试报警——需要一条守卫
  测试钉住。
- **单飞是硬要求**，不是性能取舍。两轮分析并行会同时写观察落库、同时装阶段纪元、
  同时入队，而 `seen_dbnums` 那套 F6 全集判定会变成两边各看半个世界。
- **分析 task 的生命周期必须绑 `async_watch`。** 事件流关闭时 `async_watch` 是按
  「看门狗死亡」报 `Err` 退出的，不能留一个孤儿 task 在后面默默入队。
- **间隔与失败策略仍然耦合**，本 ADR 不解。`BatchFailureLedger` 的连败预算数的是
  轮次（`MAX_ATTEMPTS = 5`），实际容忍时长 = 5 × 间隔。因此本期既不改自动重跑，也
  不动间隔默认值——两者要一起决定。想调间隔，先把「park 按时长还是按次数」拿出来
  单独裁决。
- **第一步必须补一行单轮耗时日志**，否则「实测之后再定间隔」这句话没有依据，本
  ADR 留下的那个决策会永远悬着。
