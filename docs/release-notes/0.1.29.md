# 0.1.29

- **版本号从 0.1.27 直接跳到 0.1.29。** 0.1.28 是 2026-09-18 从 `codex/model-projection-cache` 分支出的包，本版是主线 `gen-model-refactor` 自 0.1.27 之后的第一个包，两边内容不同，不能共用一个号。主线尚未合入该分支 09-17 之后的工作，所以 **0.1.28 说明里的这几条本版没有**：房间归属改在生成网格那一刻算、边随根回执落库（ADR-073 D1）；面板变化按新旧包围盒反查受影响的根（本版仍是本库整库重算）；房间点包含换成三方向射线奇偶；`GET /api/v1/spatial/surface-clearance`；隐式管身重发布的两条几何修复；校审三处修复。从 0.1.28 换到本版等于放弃这些，要两边都有得等下一次双向同步之后的版本。0.1.28 里的其余条目（`spatial/centerline` / `nearest-clearance` / `bran_centerline`、`element/ptset` / `plines`、元数据门开关退役、刚体前移三条排除）本版都有。
- **新增一组「版本与历史」只读接口，全部按需从会话链现算、不落库、不动模型（ADR-081；给 plant3d-web 的节点版本视图用）。** `GET /api/v1/model/versions` 给出最小交付单元（模型根）的版本表：每一版是哪个会话、谁、什么时候、动了什么（ams7997 332 个会话冷算 1.9 s，之后命中缓存 17 ms）；`GET /api/v1/element/versions` 对任意 refno 都受理，每一版并排给「本构件变没变」与「所属单元的折叠影响」两列；`GET /api/v1/node/versions?scope=self|subtree` 给容器节点（SITE / ZONE …）「仅自身 / 所有子节点」两种口径的时间线，每版附动了几个单元；`GET /api/v1/element/attribute-history` 是一个节点的属性变化时间线（会话 user / comment + 逐属性 before / after），`GET /api/v1/node/diff-summary` 是两版之间的差异摘要（索引差分 + 模型影响，按单元分组，不生成几何）；`POST /api/v1/model/history/query`（`tool=attributes`，`{ snapshot_key, arguments: { refno } }`）按快照回执钉住的 (source_file, sesno) 读某构件当时的属性，与 `element/attributes` 同一个渲染器出行，不存在回 `exists:false` 而不是 404。这些接口都不写库：重启后第一次查会再算一遍。
- **属性面板与 E3D 对齐。** `element/attributes` 换了渲染器：目录 noun 补上类型默认值行（E3D 自己 ATTLIST 那一页上有的行面板都有）、E3D 的 unset 不再算成诊断、UDA 字典默认值保留来源、运行期派生行只显示不可编辑；目录 noun 上 565843 那一格按 E3D 的名字印 `DETR` / `Detref`。对拍铺到整份 128 元素语料、17 个 noun，「E3D 有值而面板没画」归零。
- **空间与测量接口。** `GET /api/v1/spatial/centerline` 把一条 BRAN 的中心线按段给出来（成员的到达→离开点 + 隐式管身，每段带 noun / 是否隐式 / 外径），管-管间距因此改按「两条 BRAN 平行直段的中心距」算，不再拿包围盒近似；`nearby` / `nearby/refnos` 加 `source_mode=bran_centerline`；新增 `GET /api/v1/spatial/nearest-clearance`（沿中心线走廊按目标分桶取最近构件，每条候选带可直接画尺寸的两个端点）。`POST /api/v1/element/ptset` 直读构件目录的 P 点集，`POST /api/v1/element/plines` 给型材 PLINE 线端点并带 `snap_points`（SCTN 名下 FITT / SJOI / SUBJ / SNOD 的沿轴位置，对应 E3D Pick Settings 里 Significant Snap Points 那三档）。
- **进程内两块缓存有了数量上限，默认值按实测定（ADR-082）。** 此前模型投影 overlay 与生成用元素缓存都无界（7997 一轮就把进程从 768 MB 顶到 1.55 GB）。新键 `model_overlay_max_roots`（默认 50,000 根 ≈ 0.7 GB；只在 rocksdb 介质下逐出，且只逐出已落盘 ACK 的根，未落盘的不丢）与 `model_element_cache_max_entries`（默认 200,000 条 / 库 ≈ 0.7–0.95 GB，满则整张清）；**写 0 = 不限**，环境变量 `AIOS_MODEL_OVERLAY_MAX_ROOTS` / `AIOS_MODEL_ELEMENT_CACHE_MAX_ENTRIES` 压过配置。现值看 `/health.model_cache.overlay`（根数 / 记录数 / 估算字节 / 累计逐出）与 `/health.model_cache.element_cache`（每库条数与估算字节），都是被查时现算、不落库。被逐出的根读路直读 RocksDB、便宜路回退整根重算、整库房间重算从库读几何行。
- **元数据门改成两票判「不影响模型」的属性变化，不再靠一份五个名字的清单。** 一处属性变化只要满足「字典 DCHC=0」且「生成器一处都不按名字读它」，就归 `no_model`、不触发重算，账本分 `metadata_only` / `unread_attribute` / `cache_stamp` 三档；`CACHID` 与 `SPAMAP` 单列成戳，只有戳跳动的候选记 `cache_stamp`，不再混进「属性变了没有」的比较集；账本去向 `no_model` 的候选不再把根踢回整根重算。开关 `model_skip_unread_attribute_changes` 退役——它早已是空挡，`DbOption.toml` 或 `AIOS_MODEL_SKIP_UNREAD_ATTRIBUTE_CHANGES` 里还留着的，启动打一条告警提醒删掉，不影响运行。刚体前移便宜路径（`model_transform_cheap_path`，仍默认关）补了 P23 类、被属主消费的几何（负体 / 开孔 / 剖面 / 几何集）、EVALAT 规则 M 三条排除，并修了嵌套根共有记录被乘两次 Δ、含旋转不重算包围盒两处。
- **单元级发布（ADR-080）作为可选开关落地，默认关。** `model_unit_level_publish = true`（或环境变量 `AIOS_MODEL_UNIT_LEVEL_PUBLISH`）时，一根里只有几个最小交付单元变了就只重算、只提交那几个单元，其余记录原样保留；管段完整性门夹在产出与提交之间，触到的 BRAN 少带一段就整根回退到老路；「touched 但 0 单元」的根只推回执不重算。关着时行为与 0.1.27 逐位相同。真库探针 ams8000 五窗五根与整根重算逐字同章。
- **房间归属（`room_membership = true` 时）：输入不全降级不判死，整库重算可再武装。** 缺一个 DESI 库或一块面板没有几何，常驻房间模型进 `Degraded`（`/health.features.room.status = degraded`，`room_build.resident.missing_dbnums / problems` 列出缺口，`degraded_sections` 含 `room`），`e3d.room.lookup` 照 `Ready` 判，不再整批模型根被判死；每个任务开工前把常驻房间模型对齐到此刻的文件版本，房间代号改为计算输入摘要（D12）；面板自身变了（PANE 动几何、FRMW / SBFR 改名、CWALL / CFLOOR 搬迁）触发本库整库房间边重算（`RoomOnly`，D13），触发改成 durable 欠账 `dbnum_room_recompute_owed`，中途死掉下次照排；`model_room_generation` 盖的是算边那台计算器的代号（D14），`e3d.room.lookup` 多一道 durable 侧就绪判据。库函数 `fn::room_code`（hd 版）此前恒回 NONE，已修，随连接初始化脚本自动更新。
- **升级注意。** ① 不需要迁移数据：版本与历史接口不落库，`/health` 只多不少。② 配置里若有 `model_skip_unread_attribute_changes`，删掉即可。③ 两个缓存上限默认已开（50,000 / 200,000），内存充裕、想沿用旧行为的写 0。
