# 0.1.24

- 三维校审后台并入本服务：`/api/review`、`/api/users`、`/api/auth`、`/files/review_attachments` 四个前缀由 `aios-database.exe` 直接提供，不再需要单独部署旧端。提资单、确认记录、评论、批注状态、附件元数据与工作流历史落在与模型数据同一个 `SUL_DB` 的 ns·db 上，靠 `review_` 表名前缀分辨；不另开连接、不另开库，一份备份即覆盖全部校审数据（`docs/adr/ADR-075-review-data-persistence.md`）。
- 校审域的可用性与存储介质绑定，判据只有 `StoreMode::is_durable()` 一条，与 `/health` 同一个出处。按 ADR-074，介质只有两档：`mem`（进程内嵌，无端口，进程一退整库即空）与 `rocksdb`（连一台已在运行的 SurrealDB）；服务在任何档位都**不拉起**数据库进程。
- **出厂默认 `mem`，所以校审域出厂是关着的。** 这一档下四个前缀的任意路径、任意方法一律返回 `503` 与 `{"success":false,"code":"review.persistence.refused","message":…,"storeMode":"mem"}`。这是配置结果不是故障，也不是「这一版还没移植」——刻意不回 404，正是为了让前端能把「被配置拒绝」和「后端地址配错」分开。校审域之外的接口不受影响：模型侧 `/health` 照常 `200`/ok，服务也不会因为这一条退出。（`DbOption.toml` 里 `store_mode` 与 `in_memory_db` 两个键都不写时，生效档位同样是 `mem`。）
- 拒绝不是一行 warning，而是多行启动横幅：点名哪一档介质、哪些接口没了、为什么、改哪儿——运维不看代码就能判断。
- 启用校审域有两条路。① 正解：先自行启动一台持久 SurrealDB，把 `DbOption.toml` 的 `store_mode` 改成 `"rocksdb"`、`v_ip:v_port` 指向它，重启服务。② 只是演示 / 联调且明知重启即丢：设环境变量 `PLANT_REVIEW_ALLOW_EPHEMERAL_STORE=1`（认 `1/true/yes/on`）后重启，`mem` 档也照常启用校审域，但数据仍然活不过重启，启动横幅每次都会点名这次放行。
- 逃生门刻意做成环境变量而不是配置键：这不该是一个能躺在 `DbOption.toml` 里过一个月的决定，进程一停它就没了。没设、留空、拼错一律不放行。
- `rocksdb` 档连的 SurrealDB 必须是本仓 fork 的 2.1.x（包内 `bin\surreal.exe`）；别用 PATH 上 `cargo install` 装的 3.x，它会要求对数据做不可逆迁移，且与 2.1.4 客户端握不上手。
- 校审域的 `[review_auth]`、`[platform_auth]`、`[review_attachments]` 三段配置均可整段不写，不写即用缺省值。
- `scripts/New-LocalRelease.ps1` 新增 `-ReuseWebFromZip <zip>`：正常重建后端，但从一份既有的 `-full` 发布包复用 `web\`。适合后端单独发版，避免把 plant-ui 工作树里的未提交改动夹进同一个版本号。与 `-SkipBuild` 互斥——后者是连 `aios-database.exe` 一起复用。
- 复用 Web 设四道闸，任一不过即拒绝出包：必须指向 `.zip`；必须存在同名的 `<包名>.release.json`；该清单的 `plant_ui_version` 要与本次声明的 Web 版本一致（防错标版本）；三腿冒烟 `status` / `setup_leg` / `rocks_leg` 必须全部 `passed`；源 zip 的 SHA-256 要与清单里的 `zip.sha256` 对得上。
- `release.json` 如实记录 Web 来源：复用时 `web_source` 写成 `reused-from:<源包文件名>`、`web_source_sha256` 记源包哈希；正常构建仍是 `built-from-plant-ui`。
- `release.json` 新增 `e3d_io_git_commit`，打包时读 `vendor\e3d-io` 的 HEAD 提交，取不到记 `unknown`。与既有的 `backend_git_commit` 合起来，一份清单就能回答「这个包的后端与 e3d 解析库分别是哪一版」。
- `e3d_version` 仍是 `DbOption.toml` 的可选键、不进 `release.json`：未配置时默认 `e3d210`，出厂配置显式写 `e3d31`，项目来自 E3D 2.10 时请在初始化前改回 `e3d210`。发布包始终同时携带 `schema\e3d210` 与 `schema\e3d31` 两套 attlib / `*vir.dat`，服务不按目录名或数据库会话字段猜版本。
