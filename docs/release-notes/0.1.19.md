后端 gen-model 0.1.19 面向使用者/运维的更新说明。这份是手工提炼稿（gen-model 的 `changelog.md`
是按日期记的开发流水，太技术，不直接进发布包）。`New-LocalRelease.ps1` 组包时把本文件原样作为
CHANGELOG 的「后端」一节；下一版发布时在同目录新增 `<版本>.md` 即可。

### 模型与房间增量

- **MDB 源声明范围修复。** 更新范围此前会把「MDB 声明了、但当前项目目录里其实没有文件」的库也算进去，
  报的库数比真会跑的一批偏大；现在按真正会执行的库报数与排程。
- **补上缺失的 DESI 房间输入检查。** 房间增量在输入不完整（缺 DESI 房间输入）时不再默默走空，而是先检查。
- **新增房间原子结果提交模块。** 房间收尾的结果按文件回合原子提交，避免半截状态被别的路径看到。
- **三水位凭证读取。** 每个设计库现在读三枚水位——数据水位、模型水位、房间水位，作为「算到哪次保存」的凭证。

### 已知限制（本版不代表通过）

- **每库 Task 的纯内存房间路径尚未接完。** 本次发布不代表完整房间初始化、三次重启、或十轮内存验收通过。

### 运行依赖（部署时注意）

- **SurrealDB 是本仓 fork 的 2.1.x**（`bin/surreal.exe`；客户端 SDK 锁在 gitee fork 2.1.4）。
  **不要用 PATH 上 `cargo install` 装的 3.x**：它会要求对 `.surreal` 数据做不可逆迁移，且与 2.1.4 客户端握不上手。
- **默认 `store_mode = external`**：库不由服务自己拉起，需先有一台在 `127.0.0.1:8010` 跑着的 SurrealDB。
  要服务自带内存库（不连外部），显式设 `AIOS_STORE_MODE=spawned-mem`。
- **HTTP 面 `127.0.0.1:9099`。** 端口被别的版本占用时明确报错，不静默连上。
