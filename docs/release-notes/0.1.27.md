# 0.1.27

- **生成根的成败不再存表，只活在进程里；模型面唯一的持久事实是水位 `dbnum_watermark.model_sesno`（ADR-079）。** `gen_root` 一表五用（回执 / 失败留痕 / 规划输入 / 启动证据 / 目录落款），全 AMS 12 万根时一致性普查每 30 秒整表扫一遍 4–6 秒、每根落库多一笔 `UPSERT`，而 ADR-071 / 072 / 076 之后这五个角色没有一个需要持久化。现在每根一条 `Generated | Failed | Refused` 记在进程内账本，窗口规划、启动核对、一致性判决全部零表扫描；启动核对只比两枚水位——`model_sesno < applied_sesno` 才排 ModelOnly（`0` = 整库重排），库里再没有逐根的证据可拿来下调或清零。恢复口径不变：任务中途死掉 → 写入标记 → 整库重做；正常收尾但模型没成 → `model_sesno` 不盖 → 下一次按 `model_sesno → 文件最新` 重排。
- **存量库首次用本版启动时会删掉 `gen_root` / `root_dependency` 两表与 12 个 `fn::gen_root_*` / `fn::sync_*` 函数**（`REMOVE … IF EXISTS`，幂等，与其它退役表走同一段启动迁移）。这一步单向：删过表的库再回滚到旧版，逐根凭证是空的，等价于「全部根按需懒生成」。
- **接口面随之变化。** `/model/ensure` 回执的 `publication_status` 改由投影 ACK（`ready` / `stale`）与账本（失败带 `last_error`）合成，逐根 revision / target 四格不再出现；`/dbnums` 的「已追平 / 还在赶 / 已放弃」重启后从零起算（它们本来就是本进程的工作记录），「一致 / 落后」只看水位、不受影响；`/health.startup.no_credential_dbnums` = 模型水位从没盖过的 DESI 库；`/model/rebuild` 改排起点 0 的 ModelOnly，不再随身带全量名单。目录落款收成库级一份 `dbnum_watermark.model_catalogue_sessions = [{dbnum, session}]`，随 `model_sesno` 合并写。
- **掉线的 UNC 搜索根现在真的只等 15 秒。** 0.1.26 的 15 秒上限只管扫描线程，可线程起来之前对每个根算 key 的那一步走 `canonicalize`，在掉线的共享盘上会把调用方线程阻塞到 OS 自己放弃（现场 `\\<文件服务器>\<共享>` 实测 21 秒；接得上 TCP 但 SMB 不应答的服务器可能更长）——启动、重扫、向导「看闭包」每个掉线根都多等这一段，而且报的是 OS 的 `os error 53` 而不是「扫描 15 s 未答」。根的去重与闭包 key 改用字面归一（斜杠方向 / 大小写 / 末尾分隔符），不碰文件系统；代价是联接与其目标、8.3 短名这类「字面不同、实为一处」的根不再合并，各扫一遍、后到的列 `shadowed`，不阻断也不算冲突。
- **校审：校核回退次数算对了。** `count() … WHERE task_id = … AND action = 'return'` 命中索引时 SurrealDB 2.1.4 走计数捷径把 `action` 谓词整个丢掉，数出的是该任务全部历史条数；于是 active 之后 round 变 2，校核侧 agree / reject 按 `…:2` 找不到设计侧 `…:1` 的状态，一律 409「未找到设计处理状态」。改成只按索引列过滤、在聚合里数 action。
- **RVM 基线对拍：亚容差薄壳不再定成员 AABB。** FacetGroup 按连通分量算壳，`2·V/A < RES_TOL_MM` 的壳不参与成员包围盒；快照多一格 `subresolution_shell_count`（旧快照缺它按 0 读）。
- **发布包只剩 `runtime` 一档，`workspace\` 一律不进包。** 打包机现场的 `config\`、`search-index\`、`accel_tree_*.snapshot` 与 `assets\` 都带着本机项目的痕迹，发出去既撑大 zip 又让现场以为那是自己的数据。运行期资源由目标环境自己提供：`Start-AMS.ps1 -Workspace <路径>` 或环境变量 `AMS_WORKSPACE` 指过去，不指就用包根（`assets` 缺失时后端自己在包根下建）。包根仍附 `bin\surreal.exe` 与 `Start-Surreal.ps1`（rocksdb 档先自己起库）、`.first-run-pending` 首跑哨兵（解压即进配置向导）。
