# 0.1.26

- **这个服务要开哪些项目，改由 MDB 说了算；每个项目的目录，到人指定的几个搜索根里按项目码找（ADR-078，取代 ADR-046）。** 此前靠配置里一份人手勾出来的 `included_projects` 名单：少勾一个项目，那个项目里的库就成批落空——0.1.25 的现场只勾了主项目，MDB `/ALL` 声明的 40 个外部库全部找不到文件，启动刷 40 条「声明了 dbnum … 项目目录里却没有它的文件」，点「显示模型」只报一句「db 7001 没注册进这个 DbSet」。E3D 自己没有「项目名单」这回事：每条 CURD 声明自带项目码，core.dll 拿它拼 `%<项目码>000%` 去定位。现在项目集合从主项目 SYS 里该 MDB 的声明现算，`included_projects` 退役。
- **配置只剩四项：`project_path`（主搜索根）+ `project_search_paths`（其它搜索根，本地或 UNC，顺序即优先级，可空）+ `project_name`（主项目）+ `mdb_name`。** 项目码 → 库目录按 `set_project_evars.bat` 文档化的三种摆法找 `<code>000`（`根\<code>000`、`根\<项目>\<code>000`、`根\<项目>\<层>\<code>000`），目录名不区分大小写；同一个根里同码两处算冲突、不选，跨根先到的根赢、其余记影子；每个根在独立线程里扫、15 秒超时，掉线的共享盘只让它自己缺席，不拖死启动。不读 `<CODE>000` 环境变量、不解析也不执行 `evars*.bat`——远程项目请把装着 `<code>000` 的目录填进 `project_search_paths`。
- **老配置照旧能起。** `included_projects` 这个键留着（`aios_core::DbOption` 加了 `serde(default)`，删掉整行也装得进来），但不再参与任何解析；非空时启动只多打一句「已忽略，本次由 MDB 派生：AMS(主) / ACP→AvevaCatalogue / …」。`catalogue_project_priority` 保留，校验对象改成闭包里的项目名。
- **缺口开始说人话。** 声明落空一路带着项目码走到底：启动横幅归并成一段闭包摘要（搜索根几个、哪个不可达、每个项目码落在哪个根、外部库定位了几个）加每个未定位项目一句；`/health.mdb_closure` 给出 `roots / projects / seen_projects / unresolved / problems`，有缺口时计入 `degraded_sections`（不拒绝启动）；按需生成与 `/model/ensure` 的错误尾巴追加路由目录给出的原因——「MDB /ALL 声明了 dbnum 7001（\*MASTER/STLCATA，项目 ACP），搜索根里没有 acp000 库目录……加进 `project_search_paths`」。
- **配置向导第①步改成「搜索根 + 主项目 + MDB → 看闭包」**，没有项目勾选框了。新探测 `POST /api/v1/setup/probe/mdb` 不依赖运行中的服务，直接跑一遍闭包，页面画成项目码 / 目录 / 所在根 / 库数 / 影子的表；未定位的项目码与不可达的根红字列出，仍有缺口时保存前要确认。
- **出厂模板 `room_membership` 从 `true` 改成 `false`**，与代码默认一致。开着它时常驻房间要 MDB 声明的全部设计库都在，缺一个库整批模型根都会被判死（上一版现场 1112 的 18 根、7997 的 6772 根就是这么全灭的），而向导并不暴露这个键。单测钉住模板值与代码默认不再分叉。
- **Windows 的目录联接（junction）现在算目录。** 搜索根里的项目目录挂成联接指到别的卷是常见摆法，而 `read_dir` 的 `file_type()` 对它报 symlink 不报 dir——不跟一步整个根会扫成空，连主项目都定位不到。
- **`aios_db.parse.sessions` 的 `computer_name` 别名按 0.1.25 的预告删除**，会话页只剩 `user`。那一格是 core.dll 的会话属性 `USER`（写这一会话的登录名），从来不是机器名。仓外脚本还读 `row["computer_name"]` 的会 `KeyError`，改读 `row["user"]`。
