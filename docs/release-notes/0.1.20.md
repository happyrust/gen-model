面向使用者的更新摘要（后端 gen-model 0.1.20）：

- **首跑配置向导**：解压 -full 包、双击 `Start-AMS.cmd`，浏览器自动进入 `/setup.html` 五步向导——选 E3D 项目目录（带探测）→ 选存储（连已有 SurrealDB 带连通与版本校验，或试用模式）→ 定监听端口（带占用预检）→ 选「只导数据 / 一步到位」→ 保存自动重启 → 勾库初始化看着水位追平。不想用向导：直接改 `workspace\DbOption.toml`、删 `workspace\.first-run-pending` 再重启，效果一样。
- **配置写盘不毁注释**：向导保存走逐键修改，`DbOption.toml` 里的注释与你手写的其他键原样保留，写前自动落 `DbOption.toml.bak` 备份。
- **设置模式**：配置还没配好（项目路径缺失、库地址未填）时，服务不再在启动早期直接退出——改为只起网页面供向导使用，`/health` 会标 `mode:"setup"`。库地址填了但连不上仍按真故障处理（启动失败退出），不会被误当成「未配置」。
- **配置接口只认本机**：`/api/v1/setup/*` 只接受来自 127.0.0.1 的请求；局域网可以正常用应用（出厂监听 `0.0.0.0:9099`），但改配置必须在服务器本机浏览器里做。SurrealDB 版本校验不放行 3.x（必须包内 fork 2.1.x）。
- **出厂包形态变化**：包内 `workspace\DbOption.toml` 现在是中性出厂模板（不再是打包机的配置快照）；新增 `.first-run-pending` 首跑哨兵。老部署（自有 workspace 配置）行为不变。
- 已知边角：向导触发自重启后，包根 `process.json` 记录的还是旧进程 pid（仅影响那个记录文件，不影响服务）；在本机用局域网 IP 打开向导也会被拒，请用 `127.0.0.1`。
