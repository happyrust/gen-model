# 0.1.23

- DbOption.toml 新增 e3d_version，支持 e3d31、e3d210；手动指定时直接选择对应模板包，不根据数据库二进制猜测版本。
- 手动版本优先于 AIOS_E3D_TEMPLATE_DIR；两者都未指定时使用产品默认 e3d210。错误版本、配置解析错误或缺失模板会报错，不静默改选另一版本。
- 部署包继续携带两个版本的 schema，运行时优先使用包内资源；出厂配置显式选择 e3d31，可按工程修改为 e3d210。
- 启动日志输出 mode=manual/default、有效 e3d_version 与 auto_detect=false；默认路径仍输出数据库二进制版本证据供排障，但证据不参与选版。
- 每次正常构建发布包都会嵌入唯一的 `<版本>+release.<UTC时间戳>.g<提交>[.dirty]` build_id，ZIP 文件名、EXE `ProductVersion`、`version --json` 与 `release.json` 使用同一身份；旧构建不再被同版本新包覆盖，可直接作为后续二进制 patch 的精确源基线。
- 二进制 patch 的默认文件名同时带源/目标 build_id 与目标哈希前缀；同一 Cargo 版本内的多次构建也能从文件名直接分辨升级方向。
- 每份 patch 同时生成 `.install.ps1` 自动安装脚本：先校验旁置哈希和 dry-run，只停止路径精确匹配的旧进程，升级后校验目标哈希与 `/health.build_id`；启动失败时原子恢复 `.bak-*`，并在升级前服务原本运行的情况下尝试重启旧版。
- 新增单文件 GPUI `AIOS-Patch-Maker.exe`：可在图形界面依次选择现场旧 EXE 与新版 EXE，实时查看两端 version/build_id/SHA-256，异步生成补丁并在界面内展示结果、打开产物目录；Patch Engine 已内置，无需旁置程序。补丁默认输出到旧 EXE 同目录；命令行仍可用 `make <old-exe-or-zip> <new-exe-or-zip>`，支持混用或直接传两个发布 ZIP。程序在交付前自动完成 dry-run、真实替换、备份哈希与二次幂等自检。
- Global Project 的 MDB 跨库声明可用：解析 `<项目>sys` 时会扫描同目录项目元数据库，以各文件头自报的 dbnum/type/session 建 resolver，按需用 `glbvir.dat` 打开 `<项目>glb`；不写死 8188，也不按文件名猜库号。`*glb` 同时纳入启动扫描，发布包强制校验 GLOB/SYS/COMM/MISC 模板齐全。
- `room_membership=true` 的 spawned/embedded kv-mem 新增冷启动房间屏障：resident 就绪后串行生成 MDB 全部 DESI 根并逐根发布模型行、房间边与回执，全部成功后才置 `model_ready`。
- ready 根新增进程级完整发布 ACK；候选几何不再能在房间/数据库事务失败后冒充完成。`/health` 暴露 `room_bootstrap` 进度，`e3d.room.lookup` 增加 `calculation_status`。
- `/dbnums/{dbnum}/model/rebuild` 在 memory 路由下复用整库即时执行器，不再进入无消费者的 durable queue；read-through 版本三元组仍保持 `null/null/unsupported`。
- `http_api_addr` 缺失或留空时不再让 read-through 服务无错误退出：后端先兼容旧配置的 `server_release_ip`，两者都空时提供 `127.0.0.1:9099` 本机默认访问；`/health.http` 与启动横幅同步报告最终生效地址。
