# 0.1.25

- **一个 dbnum 的增量任务，等到本批根真的刷进 RocksDB 才算结束（ADR-076 S1–S3）。** 此前任务置 `durable_pending` 就返回，存在一段「任务说完了、盘上还没有」的真空：任务完成信号、模型水位与盘上的行三者不同时到位。现在任务等的是**本任务单元清单里的那批根**（同库里 `/model/ensure` 按需生成登记的根不算本任务的账），收尾一笔事务同时盖 `model_sesno` + 写入标记 `finished` + Ref0 统计。模型水位从此只有任务一个写者。
- **刷盘有预算，用尽不原地空转。** 每根最多 5 次重试（退避 1+2+4+8+16 秒），整批 10 分钟护栏；判死或用尽的根从待刷队列摘掉、从进程内投影逐出（读路落回库里的旧行——落盘的才是真值），对应单元记 `Failed`、`gen_root` 上留 `status=failed` + `last_error`，任务判 `Partial`、`model_sesno` 不盖但写入标记照收。不收标记会让一个确定性失败的根变成「每次启动整库重建 → 同一根再失败」的跨重启活锁；标记收下后由缺口重排恢复。
- **任务进度里能看见刷盘。** `durable_pending` 成为任务内的一个阶段并带「已 ACK n / 共 N 根」的进度，不再是一个立刻掠过的瞬时态。
- **`/health` 去掉四格已无意义的水位镜像**：`settlements`、`settlement_state_by_dbnum`、`durable_target_by_dbnum`、`memory_target_by_dbnum`。它们属于随本版整条退役的 write-behind `settle` 机制（模型水位改由任务自己盖，后台不再持有它）。有脚本读这四格的请改读任务回执与 `model_sesno`。
- **初始化 dbnum 改走两条并发写入 lane 直接落盘（ADR-077）。** 属性面与模型面写的表互不相交，此前却被「模型开工要先读 `pe` 表枚举根」这一处硬串起来；现在枚举根直接从文件做，两条 lane 并发写 RocksDB，任务收尾一笔盖两枚水位。初始化的模型行不再先进进程内投影、再由 write-behind 渲成 SQL 刷库——初始化期间没有人读那份投影，绕这两层只是白费一份整库内存。
- **同一个目录元素在一个进程里只解析一次、只渲一次、只往属性 lane 发一次。** 新增 CATA 依赖闭包的进程内缓存：键是「项目 / 目录库 / refno」，条目盖着「文件指纹 + 目录会话号」的库级戳，跨初始化任务与增量窗口保留，文件身份一变整库作废；有界 LRU（200,000 条 / 256 MiB 双上限），没有运行时开关。AMS 8000 同一批种子连解两次：冷启 456 ms、热 57 ms（13,995 命中），闭包逐位相同。RocksDB 仍是唯一事实，不加持久化缓存表。
- **已经落过库的依赖行不再重发。** 事务全部成功之后才记账；目录版本前移、整库 wipe 与运维口 `DELETE /dbnums/{dbnum}` 三处都会作废这份记忆——此前删库只清行、不清记忆，之后的任务会按记忆跳过不发，缺的行要等重启或目录版本前移才补得回来。
- **整库取根改成每个 ZONE 一根，不再上溯 SITE。** SITE 根会罩住邻居 ZONE，整片删会抹掉别人刚落一半的行。7997 上 142 根、生成 17.4 s（按文件顶层取根是 25.8–32 s），回读六项与旧口径逐字相同。只动整库取根这一处：生产的整库初始化与增量归根仍落到交付单元根。
- **池级元素缓存默认打开。** 生成阶段的 B+ 树点查大幅减少：7999 生成 71.0 → 3.84 s（点查 5,369,928 → 46,168 次），7997 18.2 → 7.19 s，1112 2.4 → 1.45 s。代价是缓存不淘汰、内存涨（7997 峰值 768 MB → 1.55 GB），换的是时间与内存、不是产物——三个库回读六项两态逐字相同。内存吃紧的现场用环境变量 `AIOS_MODEL_ELEMENT_CACHE=false` 关掉（拼错当没设，回默认开）。
- **`inst_relate.dt` 退役。** 读侧本来就不给日期，写它却要每批按 `(dbnum, sesno)` 点查 `ses` 行。要日期改用 `fn::ses_date(in.id)` 读时现算；一条 `ses` 行都不播也解得出 anc/dbnum。
- **一根的切片改为一笔带谓词的事务发布**，减少模型发布阶段的往返。
- **`Q MEMBERS` 数的是名词序号、不是行号**（`e3d_query`）；此前在成员列表上会数错。
- **RVM 基线对拍**：`resolve` 独立成模块、`compare` 判据扩充；Pyramid 偏心按记录盒裁决减回去；`UDET` 名词整串进键（不再截四字）；TTY 打 UDET 名时只比身份并单独记一笔。
- **Python 调试绑定跟上 `generate_and_persist_roots`**，相关脚本在找不到配置的解释器时回退到当前解释器。
- `model_cache_mode` / `AIOS_MODEL_CACHE_MODE` 这个一直没有实现者的配置随 ADR-076 D13 删除，策略写死。配置里留着这一键不会报错，但也不再有任何效果。
