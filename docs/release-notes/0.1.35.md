# 0.1.35

> 提炼稿（2026-10-09 起草，发版时补齐构建来源与验证段）。本版两条**行为变化**都来自 ADR-086（plant-ui ADR-0030 的服务端半边）。

- **`POST /api/v1/model/ensure` 改名 `POST /api/v1/model/generate`。** 请求体、回执、状态名（`AlreadyAvailable / Generated / NoRenderableGeometry`）与 `force` 语义一字不变，改的只是名字说的事：客户端调它就是要生成，不是「确保有」。旧路径 `/model/ensure` 本版仍可用，是指向同一 handler 的别名，每次命中打一行 `deprecated: POST /api/v1/model/ensure is an alias of /api/v1/model/generate and will be removed next version`；**下一版删除**，还在调旧名的客户端（plant3d-web 的 e2e、`l3_suite` 夹具）请在此之前切到新名。`[model.worker.*]` 的字段名不动。
- **`POST /api/v1/model/records` 对没生成过的范围回 `200` 空数组，不再 `409 not_generated`。** 请求里的根在每条路由上都按**祖先**理解：rocksdb 路由本来就是 `anc CONTAINS <节点>`；内存投影路由此前只认精确生成根（给 ZONE / SITE、或 BRAN 里的一个 VALV 都是 409），现在节点在根之上就展成名下盖过章的生成根逐根取，节点在根之下就取它头上那根的记录、按祖先链只留它名下的，`owner` 三种情形下都是生成根。一条都没有 → `200` 空；`409 conflict` 只剩该库正被整库任务占用。回执形状不变，`roots[]` 里没生成的根 `total = 0`、`items` 里缺席。**消费者注意**：把 `409 not_generated:` 当「先去 ensure 再重试」分支用的客户端（plant3d-web `modelRecords.ts` 的 `isNotGeneratedConflict` 一次重试、`verify-gen-model-v1.ps1` 的整批退回逐根）从本版起走不到那条分支——它们本来就先 ensure 再 records，主路径不受影响；并发时「别人正在生成这根」的情形会表现为这一根暂时 0 条，而不是 409。
- **验证。** 本节发版时按实际结果改写。起草时：`cargo test --lib` 中 `web_service::` / `fast_model::model_memory_store::` / `fast_model::model_record_reader::` 三个模块 321 passed / 1 failed，唯一失败仍是 0.1.34 已点名的 `plant_ui_web_bundle_contains_bootstrap_and_runtime_assets`（内嵌 `index.html` 字符串，与本版改动无关）；`cargo test --test refno_native_api_contract` 4/4。新增用例：`receipt_roots_under_an_ancestor_lists_the_committed_roots_below_it`、`model_records_answer_by_ancestor_and_never_say_not_generated`、`the_ensure_handler_is_a_deprecated_alias_of_generate`、`the_ensure_path_is_an_alias_of_generate`。
