# 0.1.31

- **本版是 `codex/model-projection-cache` 分支并入主线 0.1.30 之后的第一个包，两条线的内容都在。** 0.1.28（2026-09-18，该分支）与 0.1.29 / 0.1.30（2026-09-21，主线）各出各的，互不包含。从 0.1.29 / 0.1.30 换过来，找回 0.1.29 说明里列的「0.1.28 有而本版没有」那几条：房间归属在生成网格那一刻算、边随根回执落库（ADR-073 D1）；面板变化按新旧包围盒反查受影响的根（ADR-073 D13）；房间点包含换成三方向射线奇偶；`GET /api/v1/spatial/surface-clearance`；隐式管身重发布的两条几何修复；校审三处修复。从 0.1.28 换过来，补上 0.1.29 / 0.1.30 的主线内容（ADR-081「版本与历史」只读接口、属性面板与 E3D 对齐、ADR-082 两个缓存上限、ADR-083 存储介质只由 `AIOS_STORE_MODE` 决定），详见那两版说明。以下是 0.1.28 与 0.1.29 / 0.1.30 说明里都没有的条目。
- **交付删除记录 `datacenter_delete` 与只读查询口 `GET /api/v1/datacenter/deletes`（plant-ui #1「增加删除标记」）。** 增量在交付单元被删、或交付单元自身改了位号（NAME）时各记一行：`reason` 为 `deleted` / `renamed`，记的是改前的位号、沿属主链上溯到的最近 ZONE、变化所在那一版的 `sesno` 与写入时刻；下属管件的变化与位号首次出现不记，同一构件 A→B→C 改两次记两行。gen-model 对这张表只写不删。查询口按 `zone_refno`（可逗号分隔多个）/ `dbnum` / `reason` / `since_sesno`（须同时给 `dbnum`）/ `from`–`to`（按写入时刻取半开区间，RFC3339 带时区或纯日期，纯日期按北京时间零点）过滤并分页（`limit` 缺省 500、上限 5000），每行附 `published`：该构件是否已进 `datacenter_version`。参数解不出回 400，鉴权与其它 `/api/v1` 接口相同。
- **房间层级树接口（plant3d-web ADR 0067 / 0068）。** 新增 `GET /api/v1/spatial/rooms`、`GET /api/v1/spatial/nearby/tree` 与 `GET /api/v1/spatial/rooms/{refno}/tree`（把附近 / 房间内的构件折成层级树；房间不在册回 400）；`nearby` 加 `rooms=` / `spec_values=` 过滤，排序多一个 `spec_distance`。两条树路由另有 opt-in 的 `tubes=1`：按 BRAN 单元列出直段，直段按两端归属判房间，穿过房间盒但两端属于邻房的不列；不带这个参数时响应逐字节不变。
- **`model/records` 的隐式管身记录带直段身份。** 每条隐式管身记录多一个 `tube{ordinal, from, to}`，与树路由 `tubes=1` 列出的直段是同一身份，前端据此把两边对上；`tubi_relate` 落 `route_ordinal`。其余字段一字不改；缺端点的老行不带 `tube`。
- **内存可控（ADR-084 / 增量内存控制计划）。** 新配置 `model_generation_input_max_dbnums`：生成输入缓存最多同时留几个库（约 0.7–0.95 GB / 库，最久没用的先出），默认 0 = 不限；`model_historical_snapshots_max`：历史快照最多留几格，**默认 16**，最久没 generate 的先丢，再查那一格回 `SNAPSHOT_NOT_FOUND`。出厂 `DbOption.toml` 把 overlay 根数、元素缓存、生成输入、历史快照四道闸都写明，并与代码默认一致。overlay 按根数逐出时不再逐掉「ACK 是房间边唯一证据」的根，逐出不再留下孤儿 ACK，逐出持写锁的时间变短；`/health` 的 `model_cache.historical` 与 `/ops.html` 底栏多出 overlay / 元素缓存 / 历史快照三格。
- **整库房间重算的冷读不再退成全表扫描（ADR-082 追记）。** 从库里读冷根几何的 SQL 拆成两条、各走索引：SurrealDB 2.1.4 遇到「OR 再挂 AND」会整条退回扫全表，d-149 真机上 `RoomOnly` 一窗跑了 67 分钟、看上去像卡死，根因在此。
- **目录表达式里的 UDA 读得出了：模型生成挂上 MDB 声明的字典库。** 字典库进入模型目标身份，字典换版会让相关回执作废。连带修了 `/model/ensure` 的几处误判：会话位 0 的字典库项只按摘要判新旧，不再每根每次 409 重生成，冷启动也不再把六本字典库误判为「前移」而整库重发布；生成完了后验仍不新时单列 `ModelStaleAfterGeneration`，说明是源前移还是目标核对不过；撞上「正在后台生成」回 409 而不是 500。
- **`e3d.room.lookup` 回码更正。** 库里没有的 refno 回 404（原 500 `internal`），`SOURCE_UNAVAILABLE` 归 503；没有生成根的元素回 `not_computed`（原 409「updating」）。
- **网格目录只剩一个解析口：`PLANT_ASSET_ROOT` 压过配置里的 `meshes_path`。** 生成落盘、`/assets/meshes` 与房间面板预热读写同一个目录（ADR-068 追记 D7）。两者指向不同目录的现场，升级后以 `PLANT_ASSET_ROOT` 为准。
- **增量判决：字典置了 `WNOEVT` 的属性被写时不再触发模型重算**（E3D core 对这类属性本身就不发变更事件）；`SPAMAP` 与 `CACHID` 同档进戳表。
- **房间反查（ADR-073 D13）的一组可靠性修复。** 定向重算复用任务开工时冻的计算器；换代段账本让任何任务的定向准入都能接上；常驻代号回到旧值时，中间那一代生成的根点名重算；盖章之后按另一代写过的根记进水位行新格 `model_room_stray_generations`，重启不丢；任务收尾遇到写冲突改为重试，不再落 `Partial`。
- **几何与属性。** 圆弧墙两端按 SPINE `DRNS` / `DRNE` 斜接（vendor e3d-model；WF05 RR001 WALL 4 与 E3D TTY RVM 对上 130 / 130）；E3D 类型 19 的文本列表属性在 `element/attributes` 里显示为 `text-array`（vendor e3d-io 0.3.0）。
- **升级注意。** ① **生成器指纹多了一项（`catalogue-pml-uda-key-v1`）**：0.1.30 及更早写下的模型回执与本版对不上，对应的根下次 ensure / 增量时整根重算一遍，第一次会明显比平时慢，之后恢复。② 从 0.1.29 / 0.1.30 换过来：房间点包含判据变了（见 0.1.28 说明），存量 `room_relate` 不会自己重算，每个 DESI 库发一次 `POST /api/v1/dbnums/{dbnum}/model/rebuild`。③ 历史快照默认封顶 16 格；`model_generation_input_max_dbnums` 缺省 0 = 不限，与旧行为相同。④ 不需要迁移数据。
