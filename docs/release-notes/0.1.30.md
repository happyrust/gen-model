# 0.1.30

- **存储介质改由启动环境决定，配置文件与向导不再管它（ADR-083）。** 服务连内存库还是持久库，此前由三层叠加决定：环境变量 `AIOS_STORE_MODE` > `DbOption.toml` 的 `store_mode` > 更老的 `in_memory_db`。现场真踩过：文件写着 `rocksdb`，会话里残留的 `AIOS_STORE_MODE=mem` 把它压成内存库，服务照常起、模型照常对，只有属性行一直不进库，日志一个字没提。本版起**只认环境变量 `AIOS_STORE_MODE`**（`mem` / `rocksdb`）：`DbOption.toml` 里的 `store_mode` / `in_memory_db` 与环境变量 `AIOS_IN_MEMORY_DB` 一律不再生效——文件里还留着这些键的，启动日志会整行点名「已不生效、实际按 X 跑、要按文件那一档请设 AIOS_STORE_MODE=X、请把这一行删掉」，向导第②步也不再有存储单选，只展示本进程实际跑的那一档与它的出处（`GET /api/v1/setup/config` 的 `effective` 多出 `store_mode_source` / `store_mode_env` / `store_mode_env_value` / `stale_config_store_mode`）。`v_ip` / `v_port` 仍在文件里：它们是「rocksdb 档连哪儿」，不是「要不要 rocksdb」。
- **漏设 `AIOS_STORE_MODE` 时按 `rocksdb` 起，不再默默落到内存库。** 两种漏法的代价不对等：兜底 `mem` 时服务起得来、模型对得上，只有属性行不进库、校审整域 503、重启即清空，要查半天；兜底 `rocksdb` 时地址上没库就当场 `SurrealDB 连接失败（ws://…）` 退出（exit 1），一眼知道漏了什么。默认落在会喊的那一侧。`mem` 仍可显式选。
- **发布包「解压即跑」不靠默认兜，改由启动脚本说出来。** 包内 `Start-AMS.ps1` 新增 `-StoreMode mem|rocksdb`：给了以它为准；不给、且调用方环境里也没有 `AIOS_STORE_MODE` 时显式回填 `mem`（环境里已有的照旧沿用，不被盖），日志 `STORE_MODE=` 一行标出这一档是参数给的还是包默认。出厂 `DbOption.toml` 不再写 `store_mode`。要数据活过重启：先 `Start-Surreal.ps1` 起库、向导填地址、再 `Start-AMS.ps1 -StoreMode rocksdb`。
- **升级注意。** ① 不需要迁移数据。② **手工直起 `aios-database.exe`（不经 `Start-AMS.ps1`）的现场要改习惯**：以前靠文件写 `rocksdb` 就落盘，现在必须 `AIOS_STORE_MODE=rocksdb`（Windows：`$env:AIOS_STORE_MODE='rocksdb'`；systemd：`Environment=AIOS_STORE_MODE=rocksdb`）；不设的话会去连 `v_ip:v_port`，端口上没库就起不来，失败信息里带着地址。③ 配置里若还有 `store_mode` / `in_memory_db`，删掉即可，留着只会在启动日志被点名、不影响运行。④ 校审模块要求持久库的判据不变，拒绝启用时的提示改为指向「先起持久 SurrealDB、把 `v_ip:v_port` 指过去、再以 `AIOS_STORE_MODE=rocksdb` 重启」。
- 其余：内存模式启动横幅「由 环境变量 AIOS_STORE_MODE 定的」补上空格；校审 JWT 密钥 `[model_center].token_secret` 的配置模板与规格说明改口（PMS 不持有密钥，密钥只需本机签 / 验一致），不改运行行为。本版与 0.1.29 之间没有别的运行时改动；0.1.29 说明里「0.1.28 有而本版没有」那几条本版同样没有。
