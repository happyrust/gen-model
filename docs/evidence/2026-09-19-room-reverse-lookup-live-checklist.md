## 0. 每条都要看的那几行

| 看什么 | 在哪 | 形状 |
| --- | --- | --- |
| 定向成功 | stdout | `dbnum=N 定向房间重算完成（触发：…；计算器 g…（本任务开工冻的）；换代段 K 段 …；反查 roots=… tree_hits=… tube_hits=… member_hits=… cross_library=… foreign_libraries=… unresolved=…（库上管身范围查 Nms、回库取祖先链 K 个 Mms、面板现存成员 P 块 Qms）；停放链 S 段 E 个元素 → R 根）：根 a/b 重算 …，耗时 Tms` |
| 退整库 | 任务回执 `warnings` + stdout | `… 定不了，退整库` / `…，反查不完整，退整库`，随后一行 `dbnum=N 整库房间重算完成（触发：…；定向反查定不了，退整库）` |
| 准入接了哪几段 | 回执 `reason` | `沿换代段账本接了 K 段：g… → g…（removed=… renumbered_rooms=… recalc=… (geometry_only …)）` |
| 停放 | stdout | `dbnum=A 定向房间重算：已为 dbnum=B 停放 E 个元素（g… → g…），它的槽里现有 S 段` |
| 清槽 | stdout | `dbnum=B 定向房间重算成功，槽里消费过的 C 段停放物清掉，任务期间新停进来的 L 段留给下一个任务` |
| 账本 / 槽 | `GET /health` | `room_build.resident.swap_ledger = {entries, capacity, oldest_age_ms, segments[]}`；`room_build.parked = { "<dbnum>": {entries, elements, oldest_age_ms, segments[]} }` |
| 库上代号 | `/sql` | `SELECT dbnum, model_room_generation FROM dbnum_watermark;` |
| 某块面板名下的成员 | `/sql` | `SELECT VALUE out FROM pe:⟨<word0>_<word1>⟩->room_relate;` |
| 某个构件在哪间房 | `/sql` | `RETURN fn::room_num_of(pe:⟨…⟩);` |

判据的总口径：**漏算 > 多算**。任何一条里出现「该删的边还在」就是红；出现「本可定向却退整库」是黄（记下原因那一行）。

### C8 · L2 —— 库上管身范围查询的成本（钉 29）

- 操作：7997 上任意一次定向（C1–C6 任一条顺手记）。
- 记：`（库上管身范围查 Nms、回库取祖先链 K 个 Mms、面板现存成员 P 块 Qms）` 与末尾 `耗时 Tms`、`读回几何 … {}ms`。
- 判据：`N` 明显压过其余（例如 N > T/2）→ 做 `tubi_relate.aabb_d` 平副本，并决定回填还是查询分两半；否则不动。
- 结果：**不动**。S1（R286 挪位，15 根）：N=2156ms K=27 M=17ms P=1 Q=18ms T=20540ms，`读回几何 925 条 19120ms`；
  S3（15 根）：`读回几何 1195 条 17010ms`，T=17535ms；S5（10 根）：`读回几何 403 条 11998ms`，T=12514ms。
  管身范围查只占 T 的一成，压过一切的是**逐根回读库上几何**（~50 条/s）——要提速先看这一段（也是 C5 那次整库慢成小时级的根源），不是平副本。
- 追记（整库那一窗的量，C5）：`回读库 6769 根：读回几何 66418 条、4913815ms` → **0.73 s/根、13.5 条/s**；定向 S7c `15 根 1195 条 9741ms` → 0.65 s/根。一根有几条几何
  代价都是那 ~0.7 s，**慢的是每条查询的固定开销，不是数据量**。`model_record_reader::durable_records_of_root` 一根发两句（`inst_relate` / `tubi_relate`），
  `WHERE (anc CONTAINS {packed} OR in = {owner}) AND aabb.d != NONE AND world_trans.d != NONE`——`anc` 与 `in` 各有索引（`idx_inst_relate_anc` / `_in`），
  但两个索引字段用 `OR` 接，按「固定代价、与根大小无关」的形状推是退成了两张表各扫一遍（**推断，没跑 `EXPLAIN` 钉**）；每行再跟三次链（`in.old_pe`、
  `out.ptset.d.pt`、`insts_flat` 缺时的 `out->geo_relate` 子查询）。`recompute_dbnum_room_edges` 里 `for root in &durable { … .await? }` 逐根串行、不批不并发；
  surreal 进程累计 CPU 5204 s ≈ 回读的 4914 s 墙钟——整段就是库内一个核在扫。修法见 §2。
