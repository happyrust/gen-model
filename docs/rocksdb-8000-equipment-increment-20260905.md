## 对比口径

逐件匹配设备子元素，并比较 RVM 面片的世界包围盒与模型接口包围盒；修复局部变换后，还用标准 BOX 的八个顶点依次应用实例变换和世界变换，验证实际渲染边界。容差 0.01 mm，通过样本最大误差约 0.00068 mm。此结果不代表任意复杂曲面、布尔孔洞或拓扑已经验证。

## 本轮修复

1. `on_demand_model.rs`：直接模型读取路径不能仅凭磁盘发布凭证判定可用；还要确认内存根可用，返回数量使用内存模型口径。
2. `increment_manager.rs`：ingest 监听路径刷新 MDB 快照，使直接树感知源文件新会话。删除时 Plant UI 已展开的树分支自动从两个子节点变成一个，验证了无需重启的更新。
3. `handlers.rs`：普通标准图元在模型记录接口中传递 `local_transform`，包含 BOX 尺寸缩放。隐式管身已合并此变换，避免重复应用。旧记录的网格边界误差约 307/465 mm，修复后小于 0.001 mm。

构建成功；`cargo test --lib on_demand_model` 为 12 通过、1 忽略。新增的真实 RVM 比较可以对旧模型记录复现缩放错误。

## 尚未通过的检查

- 删除发布收敛：`deletion-observed/publication-timeout.json` 和 `durable-state.json` 记录了 292 已应用、模型发布仍为 291、根任务 running。界面过滤了删除元素，但模型内存尚有旧记录；不能只凭画面判成功。
- 删除后 `pe` 有 `deleted=true, sesno=292`，BOX 属性行仍保留 XLEN=700、POS=[1000,0,0]。这是实际保留状态；是否符合历史备份策略需按数据生命周期规则判断，不能简单称为物理清除。
- UI 设备属性能读取，但同时出现房间归属查询失败和文件属性不完整诊断。本轮没有将这些标记为通过。
- 本轮没有重复整个 RocksDB 文件重启哈希校验；之前的落盘/重启验证见 `rocksdb-8000-validation-20260905.md`。

## 复跑方法

`scripts/equi8000_live.py` 提供 edit、capture、compare。阶段目录必须唯一，以免覆盖旧证据。`capture` 最多等待 150 秒，使发布目标和模型数量收敛；超时仍保存失败现场，不自动强制生成。`capture-now` 立即保存当前状态。`compare` 非零退出表示数量、包围盒或 BOX 实例变换不匹配。

下一步应优先定位删除后 `regen_root` 长时间 running 的原因，确认模型内存、磁盘凭证及队列最终一致，再扩展到带管嘴、圆柱和布尔几何的设备。
