# E3D模型生成系统数据库查询函数分析文档

## 概述

本文档详细分析了E3D模型生成系统中使用的各种数据库查询函数，包括MySQL查询、SurrealDB查询以及ArangoDB查询。这些查询函数是模型生成过程中的核心组件，负责从不同数据源获取几何数据、属性信息和关系数据。

## 1. 数据库类型与用途

### 1.1 MySQL数据库
- **用途**: 存储PDMS元素数据、项目信息、用户数据等结构化数据
- **主要表**: 
  - `PDMS_ELEMENTS_TABLE`: PDMS元素表
  - `PDMS_DBNO_INFOS_TABLE`: 数据库编号信息表
  - `PDMS_PROJECT_MDB_TABLE`: 项目MDB表
  - `PDMS_SSC_ELEMENTS_TABLE`: SSC元素表
  - `ROOM_CODE`: 房间编码表

### 1.2 SurrealDB数据库
- **用途**: 存储图形数据、几何关系、实例数据等复杂关系数据
- **主要表/记录类型**:
  - `pe`: PDMS元素记录
  - `inst_geo`: 实例几何记录
  - `geo_relate`: 几何关系记录
  - `pe_owner`: 所有者关系记录

### 1.3 ArangoDB数据库
- **用途**: 存储虚拟孔洞数据、图形节点数据等
- **主要集合**: `virtual_hole`, `hole_data`

## 4. SurrealQL函数定义

### 4.1 房间编码查询函数
```sql
-- 文件: resource/surreal/fn_query_room_code.surql
REMOVE FUNCTION fn::room_code;
DEFINE FUNCTION fn::room_code($pe:record) {
    let $noun = $pe.refno.TYPE;
    // 根据不同实体类型处理房间关系
    if ($noun == 'EQUI' || $noun == 'STRU' || $noun == 'REST') {
        $id = array::flatten([$pe<-pe_owner.in.id, $pe<-pe_owner.in<-pe_owner.in.id])[0];
    } else if ($noun == 'BRAN') {
        $id = $pe<-pe_owner.in.id;
    } else if ($noun == 'SUPPO' || $noun == 'ZONE') {
        $id = array::flatten($pe<-pe_owner.in<-pe_owner.in<-pe_owner.in.id)[0];
    } else {
        $id = $pe;
    };
    // 检查房间关系
    let $res = select * from only $pe<-room_relate limit 1;
    return if ($res == none) { none } else { $res.room_num };
};
```

remove function fn::find_deep_children_type;
define function fn::find_deep_children_type($pe:record,$t:string) {
    let $children = array::flatten( object::values( (select
                      [id] as p0, <-pe_owner<-(? as p1)<-pe_owner<-(? as p2)...
                   from only $pe where record::exists(id))?:{{}} ) );
    return select value id from $children where id.noun == $t

## 8. 总结

E3D模型生成系统使用了多种数据库查询函数来支持复杂的3D模型生成过程：

1. **MySQL查询**: 主要用于结构化数据的CRUD操作，包括项目信息、用户数据、属性数据等
2. **SurrealDB查询**: 用于复杂的图形关系查询，支持几何实例、关系数据的高效查询
3. **ArangoDB查询**: 用于特定的图形数据查询，如虚拟孔洞数据
4. **性能优化**: 通过连接池、批量操作、分块处理等方式提升查询性能

这些查询函数构成了E3D模型生成系统的数据访问层，为上层的模型生成逻辑提供了强大的数据支持。

            );
            return;
        }
        let result: Vec<QueryGeoParam> = r.unwrap();

## 14. 查询函数分类总结

### 14.1 按功能分类

1. **几何查询函数**
   - 几何参数查询: `query_gm_params`
   - 几何实例查询: 通过`inst_relate->inst_info->geo_relate`路径
   - AABB查询: 获取包围盒信息
   - 负实体查询: `query_filter_children`

2. **属性查询函数**
   - 隐式属性: `gen_query_implicit_attr_sql`
   - 显式属性: `gen_query_explicit_attr_sql`
   - UDA属性: `gen_query_uda_attr_sql`
   - 命名属性映射: `get_named_attmap`

3. **关系查询函数**
   - 父子关系: `get_children_named_attmaps`
   - 所有者关系: `pe_owner`关系查询
   - 外键关系: `query_foreign_refnos`
   - 祖先关系: `query_filter_ancestors`

4. **项目数据查询函数**
   - 项目信息: `query_db_quick_info`
   - 用户数据: `query_all_pdms_user`
   - 房间数据: `query_room_nodes`
   - SSC数据: `gen_query_ssc_children_sql`

5. **材料清单查询函数**
   - 电气专业: `fn::dq_gensec`, `fn::dq_stru`
   - 通讯专业: `fn::tx_sb`
   - 通用工具: `fn::get_uda_value`, `fn::room_code`

### 14.2 按数据库类型分类

1. **MySQL查询** (结构化数据)
   - 项目管理数据
   - 用户权限数据
   - 基础配置数据
   - 统计汇总数据

2. **SurrealDB查询** (图形关系数据)
   - 几何实例数据
   - 元素关系数据
   - 空间位置数据
   - 材料清单数据

3. **ArangoDB查询** (文档图形数据)
   - 虚拟孔洞数据
   - 复杂图形节点数据

### 14.3 查询性能特点

1. **高频查询**: 几何参数、属性映射、关系查询
2. **批量查询**: 多元素并行处理、分块查询
3. **复杂查询**: 多层级关系遍历、条件过滤
4. **实时查询**: 增量更新、状态监控

这个完整的查询函数体系支撑了E3D模型生成系统的高效运行，通过合理的数据库选择和查询优化，实现了复杂3D模型的快速生成和处理。
