# 多 Agent 交接入口

协议版本：1；协作轮次：ROOM-20261016-01；建立日期：2026-10-16。
共同目标：继续审核房间初始化与增量更新，补足隔离验收与性能证据。

> 当前状态：PAUSED / 仅记录。用户决定“先暂时不考虑协同。只记录到对应的文件。”
> 不再分派任务、查询其他 Agent 接单或等待跨会话交付。下文协作接单、冻结、归属与命令预约条款仅留档，恢复后才启用；后续独立工作以用户明确指示为准。

## 1. 身份与真实能力边界

- 用户已确认共 2 个 Agent，使用临时编号：本会话 Agent-A，另一会话 Agent-B。
- 原 A/B 分工现已暂停；编号仅保留记录，不再等待 B 确认，也不能据此声称 B 在线或已读。
- 各会话通过同一工作区的文件交换状态；没有自动广播、跨会话调用或后台监视。
- 此协议是协作约定，不是文件锁。必须由用户把本入口告知其他会话，并要求它们确认已读。

## 2. 每个 Agent 的必读顺序

接入 Bridge 后先 workspace_brief，再读本文件、REGISTRY、BOARD、BASELINE 和自己的个人交接文件。
每次恢复上下文、开始任务、准备修改文件或执行命令前，重读 BOARD 与自己的交接文件。
已登记者在个人文件记录：协议版本、读到的任务板修订号、任务 ID、允许写入范围和实际阻塞。
不能代其他 Agent 标记“已读”“在线”“完成”。未登记者先向用户说明希望认领的任务，等协调者登记。

## 3. 谁写哪些文件

- Agent-A 单独维护 README、REGISTRY、BOARD、BASELINE 和根 AGENTS.md；他人通过个人交接文件提出请求。
- 每个已登记 Agent 只维护自己的个人交接文件，以及任务板明确授予的报告/代码文件。
- 当前 OPEN 任务不等于已分配，业务源代码与现有测试文件默认无写入许可。
- 一个业务文件同一时刻只能有一个负责人。其他人只读审查或在自己的报告中附建议补丁，不直接应用。
- 新文件也要登记范围；跨任务公共文件的模块接线、合并和统一格式化由协调者串行处理。

## 4. 认领与状态流转

1. 用户向协调者提供其他会话的临时称呼与任务意向。
2. 协调者分配唯一编号、创建个人交接文件，并在成员表登记；编号不是模型身份。
3. 协调者检查文件冲突后写入任务负责人、写入范围和验收条件，状态改为 READY。
4. 执行者重读任务板并在个人文件确认接单；协调者据此更新 IN_PROGRESS。
5. 执行者提交证据与限制，在个人文件标记 REQUEST_REVIEW；协调者审查后更新 REVIEW / DONE。
6. 阻塞必须记录原因、已尝试步骤与需要谁决策；超时或沉默不等于任务完成或负责人已退出。

任务状态：OPEN、READY、IN_PROGRESS、BLOCKED、REVIEW、DONE、DEFERRED。
只有协调者更改总表状态或转移文件归属。不能通过覆盖别人的状态来抢占任务。

## 5. 写入与并发保护

- 修改前用 read_file 读取最新编辑器内容与 version；小改用精确 edit_file，并传 expected_sha256。
- STALE_FILE 时停止、重读、协调差异；不能通过去掉版本检查或整文件覆盖来强写。
- 多文件补丁先校验，但 apply_patch 的原子校验不等于跨会话互斥；执行前仍需独占文件归属。
- 保留编码与换行。不 git reset/clean/checkout 回滚用户文件，不把他人的未提交改动纳入自己的成果。
- 不提交、推送、删除共享工件或全项目格式化，除非用户明确授权。

## 6. 命令预约

构建、测试、性能测量、启动服务等写入构建目录或占用资源的命令必须先由协调者在 BOARD 预约。
默认同时只允许一组 Cargo 构建/测试或性能实验；未持有预约者不执行，避免锁等待和数据污染。
预约状态不是 OS 锁。执行者在个人文件记录实际命令、工作目录、结果、job_id 与是否仍运行。
后台 job_id 只能来自本次工具返回；Bridge 重连后不得沿用旧会话编号去操作新任务。
命令结束后由协调者清除预约。不得终止不属于自己的命令。
只读查找/读文件可并行；受控实验之外不得访问或修改真实项目数据库、源模型或全局配置。

## 7. 验证与证据标准

- 代码修改后查 get_problems 和 get_changes；报告精确范围，不能把窗口全部 diff 当成自己的改动。
- 历史绿测、当前绿测、源码契约、回调行为测试、内存数据库测试、真实几何端到端验收必须区分。
- 每条测试证据包含日期、命令、退出码、通过/失败/ignored/过滤数，以及适用的代码版本或哈希。
- ignored、未运行和阻塞不算通过。没有运行就写“未运行”，不能复制历史计数冒充新证据。
- 真实数据库或源模型实验须先给出隔离对象、写入范围、还原方案，取得用户明确许可。

## 8. 告知其他 Arena 会话的文字

将下面文字发送到每个参与会话；如已由协调者分配编号，再补充编号和任务 ID：

> 请参与同一工作区的房间初始化与增量审核协作。先调用 workspace_brief，然后读取根 AGENTS.md、
> docs/agent-handoff/README.md、REGISTRY.md、BOARD.md、BASELINE.md。未登记前仅只读，
> 不自行占号或改业务代码。已登记后再读成员表指定的个人文件，向用户确认身份、已读版本、任务及边界。
> 不修改总任务板；进展、请求和证据写入自己的交接文件，等待协调者处理。不要在文件中保存访问凭据。

## 9. 最小交接模板

个人交接至少包含：身份、任务、已读版本、状态、允许写入范围、实际改动、测试证据、运行命令、
阻塞、下一步、需要协调者处理的请求。交付前更新个人文件，清楚区分“完成实现”和“完成验收”。
