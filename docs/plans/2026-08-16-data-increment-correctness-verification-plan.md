（增/删/改/移/改名），引擎增量落库后，Surreal 侧的 pe / pe_owner / 水位与
E3D tty 报告的事实一致，plant-ui 模型树呈现一致。

- E3D 侧缺陷的修复（如 COPY 不保留 SPRE/LSTU、GENSEC access violation 的
  E3D 本体原因）——只决定绕过策略。

## 3. 判定口径（待决 D1）

数据对拍的三方角色（推荐口径）：
- **外部权威**：E3D 库文件本身（宏 Q 输出 + `parse.net_changes` 纯文件差分）。
  tty 输出是权威的人读投影，文件差分是权威的机读投影。
- **被验对象**：Surreal 侧 pe / pe_owner / dbnum_watermark / 队列回执。
- **呈现层验证**：plant-ui 模型树（定位、属性、树结构），只验数据可见性，
  不承担权威职责。

## 5. 阶段一验收标准

每个在范围场景验五项（D5 裁决的维度）：
1. 数据批次回执：status=Applied、窗口与 merged_sesnos 与文件会话页一致；
2. 水位：applied_sesno = 文件末会话；
3. pe 行：name/noun/owner/deleted 与宏 Q 输出（文件权威的人读投影）一致；
4. owner 边：pe_owner 与文件层级一致，删除/恢复后无残边；
5. plant-ui 树：按 tree_item + refno 定位成功、层级与属性一致。

另：模型任务规划级断言（对的根进队列且任务成功）保留（D5b）；阻断场景有
显式定性记录；改动过 `cargo fmt` + `cargo check`；live 用例动过即更新台账。

## 7. 裁决记录

- **D1（2026-08-16）：采纳推荐**——文件本身为唯一外部权威，`parse.net_changes`
  为机读投影、tty Q 输出为人读旁证；Surreal 侧为被验对象；plant-ui 树只做
  呈现层验证不当权威。
- **D2（2026-08-16）：采纳推荐**——本轮验收边界 = db8000 管道 8 场景 +
  db7999 设备 9 场景全绿；GENSEC 单列 G2 不阻塞宣称；CATA 增量不造新场景，
  凭既有「CATA 5052 残留重放」通过记录带过。
- **D3（2026-08-16）：采纳推荐 (a)**——GENSEC 换构造方式重试一次（先建骨架
  再补属性，或换 PANE/SCTN 等价结构元素）；仍崩则定性为 E3D 侧缺陷、留档
  绕过，不开展 E3D 本体 debug。
- **D4（2026-08-16）：采纳推荐**——授权全自动跑：允许拉起/结束隔离后端
  （8028/8048）与 Plant UI 进程，仅限隔离实例，不碰正式 8009 库与用户自开的
  E3D 会话；des.exe 是否空闲交由 l3_suite 自带互斥门裁决，被拦即等待窗口。
- **D5（2026-08-16）：后置确认 + 分阶段口径明确**——用户裁定：分阶段推进，
  **第一阶段只保证「数据 + 层级树」正确性**（pe / pe_owner / 水位 / plant-ui
  模型树结构与定位）。issue7_e2e（房间归属）、房间场景（f8）、模型/几何
  正确性均属第二阶段起。第一阶段验收维度收敛为：数据批次回执、水位、pe 行、
  owner 边、树呈现五项。
- **D5b（2026-08-16）：采纳推荐**——模型**任务规划级**断言留在阶段一
  （影响分类/该重生谁/漏根即数据侧契约缺陷），验到「对的根进了队列且任务
  成功」为止；生成出的几何对不对不验、归阶段二。
- **D6（2026-08-16）：采纳推荐 (a)**——F5 未提交改动等 live 通过、台账更新
  后一并提交；不把未验资产入库。
