# 监控链路「收集 / 分析」分层开发计划

状态：**已定稿待实施**（D1–D6、D8、D9 已决，D7 出界）。分层本身的决策已记入
ADR-035，本计划只保留逐条裁决的理由与实施顺序。

日期：2026-08-19
提出背景：`AIOS_WATCH_RECONCILE_SECS` 默认 300s 想调短到 60s，但一轮对账重扫在
网络盘上可能分钟级，而它就 `await` 在 `async_watch` 的事件 select 循环里——间隔
调短会直接抬高「扫盘占空比」，把 30s 那层的发现延迟拖长。根因不是间隔选得不好，
是**收集与分析是同一个函数**。

引用的既有决策：ADR-011（手动与自动共用一条数据批次队列；watcher 只负责发现即
入队，不做执行）、ADR-016（监控目录解析与项目数据域）、ADR-021（水位必须有数据
支撑）、ADR-023（启动重扫修复无数据支撑的水位）、ADR-025（严格初始化阶段与清
单）、ADR-028（抽取树文件身份）。本计划**不修改**任何既有决策。

## 1. 目标与不做什么

**目标**：把监控链路切成两层——收集层只产**文件观察**（见 `CONTEXT.md`），分析层
消费合并后的观察集合，产 `DiscoveredBatch` 入队。切完之后，收集频率与分析成本解
耦，`AIOS_WATCH_RECONCILE_SECS` 变成可以自由调的参数。

**不做什么（本期显式出界）**：
- 不改任何入队判定口径。同一份观察集合喂进去，产出的 `DiscoveredBatch` 必须与
  今天逐字一致（范围门、F6、`ScanGate`、水位比对、park 判定都原样搬）。
- 不动 worker 侧的执行、重试与收口。
- 不把手动路径与自动路径分家（ADR-011 的合流不得回退）。
- **不改自动重跑与 park 的任何行为**（见 D7），因此本期也**不动
  `AIOS_WATCH_RECONCILE_SECS` 的默认值**。两者是同一件事：连败预算按轮次数，调间隔
  就等于调故障容忍度；本期只做分层，不从后门改失败策略。间隔的新默认值等分层落地
  并实测单轮耗时之后单独决定。

## 2. 现状事实（已核实，不必再查）

位置一律记函数名不记行号：这个文件正在被其他工作同时改，行号一天能漂三十行。

| 事实 | 位置 |
|---|---|
| 对账 tick 与文件事件共用一条 select 循环，两者都直接 `await sweep_watch_dirs` | `async_watch` 的 `tokio::select!` |
| 一轮 `sweep_dirs` 走**三遍**目录树，每遍对每个候选库真开文件读头 | `catalogue_manifest_for_dirs` / `collapse_watch_dir_families` / `sweep_dirs` 主循环 |
| 主循环的 `WalkDir::sort_by` 用的是 `a.path().metadata()`——那是每次比较都真发一次 stat（共享盘上是网络往返），O(n log n) 次；`DirEntry::metadata()` 在 Windows 上取的是目录列举时就带回来的缓存值，不发系统调用 | `sweep_dirs` 主循环 |
| 每个在范围内的库每轮还要：`get_latest_sesno` 读文件、`scan_and_check_file` 写观察落库、`discover_batch` 查水位 | `sweep_dirs` 主循环 |
| 事件分支里有 `sleep(250ms)` 手搓防抖——因为没有队列可以合并 | `async_watch` 事件分支 |
| `DiscoveredBatch` 携带 `project/dbnum/db_type/phase/epoch_id/intent/applied_sesno`，已是分析成品 | `batch_scheduler::DiscoveredBatch` |
| 批次连败 park 预算 `MAX_ATTEMPTS = 5` 是**按对账轮次**数的，不是按时长 | `model_update_pending::MAX_ATTEMPTS`、`batch_worker::BatchFailureLedger` |
| `dbnum_state::FileObservation` **这个名字已经被占了**，指的是带库号、库类型与会话号的登记观察 | `scan_and_check_file` 里构造的那个 |

## 3. 决策记录

### D1（已决）：一条文件观察里装什么

**裁决：只装纯文件系统事实**——`{ path, mtime, size, seen_at, origin }`。收集层只
stat，一行文件头不读、SUL_DB 不碰。

理由：读文件头就是成本本身，把它留在收集层等于绕一圈回到原地。附带收益是排序需要
的 `size` 顺手就在 stat 里拿到了，`WalkDir::sort_by` 那个 O(n log n) 次网络 stat
的风暴自然消失。

F6 同号重复不因此失守：重复判定需要的是**全集视野**而不是单条观察，它本来就属于
分析层；而 `is_candidate_db_file` 只看文件名不读头（`CONTEXT.md` 已钉死），收集层
在不读头的前提下就能完成筛选。

### D3（已决）：分析层独立成 task，同一时刻单飞

**裁决：独立 tokio task + 单飞。**收集层往共享观察表里塞完就回去听，分析 task 自己
醒来消费。

理由：留在同一条 select 循环里等于没改——PollWatcher 的回调是
`block_on(tx.send())` 且 channel 容量为 1，分析一慢，它自己那个 30s 扫描线程跟着
停，间隔依旧不是自由参数。单飞是硬要求：两轮分析并行会同时写观察落库、同时装阶段
纪元、同时入队，而 `seen_dbnums` 那套 F6 全集判定会变成两边各看半个世界。

**随之要处理的两件事**：`async_watch` 在事件流关闭时按「看门狗死亡」报 `Err` 退
出，分析 task 必须跟着一起收，不能留孤儿 task 继续默默入队；`self.watcher.
file_name_full_path_map` 这类共享可变状态的归属跟着分析层走。

### D2（已决）：观察队列是进程内按 path 聚合的 map

**裁决：内存 map，键为 path，同 path 保留最新一条观察。**不落库、不用无界 channel。

理由：这个队列不需要可靠。丢了也只是晚一轮——下一次全集观察轮会把整个状态重新发
一遍。对账本来就是这套机制的兜底，再给队列加一层持久化是重复投保。按 path 聚合而
不是 channel，是因为观察描述状态不描述事件，天然可合并；一次 SAVEWORK 打出的一串
变化塌成一轮分析。

### D4（已决）：观察显式带全集标记

**裁决：观察带 `origin` 与「是否全集」两个字段，分析层不做推断。**

理由：只有全集轮才有资格做「这个文件不见了」这类需要全集视野的判定；子集轮里某个
路径缺席只说明它这轮没变。让分析层去猜自己拿到的是不是全集，是把一个调用方本来就
知道的事实丢掉再重新猜。

### D6（已决）：阶段纪元由分析层安装

**裁决：每轮分析结束时装纪元。**

理由：`CONTEXT.md` 对阶段纪元的定义是「一次完整候选扫描安装的可重建版本」——切开
之后，「一次完整候选扫描」这件事发生在分析层，收集层只是把观察递过去。

### D8（已决）：删掉 250ms 防抖，`arm_auto_work` 移到分析层

**裁决：`sleep(250ms)` 删除；`arm_auto_work` 与初始化协调器的 `arm` 移到分析层
判定「确有新会话」之后。**

理由：那句 sleep 是在手搓防抖，因为当时没有队列可以合并；D2 之后合并是队列的天然
性质，防抖失去理由。而在收集层 arm 意味着任何一次文件触碰（哪怕水位早已覆盖、本轮
零入队）都会给本进程上弦，这与「本进程这一趟里发生过真实增量」的语义不符。

### D9（已决）：`AIOS_WATCH_RECONCILE_SECS` 保名改义

**裁决：变量名保留，语义变成「全集观察轮间隔」，默认值待 D5 与实测之后再定。**

理由：部署模板已经在用这个名字，改名要人跟着改配置，而它表达的意图（多久整面对一
次账）切开前后没变。

### D5（已决）：本期不做读头缓存，先合并三遍遍历并实测

**裁决：不加缓存。**三遍目录遍历合成一遍，每个候选库每轮读一次头（而不是三次），
先拿到真实单轮耗时；慢到不可接受时的退路是「缓存 `(path, mtime, size)` + 每 N 轮
强制全读」，但不在本期先上。

澄清一个容易搞反的点：**缓存并不会削弱对账的兜底作用**。兜底靠的是「文件侧 sesno
vs 活的水位」每轮都比，而水位那一侧永远新查；丢事件丢的是处理而不是文件，处理失败
不会抹掉文件侧那个已经变高的 sesno，所以即便该值来自缓存，比对照样命中。缓存真正
会丢的只有一种情形：**内容变了而 mtime 与 size 一模一样**。这种情形 PollWatcher
本来就看不见（它就是比 mtime 的），所以今天的对账是全系统唯一能接住它的东西——这
才是上缓存要付的价。

因此「缓存但不强制全读」被显式排除：那等于把对账降格成一个跑得更慢的
PollWatcher，付了整套分层的代价，却把它唯一独有的那道保护退了回去。

### D7（出界）：本期不碰自动重跑

**裁决：不改。**`BatchFailureLedger` 的连败计数、`MAX_ATTEMPTS = 5`、park 与三条复
活路径全部原样保留。

因此本计划带一条硬约束：**间隔默认值也不能动**。连败预算数的是轮次，实际容忍时长
= 5 × 间隔；分层完了顺手把间隔调短，等于没经过任何裁决就把故障容忍窗口从 25 分钟
砍到 5 分钟。要调间隔，先把 D7 拿出来单独决定。

## 4. 实施顺序

每一步各自可编译、可验证、可单独合入；每步都要现有扫描口径测试全绿
（`project_paths` 那一组、`batch_worker` / `batch_queue` 那一组）加
`cargo fmt` + `cargo check`。

| 步 | 内容 | 行为变化 |
|---|---|---|
| 1 | 三遍目录遍历合成一遍，产出 `Vec<FileObservation>`；`WalkDir::sort_by` 的 `metadata()` 改用遍历时收下的 `size`；补一行单轮耗时日志 | 无（纯重构） |
| 2 | 引入按 path 聚合的观察表与 `origin` / 全集标记；收集层只往表里塞，`sweep_dirs` 改成消费观察集合 | 无 |
| 3 | 分析层拆成独立 task + 单飞，绑 `async_watch` 的生命周期；删 `sleep(250ms)`；`arm_auto_work` 移到分析层 | 事件摄入不再被分析阻塞；一串事件塌成一轮分析 |
| 4 | 拿步 1 的实测耗时，重开 D7 与间隔默认值 | 另行裁决 |
