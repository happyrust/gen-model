# SCOSEL 序列化栈机 —— opcode 参考（真实字节 + IDA 取证）

GPSET 的规则成员存在 `SCOSEL` 隐式属性里，是一段 int 数组。本文供 G3 / M4 实现 `scosel.rs` 使用。

**证据优先级**：真实字节 > IDA 反编译 > 推断。凡本文「实测」与「确证」冲突，以实测为准；
IDA 结论只用来解释「为什么」。

- **实测**：`AvevaPlantSample` 的 aps250204 里全部 27 个带 `SCOSEL` 的 GPSET，
  基准 `tests/fixtures/group-contract/scosel-real-samples.json`，
  取数探针 `src/bin/scosel_sample_probe.rs`（只读）。
- **确证**：`core.dll` 反编译地址（`idalib-14972`，`D:\ida_scratch\plant3\core.dll.i64`）。
- **推断**：只有语义解释，没有字节或反编译的直接支持。

## 0. 真实字节长什么样

27 个样本全部同形，只有文本与规则数不同。最短的一条（`/AREA01_PIPE`）：

```
35, 100016, 1, 100009, 3, 100007, 640493, 100015, 27, 1,
106, 4, 604480, 1, 120, 0, 1602, 4, 2, 640493, 6, 1701, 118, 10,
65, 82, 69, 65, 48, 49, 80, 73, 80, 69, 402
```

`65,82,69,65,48,49,80,73,80,69` 就是 `AREA01PIPE` 的 ASCII。

两条规则合并的一条（60 字，`/AREA01_GRID`）：

```
60, 100016, 1, 100009, 3, 100007, 67635315, 100015, 52, 1,
106, 4, 604480, 1, 120, 0, 1602, 4, 2, 67635315, 6, 1701, 118, 10,
<AREA01GRID 的 10 个 ASCII>, 402,
106, 4, 604480, 1, 120, 0, 1602, 4, 2, 67635315, 6, 1701, 118, 9,
<PLANTGRID 的 9 个 ASCII>, 402,
301
```

**27 条里出现过的 opcode 只有 11 个**：`100016` / `100009` / `100007` / `100015` / `106` /
`120` / `1602` / `1701` / `118` / `402` / `301`。

**`1306` / `1307` / `1317` 一个都没有**。这 27 组是**等值分组**（`402` 全串相等），
不是前缀分组——先前「27 组是前缀规则、要用 `1307`」的说法被真实字节推翻。

## 1. 整体形状

```
[word_count] 100016,1  100009,<N>  100007,<attr_hash>  100015,<len>,1 <expr>*
```

- `[word_count]` = 数组总字数，含自身。27 条全部成立。
- `100016,1` 是头部，值恒为 `1`。
- `100009,<N>` 是 class 段。
- `100007,<attr_hash>` 是规则组标记，后接它的 `100015` 段。
- 多个规则组可串联（GRID 组两条），用 `301` 合并。

## 2. 三个长度口径（实测，三个都容易错）

| 段 | 计数字 | 口径 | 验算 |
|---|---|---|---|
| `[word_count]` | 首字 | 数组总字数，**含自身** | 35 字数组首字 35 |
| `100009,<N>` | `N` | 段总字数，**含 `N` 自身，不含 `100009` opcode** | `N=3` → 段是 `3,100007,640493`，下一个字正好是 `100015` |
| `100015,<len>` | `len` | 段总字数，**含 `len` 自身，不含 `100015` opcode**；含那个 `1`、含表达式、含 `402` | `len=27` → 从 `27` 到 `402` 正好 27 字，段末即数组末 |

**`100009` 的 `N` 含自身，这一点必须钉死。** 把 `N` 当「不含自身」会让 `100015` 被当 class id
吃掉，解码在 `100015` 的 `len`（27）处报 `unsupported opcode 27`。当前 `scosel.rs` 就是错在
这里，实测 27 条**全部解不开**。

## 3. 表达式层

分派入口：`DBE_Builder::getExpressionTree` @ `0x59C8F70`，按 `opcode / 100` 分族。

| opcode | 语义 | 计数字口径（实测） |
|---|---|---|
| `106` | 属性引用 | `106,<count>,<attr_hash>,<flag>`，`count` **含 `106` 自身**；`count=4` → 这 4 个字，内容是 `attr_hash` + 1 个 flag |
| `120` | 点号成员名（`addDotNameMember` @ `0x59E1570`） | `120,<n>`，2 字，不单独入栈，修饰前一个属性引用 |
| `122` | 点号属性名（`addDotNameAttribute` @ `0x59E14E0`） | 同 `120` |
| `1602` | id-of / noun 限定（`DBE_IdExpression` @ `0x59CF930`） | `1602,<count>,<X>,<noun_hash>` **+ 1 个类型标记字**；`count` **含 `1602` 自身、不含类型标记**（`count=4` → `1602,X,noun,?` 四个字，再加标记 = 5 字）；末字 `6`=noun、`4`=IdName、`3`=IdRef |
| `1701` | 零操作数终止符 | 1 字，只前进 |
| `118` | 文本字面量 | `118,<len>,<ASCII>×len`，`len` **只是字符数**，不含 `118` 与 `len` 自身 |
| `402` | 字符串全串相等 | 1 字，二元 |
| `301` | OR（并集） | 1 字，二元 |
| `302` | AND（交集） | 1 字，二元 |

**计数字口径不统一，这是第二个容易错的地方**：`106` / `1602` 的计数字含 opcode 自身，
`118` 的计数字只是字符数。

### 3.1 一个条件不是「多个栈元素 + 一个比较」（实测栈演算，语法属推断）

以 `106,4,604480,1 120,0 1602,4,2,640493,6 1701 118,10,"AREA01PIPE" 402` 为例。

按「每个 opcode 各压一个、`402` 弹两个」去算，段末栈里会剩 2 个元素，不是 1 棵树——
四道自检里的第 3 道会直接报错。27 条**全部如此**，说明它不是纯后缀栈。

能满足栈自检又对得上真实字节的读法只有一种：**`106` 开启一个属性条件，`402` 收尾，整段
只占 1 个栈元素**；`120` / `122` / `1602`+`1701` 都是这个条件内部的限定，不单独入栈。
GRID 组两条条件 + `301` → 栈 1，自洽。

**「条件」这个复合结构的确切语法仍是推断**（IDA 只给了各 opcode 的语义，没给复合结构）。
实现时以「27 条真实样本能解码且能往返」为准，不以本段叙述为准。

### 3.2 `1306` / `1307` 是字符串函数，不是比较（确证，但 v1 用不上）

`getTreeStringFunctions` @ `0x59CC790`：`1306`=`DBE_After`（取 b 之后）、`1307`=`DBE_Before`
（取 b 之前），都返回子串，**不能当布尔谓词**。`1308`/`1311`=`DBE_Match`（返回匹配位置+1，
double），`1317`–`1319`=`DBE_MatchWild`（通配 `*`=42、`?`=63，`matchWild` @ `0x59B7E70`
是标准回溯通配匹配）。

真实样本里它们一个都没出现，v1 不需要实现，遇到报 `unsupported`。

### 3.3 `402` 是全串相等（确证）

`LicFeatureCheckOut_StrEq` @ `0x5819BF0`：先比长度，不等直接 false，再逐 4 字节比。
**全串相等，不是 startswith。** 真实样本的 `/AREA01_PIPE` 组选的是 NAME 恰好等于
`AREA01PIPE` 的元素。

### 3.4 `106` 的尾部（确证 + 实测）

`106` 在 `getExpressionTree` 里没有分支，落 `getTreeValues` case `106`，交给
`DBE_Attribute::constructFromIntArray` @ `0x59D7B30` 消费。实测 `106,4,604480,1` 的
`count=4` 覆盖 `106` 自身，所以只有 `604480`（attr hash）+ `1`（flag）是内容。

`604480` / `640493` / `67635315` 各是什么属性 / noun，用 `db1_dehash` 反查，不要猜。

### 3.5 `120` / `122` 是独立 opcode（确证）

它们是 `addDotNameMember` / `addDotNameAttribute` 两个独立分支，**不是** `106` 的尾字。
`120,0` 的 `0` 是成员序号（`0` = 自身层级）。

## 4. 容器层其余 opcode（IDA 确证，真实样本里没出现）

解码入口 `DB_Collection::decodeStack` @ `0x59BAA30`、`decodeClass` @ `0x59BA470`；
编码对称入口 `encodeClass` @ `0x59BB000`。

| opcode | 语义 | 备注 |
|---|---|---|
| `100001` | 显式成员组 | 后接**一个与 `100015` 同格式的 len-prefixed 表达式**，不是 refno 列表、没有 index；可选跟 `100008` / `100017`；求值走 `preProcessInclusions` @ `0x59BEE10`，不走 `evaluateDB` |
| `100046` | 类型组 | |
| `100003` | scope | |
| `100010` | volume | |
| `100008` / `100017` / `100036` | 标志位 | 位含义未查清 |
| `100040` / `100043` | 字符串源 | |
| `100011` / `100012` | 段边界 | 真实样本里也没出现，位置未查清 |
| `100050` | 引用属性 | |

**`100001` 没有 refno、没有 index**——它后面是一个表达式。先前「`100001` 后面是 GPITEM
refno 链」的猜测是错的。

## 5. 求值域

- `evaluateMDB` @ `0x59BC330` → `DB_MDB::instance()` + `findELementsTypeActual`：
  求值域是当前 MDB 的**全量元素**，先由 class 列表（`100009` 段）缩窄。
- 单库 `evaluateDB` @ `0x59BBF00`。
- 不是「同一个库内的元素」。规则求值出的成员可以散落在 MDB 任意库，和 GPREF 跨库是同一类
  问题，走 store 的按 refno 路由，不要假设同库。

## 6. 未查清（实现按「未知即报错」处理，不要猜）

| 项 | 影响 |
|---|---|
| 「属性条件」复合结构的确切语法（§3.1） | **首要未知**；目前只有「27 条能解 + 能往返」这一条验收线 |
| `1602` 数组 index 1 的语义（实测恒为 `2`） | 只影响 id-of 的完整还原 |
| `106` 的 flag 字语义（实测恒为 `1`） | 属性引用的限定信息 |
| `120` 的序号语义（实测恒为 `0`） | 只影响点号名的完整还原 |
| `100008` / `100017` / `100036` 位含义 | v1 可只记录不解释 |
| `100011` / `100012` 在数组里的位置 | 真实样本里没出现，可能只在别的组类型里有 |
| `100013` / `100018`–`100034` 旧版兼容 opcode | 老工程文件的 SCOSEL 可能带这些 |

## 7. G3 实现约束

1. **开关 `group_scosel` 默认关**。关着时 GPSET 只看 GPITEM 链，行为与 M3 完全一致。
2. **未知 opcode 报错，不静默**。错误信息带 opcode 数值与数组下标，拿真库样本能直接定位。
   绝不「跳过不认识的字」继续读——栈机会整体错位。
3. **验收线是真实字节，不是自造样本**。`decode` 必须能解开
   `tests/fixtures/group-contract/scosel-real-samples.json` 的全部 27 条，且
   `encode(decode(样本)) == 样本` 逐字相等。自造样本往返只证明自洽，不证明对。
4. **v1 子集**：容器层 `100016` / `100009` / `100007` / `100015`；表达式层 `106` / `120` /
   `1602` / `1701` / `118` / `402` / `301` / `302`。其余一律 `unsupported opcode`。
5. **三个长度口径按 §2**：`word_count` 含自身、`100009` 的 `N` 含自身、`100015` 的 `len`
   含自身。计数字口径按 §3（`106`/`1602` 含 opcode 自身，`118` 只是字符数）。
6. **树里规则成员为 `rule: true, via: null`**。`ResolvedMember` 加 `Rule { element }` 变体
   （`via()` 回 `None`），`ResolvedMember::element()` 照常给元素，解析视图把它和
   `Reference` 成员一起按存储原序去重。
7. **坏槽单独报**：「属性不在模板上」「字面量不是 ASCII」这类进 `unresolved`，原因码另起一族
   （`scosel_unsupported` / `scosel_eval_failed`），不混进 `gpref_missing` /
   `db_not_in_mdb` / `target_missing`。
8. **契约快照**：`group_scosel` 关与开各一份基准，键名沿用 `tests/fixtures/group-contract/`
   现有四份的口径；`rule` 字段已在契约里，不需要新增。
