副作用：`ams7326 / 7327 / 7333` 两根的对拍计数完全相同（both 14 328 / 17 076 / 79 409），
因为这两个根各自都覆盖整库（gen 侧的 `--root` 语义会把 APPLDW 子树一并走到），
不是重复计数错误。**对拍分母按根算会翻倍**，报告里凡按根列的表都注明这一点。

### 1.2 「根」与「件」是两层口径，不能相加

- 计划里的 50 339 / 66 886 是**服务端 `model/roots` 口径**（生成单元，如 FRMW / STRU / BRAN / HANG）。
- 本轮产出的是**件口径**（RVM 里每个 CNTB = 一个 refno），9 库合计 238 860 件。

两者不能相加，也不能互相折算。报告里所有对拍数字都是件口径。

### 1.3 `ams7999` 整库模式下 TUBI 记录重复

整库生成 15 845 条记录，但只有 13 715 个唯一 refno：582 个 TUBI refno 重复记录，最多一条 30 份（多出 2 130 条）。
per-root 模式每个 refno 只出一次。所以覆盖判据用**唯一 refno 集合**，不用记录条数 —— 否则会得出「整库 15 845、各根并集 13 715、缺 2 130」的错误结论。

#### 4.0.1 根因一：`1011` 是 PML 的 `REAL()` 类型转换（HROD 10 104 件）

`catalogue_pml.rs` 的操作码表里没有 1011，整条程序 `parse` 失败 → 该属性 `Unresolved`。
HROD 的 `PTDI` 恰好全是 `… 1011` 结尾，于是三个 LCYL 只剩 `PBDI`/`PDIA` 能求，
E3D 那条 800 mm 的吊杆在我们这里退化成 16 mm 的螺纹端头。

证据链三层：

1. **二进制侧**。`core.dll`（shadow 安装目录，50 071 544 B）偏移 `0xbaf400` 的 printer 格式表里有
   `REAL ( . )`，与 `SQRT ( . )` / `INT ( .. )` / `NINT ( . )` 同段；偏移 `0xe5c480` 的函数名表
   在 `SQRT` / `INT` / `NINT` 同一块里列 `REAL`。
2. **语料侧**。`pml_opcode_census` 在 acp7320 + acp7003 上扫出 **420 条程序**用到 1011，
   其中落在 `PTCA`/`PTMI`/`PTAX` 几何件的 **4 750 件**（630 个 SCOM）。代表词
   `23704/67677 PTAX PDIS = 11 1 106 2 675926 1 1 0 1601 1701 1011`，
   即 `REAL ( ATTRIB HEIG )`。
3. **几何侧**。7326 `23710/69`（HANG `/MDS/FH01/20/H1`，`HEIG = 800`，`DESP = [16, 32]`）
   基准 RVM 三个 Cylinder 是 800 / 32 / 16 长、中心 z = 400 / 816 / −8。
   反推 `PBDI = REAL(HEIG) = 800`、`PTDI = REAL(HEIG) + DESP[2] = 832`、高度 `32`；
   第三只 `PBDI = DESP[1] = 16`、`PTDI = 0`。三只全对上。
   注意 `101 6 32768 0 1 0 6` 是 `2.0`，在这里是 **DESP 的栈下标**，不是乘数。

实现：新增 `const OP_REAL: i32 = 1011`，在 `parse()` 的单词操作码白名单、
`render()` 的 `apply_function("REAL")`、`apply_numeric()` 的 `unary_number(|n| n)` 三处接入。
语义是恒等转换，不改变数值，也不清除 fault。单测 `hang_rod_ptdi_programs_use_the_real_cast`
锁住 7326 / 7327 两个库的四种词形。

#### 4.0.2 根因二：定点数的小数词是有符号的（PCLA 2 314 件）

`decode_number` 把第二字按 `second as u32` 读。定点数形态是
`value = (first + second / 2^15) × 2^(third − 15)`，两个词都带符号：

| 存储词 | 无符号读法 | 有符号读法 | 出处 |
| --- | --- | --- | --- |
| `13107 6560 -1` | 0.2 | 0.2 | `PZLE = 0.2 * PARA[3]` |
| `-13107 -6560 0` | **+3.6** | **−0.4** | `PZ = 3.6 * PARA[3]` |
| `12288 0 0` | 0.375 | 0.375 | `PYLE = 0.25 * PARA[8]` |
| `-12288 0 0` | −0.375 | −0.375 | `PY = −0.375 * PARA[8]` |

正负号在两个词里各写一份，所以**只有两词同时为负时**才暴露：`-13107 -6560` 按无符号读成
`-13107 + 4294900736/32768 = +1.8`，正确值是 `-0.4`。

实证：7333 的 PCLA `23704/299829`（`SCOM /MDS-PIHASA-HANG-CAT/G-2400-1A`）`PZ` 被算成
`+2926.8`，正确是 `-162.6`；该件生成侧 `z_max = 5333.9`、基准 `429.5`，差 4 904 mm，
与 §4.1 表里 PCLA 的最大偏差一致。

修复后 7333 的 off 从 9 890 降到 7 576，`PCLA` 的偏差谱从「15.5 – 4 904 mm 的混合量级」
收窄成「15.5 – 356.5 mm 的连续谱」，且 `SNUB 558` / `HNUT 24` / `VSPR 1 300` 整族转 exact
（它们此前也是被同一条错误乘法推出去的）。单测 `a_scaled_fraction_word_carries_the_sign` 锁住五种词形。

#### 4.0.3.1 `PCLA` 的 `CLFL` 圆柱不再绕 X 转 90°（commit `861c811`，7333 off 7 576 → 0）

`catalogue.rs` 的 `uses_clfl_centreline_frame` 白名单里含 `PCLA`，对 `CLFL=true` 的 `SCYL` 施加
`frame * DMat3::from_rotation_x(-FRAC_PI_2)` 并加 `rotation.z_axis * height*0.5` 偏移。

取证（`examples/catalogue_probe`）：ams7333 `23717/208058` → SCOM `/H-HMPNMPR2K`（`23704/295580`），
`PARA=[800,30,813,25,150,30,535,47,613,1242,45,30]`，唯一 `CLFL=true` 的 SCYL 是
`23704/295462`（`PAXI=[1,2]` 即 Y 轴、`PDIA=863`、`PHEI=150`、`PDIS=-75`）；同件还有
`SBOX PXLE=80/PYLE=150/PZLE=1242` 与 8 只 SEXT。E3D 记录盒 `863×150×1242` → 863 直径在 X 上，
圆柱就在 `PAXI=Y` 上，**无四分之一转**。转 90° 后得 `250×863×1242`，正是全部 off PCLA 的
「生成 Y == 基准 X」特征。

改动：白名单收窄为 `clfl && primitive_noun=="SCYL" && member_noun=="HELE"`（保留唯一被确认的族）；
新增测试 `pcla_clfl_cylinder_runs_on_paxi_without_a_quarter_turn`。

#### 4.0.3.2 `SJOI` 正体标架不再乘切割符号（commit `78aeef6`，7356 SJOI 141/141 全 exact）

`datum::section_joint_world` 两处错：

ams7356 的 202 只 SNOD→SJOI 里 170 只 `CREF` 缺席，E3D 对全部 202 只都导出了 SJOINT 面片，
而 gen-model 只出 32 只的几何、141 只只在基准侧。
