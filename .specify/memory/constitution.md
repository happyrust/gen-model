# gen-model Constitution

本文件是 `gen-model`（AVEVA E3D → SurrealDB 增量解析与模型生成服务）的宪法，
从仓库既有的 ADR-001 ~ ADR-015 与 `docs/specs/` 提炼而成。它约束的是**增量链路**
这一类「后台默默跑、错了没人看见」的代码，因此原则全部围绕同一件事：
**让错误可见、让状态可收敛**。

## Core Principles

### I. 水位是承诺，不是进度（NON-NEGOTIABLE）

`applied_sesno` 表示「这个区间的数据确实已经落进库里」，不表示「我们尝试过」。

- 任何写失败都不得推进水位；同一窗口必须能幂等重放（ADR-001）。
- 承诺必须有数据支撑（ADR-021）：`applied_sesno > 0` 而该 dbnum 在 `pe` 里零行（幽灵水位）
  时，按首次导入重建基线，不得从水位往后接增量；存在性查询失败必须上浮为批次失败，
  不得吞成「有数据」或「没有数据」中的任何一种默认值。
- 应用水位在增量路径内单调不降，永不因失败或异常自行回拨。文件回退
  （`file_latest_sesno < applied_sesno`）的默认处置是整库重建（ADR-021，修订 ADR-001）：
  扫描只分类入队，worker 冻结点复核仍判回退才 `wipe_dbnum_for_reinit` 清库（水位行清值
  不删行、spatial epoch 同阶段递增），随后按首次导入重新解析——水位随重建归零再重新
  建立，属正常处置而非回拨例外。
- `TypeChanged` / `Duplicate` / `Missing` / `ForeignProject` 等身份歧义异常照旧阻断等人，
  绝不自动清库——机器不替人挑文件。
- 与水位共命运的副作用（交付状态、模型工作单）必须与水位推进**同一个事务**；
  只能单独提交的副作用必须落进持久补偿队列，不允许只留一句 warning。

### II. 一条规则只有一份实现

手动触发与自动 watcher 喂的是同一个队列、同一个派发器（默认单在飞批次，
`data_batch_workers` 可配至 8——ADR-011 2026-08-09 修订），因此
「哪些文件算库文件」「哪些库在本期范围内」「什么异常要阻断」
这类判定**只能有一处权威实现**，两条路径共用。

- 新增门控时必须同时接进两条路径，或抽成共享谓词。
- 无法用纯函数钉住的时序约束（例如「重复 dbnum 阻断必须先于 record_scan」），
  用源码顺序断言测试钉住——本仓库已有先例，照做。

### III. 静默失效是最高级别缺陷

宁可报错阻断，不可无声跳过。判定为「异常」的分支不允许落进 `_ => 放行`。

- 任何 `continue` / `_ =>` / `unwrap_or_default()` 落在判定路径上，
  都要能回答「它跳过的东西，谁会发现？」。答不上来就是缺陷。
- 只有 `println!` 而调用方回执里看不见的失败，视同没有报告。
- 判定与它所依赖的基准数据不得互相覆盖：先裁决，后落库。

### IV. 队列任务必须可消费、可收口、可复活

进了持久队列的每一行都要有明确的三条出路。

- **可消费**：每种 action 必须正好被某一个 drain 阶段的过滤器覆盖。
- **可收口**：成功即删除、失败即计数，且寻址按行内实际字段而非重算出来的 id。
- **可复活**：达到重试上限的死信，必须存在一条「新触发到来时清零重试」的路径。
  不认领会话号的任务（跨库派生、房间重算）一律无条件复活——每次入队本身就是新理由。

### V. 标识只用真值

`Ref0` 不是 `dbnum`，`file_stem` 不是 `file_name`，观察值不是权威值。

- 拿不到真值时留空（0 / None）并说明「未解析」，绝不填一个「看着像真的」的近似值。
- 需要 `ref0 → dbnum` 时走 `cata_closure` 的反查，不得用 `RefU64::get_0()` 顶替。

### VI. 不变量由可执行的守护看住

每条被写进注释的不变量，都要有一个对应的测试。

- 优先纯函数单测（不连库、可在 CI 跑）。
- 依赖实库的行为用 `#[ignore]` 的 live 测试补，并在测试名里写清前置条件。
- 修 bug 必须附一条「若回退到旧写法就会红」的回归测试。

## Additional Constraints

**技术栈**：Rust（edition 2024 工具链）+ SurrealDB（主库）+ 可选 MySQL/TiDB 旁路
（feature `sql`）+ MQTT（feature `mqtt`）+ axum（feature `http_api`）。

**并发模型**：一个进程一条数据批次队列、一个派发器，至多 `data_batch_workers` 个在飞批次
（默认 1 = 单消费者行为，上限 8；ADR-011 2026-08-09 修订）。并发仅限稳态 DESI 暂存窗口，
同 dbnum 恒串行；非 DESI、基线/冷启动与应急直写批次独占执行，journal 写回与水位尾事务经
`STAGED_COMMIT_SERIAL` 一次一个。合并、冻结、FIFO 语义建立在「单队列 + 单派发器」前提上；
任何引入第二条数据批次消费路径的改动都要先改 ADR-011。

**SurrealQL 拼接**：所有进入语句字面量的外部字符串必须过
`dbnum_state::escape_surql_str`（Windows 路径的反斜杠会破坏字面量）。

**运行环境**：开发机为 Windows / PowerShell。**禁止使用 `cargo clean` 清除编译产物**。

**外部权威**：属性 → 模型影响的分类以 core.dll / Core3D 逆向结论 + E3D 字典
DCHC 快照为准（ADR-002 / ADR-004）；分类原则是「宁多勿漏」——未知属性一律保守触发。

## Development Workflow

1. **有架构决策就写 ADR**：`docs/adr/ADR-NNN-*.md`。本次特性引用到的既有决策必须列出。
2. **改动前先有 spec**：`specs/NNN-*/spec.md` 描述「要什么、怎样算成功」，不写实现。
3. **plan 过 Constitution Check**：违反上面任何一条原则的设计，要么改设计，
   要么在 plan 的 Complexity Tracking 里写明为什么无法避免。
4. **tasks 必须带文件路径**：每条任务指向具体文件，且标出能否并行。
5. **质量门**：`cargo check` / `cargo test`（纯函数层）必须过；
   涉及水位、队列、模型生成的改动另需跑对应的 `#[ignore]` live 测试并在证据文档留痕
   （`docs/evidence/`）。

## Governance

本宪法优先于个人习惯与历史写法。与既有代码冲突时，以本宪法为准并把旧代码改过来。

- 每次 review 都要显式检查上述六条原则。
- 修订本宪法需要：说明动机、列出受影响的 ADR、给出迁移路径。
- 版本号语义：MAJOR = 删除/重写原则，MINOR = 新增原则或章节，PATCH = 措辞澄清。
