# Feature Specification：Plant UI 与 E3D 增量闭环

## User Stories

### US1：保存事实优先

E3D 变更宏在保存后退出时，测试执行器必须识别文件已经变化，不得重复应用。

### US2：模型阶段可观察

数据任务完成后，操作者和 Plant UI 能区分模型等待、让位、成功和真实失败。

### US3：三端一致验收

设备和管道的增加、修改、删除必须同时验证 E3D 文件、SurrealDB 数据/模型和 Plant UI。

## Functional Requirements

- **FR-001**：变更执行结果由标记、退出状态及文件会话前后值共同分类。
- **FR-002**：会话已增加的变更不得自动重试；仍必须执行验证和恢复。
- **FR-003**：UI 测试使用独立设置文件、明确资产根和确定的工作目录。
- **FR-004**：自动化只按真实树项的 role 与 refno 定位，不匹配命令历史或属性文本。
- **FR-005**：UI 在数据任务、模型任务、pending 和模型刷新四个屏障收口后才断言终态。
- **FR-006**：数据任务的空 `units` 不表示模型遗漏；模型根以 `model_drain` 任务和最终模型表证明。
- **FR-007**：会话清单用“preview 后保存再 execute”验证，并保留“保存后 preview 得空清单”的契约测试。

## Success Criteria

- `SAVEWORK` 后、DONE 前退出只产生一次文件变更。
- 新数据到达时模型让位且 attempts 不变。
- 设备与管道 CRUD 在文件、数据库、树/属性/三维视图上完全一致并可恢复。

## Assumptions

- 持久模型工作表及水位 schema 不迁移。
- 正在执行的单根生成不强制取消；数据最多等待当前单根。
