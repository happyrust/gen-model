# Spec 013：Dabacon 快照完整性

## 目标

保证每个增量窗口与首次/回退基线都来自可确认的单一文件快照；任何可能遗漏或误判
业务元素的读取失败都不得推进 `applied_sesno`。

## 需求

1. `pdms_io` 提供绑定稳定文件身份、dbnum、db_type、会话映射和 sesno 的快照接口；
   捕获期间长度或头变化必须重试，token 不得混合两个 append 时刻。
2. 净窗口终稿失败仅允许已确认的 `MNUM` 非持久系统记录跳过；其余失败返回错误。
3. 被路由选中的子索引页读取/解码失败和 refno 失配返回错误，不合成增删改。
4. 模型计划存在性复核与操作流使用同一文件身份和目标会话。
5. 基线任一 chunk 失败后清掉本次 dbnum 写入，且不返回成功结果、不推进水位。
6. CATA/ref0 扫描失败、空/旧格式缓存、未解析 Required 根与 closure missing 不得形成
   成功缓存，并在下一次触发时重试。
7. 所有允许的容忍都带结构化计数和样例；正确性门不提供运行时关闭开关。

## 成功标准

- 注入终稿、live child、refno、基线 chunk、CATA scan/closure 错误时，旧水位保持不变。
- MNUM 可见地跳过，普通 noun 解析失败阻断。
- 同文件追加被接受；同 sesno 换文件被拒绝。
- 现有 issue-019/020、db8000 会话对拍与 data-only live 不出现假删除。
