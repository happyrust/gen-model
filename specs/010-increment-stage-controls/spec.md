# Spec 010：增量阶段控制

## 目标

为数据增量、模型增量、房间增量提供可独立配置的执行控制，并保持三阶段顺序依赖与水位语义。

## 需求

1. `DbOption.toml` 支持 `data_incremental`、`model_incremental`、`room_incremental`，缺省均为 `true`。
2. 对应环境变量可一次性覆盖配置；无法识别的环境变量值回落到配置值。
3. `data_incremental=false` 时扫描仍可入队，但任何入口调用共享 drain 都不得领取数据批次。
4. `model_incremental=false` 时，已应用的数据窗口提交数据、水位和 durable 模型计划，不执行模型前置、生成、非重生成消费及模型副作用补偿。
5. `room_incremental=false` 时不得消费房间增量目标。
6. 下游不得越过上游：模型积压只在初始化数据门允许且模型开关开启时消费；房间只在模型就绪且房间开关开启时消费。
7. `/api/v1/health` 返回三个布尔字段，日志明确说明被关闭阶段及保留的工作。

## 验收

- 纯函数测试覆盖默认值、配置值、双向环境变量覆盖及错误值回落。
- 源码顺序/门控回归测试证明共享数据 drain、批内模型路径、空闲模型路径和房间路径均受对应开关控制。
- `data=true/model=false/room=false` 的调试配置启动后，health 报告相同姿态；8000 的数据批次可运行而模型与房间阶段不消费。
