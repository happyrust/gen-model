# Feature Specification：启动修复无数据支撑的应用水位

## User Stories

### US1：启动即补齐未解析库与异常水位库

启动重扫发现水位为零、文件回退，或应用水位已追平但没有数据支撑的范围内数据库时，必须形成首次导入/重建批次，并在启动自动执行开启时完成基线解析。

### US2：合法空库保持稳定

一次成功基线明确得到零业务元素时，系统必须记录与应用水位绑定的空基线凭据；后续启动不得把它误判为幽灵水位。

## Functional Requirements

- **FR-001**：`applied_sesno == file_latest_sesno > 0` 且 `pe` 零行、空基线凭据不匹配时，启动重扫必须按首次导入形状入队。
- **FR-002**：空基线凭据必须与基线水位在同一事务写入；非空基线必须清除凭据。
- **FR-003**：预览、手动入队、自动重扫和 worker 必须共用同一幽灵水位判据。
- **FR-004**：存在性查询失败必须可见，且不得形成任何默认判定。
- **FR-005**：扫描阶段不得删除数据；回退清库仍只发生在 worker 冻结复核之后。
- **FR-006**：生产默认启动自动执行；显式 `startup_autorun=false` 仍挂起启动批次。
- **FR-007**：每条新增不变量必须有回退测试；live 测试必须覆盖“水位等于文件水位、零数据”的启动形态。

## Success Criteria

- 追平幽灵水位启动后，水位与文件一致且 `pe` 内容与文件一致。
- 合法空库连续启动重扫不会再次入队。
- 未解析库和回退库无需文件再次变化即可在默认生产配置下开始基线解析。
