# 025 实施计划

## 分期

**阶段 0（前置，不写生产代码）** —— 把 FR-7 的反例做成一条会红的测试（spec T01）。
这一步的产出决定后面的形态：证得出 → FR-6 必须选持久 pending 表，本轮重心是补正确性
缺口；证不出 → FR-7 退化为源码顺序断言，FR-6 可以选纯内存失效集，本轮就是一次纯提速。
**在拿到这个结论之前不要动 `sweep_inst_relate_flat` 一行。**

**阶段 1（止血，与阶段 0 结论无关）** —— FR-10（空串分歧）、FR-11（脏值计数
`LIMIT 1`）、FR-9（修复段改 migration）。这三条都不依赖失效集的形态，可以先走，
先把每轮三次全表扫砍到一次。

**阶段 2（主体）** —— FR-1 / FR-2 / FR-3 / FR-4 / FR-6：失效集、终态消费点、按 id 点名
刷新、空闲轮全表扫下线、源码形状门。

**阶段 3（闭环与保险）** —— FR-5 的纪律落到共享 geo（FR-7 选定的路线）、FR-8 读侧自检
与版本位、NFR-4 三个指标、全部验收。

阶段 1 与阶段 2 顺序可换；**阶段 0 必须先于阶段 2**；**FR-7 的回归必须先于 FR-1**——
不要在一个尚未证明正确的失效协议上做性能优化，那只是把缺口藏得更深。

## Constitution Check

| 原则 | 判定 | 说明 |
| --- | --- | --- |
| I 水位是承诺 | 不涉及 | 本 spec 不碰 `applied_sesno`、不碰数据批次收口。`insts_flat` 是读侧缓存，ADR-025 已定「水位只承诺数据落库，不承诺模型」。 |
| II 一条规则只有一份实现 | **有张力，见 Complexity Tracking C1** | 「哪些实例进 flat」的谓词今天只有 SurrealQL 一份；FR-8 的读侧行内自检会引入第二处判定（虽然只是一个更弱的必要条件）。 |
| III 静默失效是最高级别缺陷 | **本 spec 正为它而写** | 「旧值且非 NONE 的缓存」是标准的静默失效形态：读者不落兜底、没有日志、没有告警。FR-5 + FR-7 + NFR-4 是对这一条的正面回应。 |
| IV 队列可消费 / 可收口 / 可复活 | **约束 FR-6 选项 P** | 选持久 pending 表就要给它三条出路：drain 阶段过滤器覆盖、成功即删且按行内字段寻址、达上限的死信有复活路径。刻意不复用 `model_update_pending`（理由见 ADR-043 否决方案）。 |
| V 标识只用真值 | 不涉及 | 不新增标识解析。`geo_hash` 是内容寻址值，不是 dbnum 类标识。 |
| VI 不变量由可执行的守护看住 | **硬要求** | FR-4 的顺序、FR-1 的形状门、FR-7 的共享 geo 反例，三条都必须有「回退到旧写法就会红」的测试。阶段 0 的存在就是为了让 FR-7 那条先有。 |

附加约束：

- **SurrealQL 拼接**：新增语句里若有外部字符串（迁移标记名等），过
  `dbnum_state::escape_surql_str`。
- **并发模型**：不新增数据批次消费路径，ADR-011 不动。失效集的刷新仍在既有空闲轮里，
  不是第二个 worker。

## Complexity Tracking

**C1（对原则 II 的偏离）：「哪些实例进 flat」将出现第二处判定。**

- **偏离内容**：权威谓词今天只有 SurrealQL 一份（回填段那个子查询）。FR-8 会在读侧
  加一条 `booled_id` 有效而 `insts_flat[0].geo_hash` 与之不符 → 判为缓存未命中。
- **为什么无法避免**：这正是 RM13 的**唯一**行内可判形态。要按原则 II 只留一份，读侧
  就得对每一行重跑那个图遍历子查询——那恰好是缓存要消除的 +8.7s。换句话说，
  「只有一份判定」与「缓存存在」在这里天然冲突。
- **偏离的边界**：读侧那一份**不是权威的复制品，是它的一个更弱的必要条件**——只判
  「明显不一致」，判不出「一致」。它只有一种后果：多走一次 pass2（慢）。它不能、也
  不允许被用来断言缓存有效。这一点写进读侧实现的注释，并用一条测试钉住「自检为真时
  必须转 pass2，而不是就地采信」。
- **将来怎么收回**：ADR-043 的长期方向（`insts_flat` 变成生成任务的终态产物）落地后，
  权威谓词会整体搬到 Rust，SurrealQL 那份退役，判定重新变回一份。届时删掉 C1。

**C2（不算偏离，但要记一笔）：FR-8 的 `insts_flat_ver` 是一次全库形态变更。**
它本身不违反任何原则，但会让存量行在读侧眼里集体变旧。处置见 R5——方案没写下来之前
不动手（tasks T21）。

## 关键风险

**R1：阶段 0 可能推翻整个 spec 的重心。** 如果 `bad → retry → meshed` 证不出可复现的
反例，本 spec 就从「补缺口 + 提速」缩成「提速」，FR-5/FR-6/FR-7 大幅简化。**这是好
结果，不是浪费**——反过来，跳过阶段 0 直接做阶段 2，等于在一个未证明的失效协议上加速。

> **T02 结论（2026-08-24）：能复现。**
> `live_shared_geo_bad_retry_must_refresh_sibling_insts_flat_on_disposable_db`
> （`src/fast_model/pdms_inst.rs:2042`）在 8019 一次性内存沙箱上逐句同形复刻生产序列，
> 断言红：只对 B 定向重生成后，共用 geo 的 A 行 `insts_flat` 停在旧值 `[]`（非 NONE），
> B 行回填出 `["20260823"]`。裁决：**FR-6 必须选选项 P（独立持久 pending 表）；FR-7
> 保持完整功能需求，走路线 B（反向失效）**——路线 A 要把网格算法版本纳入内容寻址
> hash，与 `reset_bad` 的「同 hash 重试」既定语义正面冲突，血面远大于低频反向遍历。
> 本轮重心自此定为「补正确性缺口」优先于提速。留证
> `docs/evidence/2026-08-23-insts-flat-invalidation/t01-shared-geo-counterexample.md`。

**R2：失效集的来源清单会漏。** `insts_flat` 依赖 `geo_relate` 的增删与
`visible`/`geo_type`/`trans`、`inst_geo.meshed`、`booled_id`。今天靠一个「packets 非
空」的粗脏位无差别覆盖，改成精确集合之后，**漏一处不会有任何用例变红**，症状是那几行
长期走兜底（若 FR-5 成立）或直接变旧（若不成立）。
缓解：(a) FR-5 是 NON-NEGOTIABLE，把最坏后果封在「慢」；(b) 加一道源码形状门——凡是写
`geo_relate` / `inst_geo.meshed` / `booled_id` 的语句渲染点，必须同批产出失效 refno，
新增写点要么接上要么进豁免表并写明理由（形状门照本文件现成的 `include_str!` +
`split_once` 惯例做，`src/fast_model/pdms_inst.rs` 的
`flat_cache_prefers_booled_mesh_over_positive_primitives` /
`flat_sweep_repairs_stale_booled_rows` 就是同一子系统里的现成模板）；
(c) NFR-4 的 `flat_fallback_ratio` 是这条风险的运行期温度计。

**R3：并发取批写错就会吃掉重新变脏的标记。** 「先取 ID → 刷新 → 逐个 remove」在刷新
期间同 refno 又被弄脏时，会把新标记一起删掉，且不会有任何现象。FR-2 写死用整体 take +
失败并回，并补一条并发回归。

**R4：启动那次全表扫仍然存在。** 老库首次启动照旧付一次全表价（AMS 实测 51.4s / 5.3 万
行；7997 之后更久）。这是设计意图。但它与 FR-9 的 migration 标记叠在一起时要想清楚
先后：**标记只覆盖修复段**，回填段的启动自愈是常驻的。

**R5：`insts_flat_ver` 是一次全库形态变更。** 加版本位意味着所有存量行在读侧眼里
立刻变成旧版本 → 全库退化为 pass2 兜底，直到后台刷完。要么随 FR-9 的 migration 一次刷
完再切读侧，要么让读者同时接受 `ver` 缺失与当前值。**不要在没想清这一步之前先上版本位。**

**R6：外部二审的结论要复核，不能照抄。** ADR-043 引用的两条已经在本仓源码里复核为真
（`render_inst_geo_upsert` 的 `reset_bad`；回填段对空串 `booled_id` 的处理与修复段
相反）。其余建议（pending 表形态、版本位、指标）属于设计取舍，按本仓惯例自行裁决。

## 与既有决策的关系

- **ADR-038 不动。** 本 spec 不往 journal 里塞图遍历；失效与刷新都在持久层非 journal
  路径上，与 `backfill_inst_relate_anc` 同族。
- **ADR-011 不动。** 不新增数据批次消费路径；刷新仍挂在既有空闲轮。
- **ADR-025 不动。** 阶段序（数据 → 模型 → 空间 → 房间）不变。
- **P4（2026-08-07 计划文档）被修订**：写时物化的**触发方式**从「进程级脏位 + 全表
  清扫」改为「终态失效集 + 点名刷新」；物化的**内容与读侧三分法**不变。
- **spec 019 被修订**：布尔存量修复从常驻热路径段降为一次性 migration。
- **ADR-041 §3 的全局几何并发闸**若先落地，本 spec 的刷新动作要接进同一份额度，不另
  开并发。
