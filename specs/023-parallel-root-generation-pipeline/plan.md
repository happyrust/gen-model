# 023 并行生成与收口提速实施计划

## Constitution Check

- **水位是承诺**：不动 `applied_sesno` 的推进条件、不动尾事务语义。并行只发生在
  `STAGED_COMMIT_SERIAL` 之外的「解析 + 暂存 + 生成」与收口段内部循环，写回与水位仍一次一个。
- **一条规则只有一份实现**：并发宽度从多处写死收敛为唯一的全局几何闸；手动与 watcher
  两条触发路径共用同一份额度，不出现第二套并发口径。
- **静默失效是最高级别缺陷**：并行下的单根失败按 `022` 既有死信路径上报，不吞。闸的额度为
  未知值时启动失败，不静默回退默认值。
- **队列任务可消费 / 可收口 / 可复活**：死信语义、attempts 门槛与显式 retry 复活路径不变。
- **标识只用真值**：稳定序的排序键使用根 ID、表名与 record id 本身，不构造派生标识。
- **不变量由可执行的守护看住**：稳定序、块指纹确定性、无写死并发宽度、Model→Room 顺序
  各配纯函数或源码形状断言。
- **并发模型**：不新增数据批次消费路径，不改 `data_batch_workers` 语义，宪法「并发模型」
  段无需修订。
- **运行环境**：Windows / PowerShell，仓库锁定工具链；不执行 `cargo clean`。

未发现需要列入 Complexity Tracking 的宪法例外。ADR-041 对 ADR-017/021/025 的修订属于
`024` 的前置，本规格不依赖它们生效。

## 阶段

1. **先量基线。** 在不改任何生成代码的前提下，给全量基线加分段计时（解析 / 生成 / 写回 /
   空间树 / 房间），跑一遍留数。没有这组数，后面所有加速比都无从归因。
2. **建闸。** 新增全局几何并发闸与 `DbOption` 配置项（默认 = 物理核数，最小 1，未知值启动
   失败）；先只接 `manifold_bool` 一处，验证额度 = 1 与改前等价。
3. **收编 fan-out。** `occ_generate`、`pdms_inst`、`gen_model` 的固定宽度并发依次接入同一份
   额度，配源码形状断言禁止新的写死宽度。
4. **稳定序封本。** journal 改为每根本地 buffer + 根结束整段合并 + 封本按稳定序排定；
   条目组作为排序最小单位，保住 ADR-038 第 2 条。补重复运行的确定性回归。
5. **收口段并行。** 房间全量收敛的逐房间判定接入闸；空间树重建的分页读接入闸，换树 / 发布段
   仍持 `SPATIAL_STATE_SERIAL`。语义保持全量重建不变。
6. **失败语义钉子。** 并行下单根死信不影响同片其余根提交；房间收敛口径「对已有 mesh 的元素
   全部定论」补回归。
7. **对照与等价验收。** 额度 = 1 与额度 = 核数各跑一遍，逐表比对 digest，记录 wall-clock
   与分段归因。
8. **文档与质量门。** 更新 `changelog.md`、live 台账与证据目录；跑 `cargo fmt`、
   `cargo check`、相关 feature 单测与 isolated live 测试；执行 `sigmap verify-plan`、
   `sigmap verify-ai-output`、`sigmap review-pr`。

## 风险

- **闸可能没有收益。** 如果根内既有的 fan-out 已经把核喂满，根级并行只会增加争用。
  阶段 1 与阶段 7 的对照组就是为了尽早发现这一点；发现了就停在阶段 5（收口段并行），
  那部分收益独立成立。
- **写回是串行的，加速比有天花板。** 前段压到极限，总时长仍停在「前段 / 核数 + 写回 + 收口」。
  这是本规格接受的边界，突破它属于 `024` 的流水线重叠。
- **稳定序可能改变写回块的划分**，进而改变现场日志形态。这是预期内的：块边界在此之前
  本来就不确定，本轮是把它第一次钉住。

## 验证与回滚

- 基线与改动后的命令、输入、分段耗时、逐表 digest、退出状态写入
  `docs/evidence/2026-08-21-parallel-root-generation/`。
- 回滚：把闸额度调回 1。这一路径必须在阶段 2 就可用，并在阶段 7 实测覆盖。
