## 本轮取证结论（详见 `docs/plans/2026-08-31-core-aligned-increment-architecture.md`）

**core.dll 带完整 MSVC 符号**，比上一手在 Core3D 匿名地址上摸索省一个量级。

### 1. core 的增量是五层管线；我们缺中间两层

`L0 会话定位 → L1 索引候选 → L2 逐元素分类 → L3 语义账 → L4 消费者上卷`

- L1 在 core 里**只是候选过滤器**（`DB_IndexTableCompare`），不是结论
- **L2 `DB_Compare::checkEle`（0x5a45cd0）才是权威判据**：12 个回调
  （create{First,After,Null} / deleteAll / include{First,After} / reorder{First,After} /
  attChange / ruleChange / {insert,remove}InSecondaryList）
- L3 `DB_UserChanges` 8 个语义桶；祖先抢占在 `DB_RawChanges::isElementTopLevelCreate/Delete`
- e3d-model 把 L1 直接接 L4，中间用 `placement_drifted` + `collect_positive_subtree`
  两个几何启发式顶替 —— **core 里没有任何对应物**

### 2. P0-1 在 core 的架构里根本不存在

`checkEle` 显式测 `hasAttributeChangedBetween(el, ATT_OWNER)` → `includeAfter/First` →
`DB_UserChanges::elementIncluded(el, 旧属主)`，把元素 + 新旧两个属主都记进账。
**改挂就是 OWNER 这个属性变了**，逐属性差分必然抓到。不需要比 world_matrix、
不需要每候选爬 owner 链 → 变换级联那套可以整体删掉，顺带解决大窗口性能。

### 3. ★ 模型单元定义 = 字典字段 `toplevel`（661628），不是手写名单也不是 CACHID

三处独立坐实：
- `DES_DrawList::getAncestorTOPFElement`（0x10515fc0）谓词 `FieldEqual<bool>(661628, true)`
- `DES_DrawList::getChildTOPFElements`（0x105166d0）同一谓词
- `FNDTOP` → `nounlib/LISTOP`（core.dll 0x561c93c），实读常量 `0x5DB6D4C`=661628、`0x5DB6D50`=659518

core.dll 有具名访问器 `?toplevel@DB_Noun@@QBE_NXZ` @ 0x58dba70。
**`FIELD_TOPLEVEL=661628` 与 `FIELD_PRIMITIVE=659518` 在 `old-parse-pdms-db/src/dict.rs:68/38`
早已定义**；`primitive` 已导进 `noun_flags.json`，**`toplevel` 没导** —— 全套唯一缺的一格数据。

`LISTOP` 完整规则：`toplevel && (noun==WORL || owner!=TMPL)`
`|| (primitive && (noun∈{RPLA,PVOL,DRAW} ? owner∈{SITE,ZONE} : noun==FIXING ? 上溯到 STRU : false))`

### 4. ✘ 纠正上一手 A7/A8：CACHID 不在两会话差分路径上

`hasTopLevelGraphicsChanged`（0x1052c850）**xrefs 实查全模块只有一个调用方**：
`PostLocalChanges+0x1aa`（0x1052b04a，GETWORK 路径）。
`changesBetweenSessions`（我们的场景）**完全不看 CACHID**，三类候选一律上卷。
→ b9fc69a5「CACHID 在设计库记录里 `encoded_location=0`」不再构成阻塞，**这条整个不必对齐**。

### 5. P0-2 隐式管身：core 有现成硬编码答案

`hasElementChangedBetween`（0x593d6d0）对 `NOUN_TUBI` 特判 `(POS, ORI, ITLE, SPRE)` 短路或；
`FNDTOP` 让 TUBI 上卷时跨过 BRAN 那一级。直接抄。

### 6. 目录跨库：core 也不靠 owner 闭包

`SPRE` 是 type 5 指针属性，`DB_Ref::operator==` 比得出「重新指向」；
但**目录件自身内容变了**它同样抓不到，靠的是 `PostDBFileChanges` → `ClearCaches` 全清。
→ 跨库不该做进窗口差分，应是「目录库版本变 → 引用者整体失效」的独立通道。
