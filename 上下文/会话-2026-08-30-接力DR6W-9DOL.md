### ③ 7333 重跑 → 揪出 DB 写侧缺陷（本会话最重要的发现）

重跑 `--dbnum 7333 --sample 200000` 后，2984 处 CRFA 从「形状冲突」转成了「真值冲突」，
明细全长这样：

```
[diff] 23717_218787 CRFA: direct=RefU64Type(23717_218788) db=RefU64Type(3_0)
```

**direct 侧逐元素不同且是邻近真引用，DB 侧 30 条全是常量 `3_0`。** 顺着查库坐实：

| 查询 | 结果 |
|---|---|
| `PCLA` 的 CRFA 取值种类 | **只有 3 种**：`null` 7694、`pe:3_0` 2788、`pe:4_0` 2 |
| 探针报的文件侧形状 | `RefNoArray[3]` **2982**、`RefNoArray[4]` **2** |
| 全库扫 `3_0`/`4_0` | PCLA 2788+2、HELE 1132+0、PCOM 0+2，合计 3924；**其它取值一个没有** |
| `pe:3_0` / `pe:4_0` 是否是真实元素 | **都不存在**（`SELECT count() FROM pe WHERE id = …` = 0） |

**结论：DB 写侧把引用数组的「槽位数」当成了 refno 的 word0 写进去。**
文件是 `RefNoArray[3]` → 库里存 `pe:3_0`；`RefNoArray[4]` → `pe:4_0`，**数量 2 对 2 精确吻合**。
`pe:3_0` 不是引用，是数字 3。这批值是垃圾，不是数据。

**所以 direct 侧是对的，DB 侧是错的。** 等价门不可能靠让 direct 去迁就一个垃圾值转绿。

探针的 `diff_maps`（`src/bin/direct_attmap_probe.rs:153-188`）对「仅 DB 有」的键做了
模型中立豁免（`attribute_affects_model`），但对「值不同」那条路**没有同款豁免**——
所以修法 A 只是把这 2984 处从 `shape_conflicts` 挪到了 `mismatches`，两者都进等价门，
门照样红。CRFA 是模型中立键（上一轮日志「仅 DB 有的模型中立键：CRFA 2994」即证）。

**ISSUE-027**（`issues/ISSUE-027-write-side-stores-array-length-prefix-as-a-refno.md`）：

标题从「槽位数当成 refno」**修正为「长度前缀当成 refno 的高位字」**——
本轮查到了字节级根因，比 DR6W→9DOL 早先的说法更准：

`old-parse-pdms-db/src/parse.rs::parse_raw_explicit_attrs` 按 schema 声明分派，
标量臂（1932-1936）`tuple((be_u32, be_u32))` **从载荷开头直接读**，
而引用数组载荷是 `[u32 长度][u64 引用]×n`，数组臂（1955-1966）**是先吃掉长度前缀的**。
两臂对同一段载荷的布局理解不一致 → 标量臂把长度当 `word0`、把空槽 0 的高位字当 `word1`。
`from_two_nums(3, 0)` = `pe:3_0`。

**本轮新取的证据（全部实跑，非转述）**：

| 证据 | 命令 | 结果 |
|---|---|---|
| 取值分布 | `SELECT CRFA,count() FROM PCLA GROUP BY CRFA` | null 7694 / `pe:3_0` 2788 / `pe:4_0` 2，**其它 0 种** |
| 同上 HELE | 同上换表 | null 273 / `pe:3_0` 1132 |
| 同上 PCOM | 同上换表 | null 7 / `pe:4_0` 2 |
| 幽灵 id | `SELECT count() FROM pe WHERE id = type::thing('pe','3_0')` | `result: []`（0 行），`4_0` 同 |
| **字节级** | `direct_attmap_probe --refnos 23717_114143,23717_62660 --dump-keys CRFA` | `raw=RefNoArray([RefNo(0/0), RefNo(0/0), RefNo(23717/114144)])` vs `db=RefU64Type(3_0)` |

最后一行是决定性的：**3 槽、前两槽空、真引用在第 3 槽**——
所以库里恒是 `3_0`（长度 3 + 空槽 0 的高位字 0）。
