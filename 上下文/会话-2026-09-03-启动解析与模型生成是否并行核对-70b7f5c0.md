# 会话 70b7f5c0 · 核对「启动时解析与模型生成是否已并行」

> 接力自会话 981ac815（P1–P3 计划分析）。用户提问：「现在的启动是否按照需要 解析和模型生成能并行的发生了。」
> 只读核对，本会话未改源码 / 文档（除本记录）。

## 一、结论

**没有。** 当前启动仍是 ADR-025 的串行：`Meta → Catalogue → Design`（data_ready）→ 启动模型复核 →
模型积压消化 → 房间。ADR-058 D7 的「两条并行链」（文件身份解析 → 模型面 ‖ Meta → Design 摄入）
在计划里挂在 **S3 第 3 条**，S3 未开工；现已落地的只有 S1 与 P1–P3 修复批。

## 四、真要落 D7 要动的面（供评估，本会话未做）

   `startup_reconcile_pending`）；`postprocess_allowed()`（房间）仍要 `model_ready`。
2. `lib.rs`：`reconcile_model_coverage_at_startup()` 提到数据等待之前（它只读文件 + `gen_root`）；
   模型门在 manifest 装好（文件身份就绪）时开，不等 `data_ready`。
3. worker 单消费者：数据批次与模型 drain 抢同一个 worker，`model_drain_yield_reason` 的 `DataQueued`
   让位是有意的公平策略；真并行要么开第二车道，要么在 ADR-025 对照块说的 D10-B（并发放开）里一起做。
4. 翻转护栏：`startup_waits_for_data_then_models_before_rooms`、
   `initialization_gate_precedes_every_model_pending_claim`（`model_update_pending.rs:8952`）及
   `initialization_phase.rs` 里断言 `!model_generation_allowed()` 的单测（`:959`）。
5. D7 与 S3 第 1 条（删 Catalogue 相 / CATA 基线）绑在一起排的；两者技术上可拆——D7 只动门，

## 六、15:26 追问：「初始化与稳态下模型生成与 DESI 解析能否并行、分别落库；除 SYST 外 CATA 等不入库」

### 6.1 现状（只读核对）

| 场景 | 数据链 | 模型链 | 是否并发 |
|---|---|---|---|
| 增量启动 | 首扫 → manifest → Meta/CATA/DESI 批次按相冻结、worker 逐相消化；每批尾事务写 `pe`/`ATT_*` + `dbnum_state` 水位 + `model_update_pending` 意图 | 门已开（D7-lite）、启动复核已提前入队；但 worker 积压 drain 因 `DataQueued` 零进展直到数据队列排空 | 门上是，消费上不是；仅 REST 按需生成并发 |
| 稳态 | 文件事件 → 重扫 → 新 manifest → DESI 批次 → 尾事务同上；`data_batch_workers>1` 时多个 DESI 窗口可并发（数据-数据） | 批次跑完 → `idle_round` → drain 积压 → 写 `gen_root`/mesh/`inst_relate`；下一个数据批次一来就让位 | 事件内串行（数据优先），数据-模型不并发 |

落库是分开的：数据侧 `pe` / `ATT_*` / `dbnum_state` / `model_update_pending` / `ref_rev`（引用侧建边）；模型侧
`gen_root` / mesh / `inst_relate` / 空间树落盘。表与事务都分开，只是没同时跑。

### 6.2 真并行（D10-B）要动的面

1. 模型车道：独立 tokio 任务循环 `drain_data_phases_disposition` + 空间落盘 + 房间轮，自己的 wake（`enqueue_plan` 后唤它）。
2. `model_drain_yield_reason` 去 `DataQueued`；`EpochChanged` 让位要重新论证（每次重扫都换 epoch，车道不该为此停）。
3. 并发风险：同 dbnum 数据尾事务新增意图 vs 正在重生成的根 → 靠 `gen_root` 凭证 CAS；`GLOBAL_AABB_TREE` RwLock 双方都碰；
   SurrealDB(RocksDB) 事务争用；`mark_model_ready` 仍要 `data_ready` + 积压空。
4. 护栏：`batch_worker.rs` 里十余条 `split_once("async fn idle_round(")` 源码顺序断言全部重写。
5. 估 1–2 周 + 真库压测。
