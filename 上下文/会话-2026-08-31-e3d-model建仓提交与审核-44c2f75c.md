## 三、问题清单

### P0 — `rvm_compare` 整个 bin 编译不过

`src/bin/rvm_compare.rs:181-183` 用了 let-chain：


edition 是**有意选的**，不是忘了升：`rustfmt.toml` 里写着「crate 是 edition 2021（与 e3d-io / e3d-attlib 一致），
但 import 排序沿用 2024 风格」。gen-model 才是 edition 2024。

### P1 — `cargo fmt --check` 不干净

`src/bin/rvm_compare.rs:853` 一处 `assert_eq!` 需要拆行。
（`cargo fmt --all` 还会连带报 `e3d-io/src/index/mod.rs:482` 的尾部空行，那是邻仓的账，不在本仓。）

### P2 — 实例缓存白建一遍网格

`primitive_instance.rs` 的 `instantiate_box` / `instantiate_cylinder` 为了保留原校验文案，
先 `let _ = box_solid(x,y,z)?;` / `let _ = cylinder_solid(diam,height)?;` **完整建出真实尺寸的实体再丢掉**，
然后才去取 canonical 单位网格 + `placed()` 变换。于是「缓存命中」这条路比直建还多做一遍事，
`hits` / `misses` 计数暗示的建模期复用其实并不存在——真正的收益只在下游持久化
（`inst_geo + geo_relate.trans` 免去每元素一份 `booled_id` 网格），这一点 doc 注释里其实写清楚了。
改法很轻：把尺寸校验抽成独立函数，别构造那个一次性 Manifold。R=23400 那种 484 段圆柱代价不小。

### P3 — 潜在/健壮性

- `polyhedron.rs::intern` 按 f64 **位模式**去重顶点，`0.0` 与 `-0.0` 位模式不同但数值相等，
  会被拆成两个索引 → 共享顶点裂开 → `from_mesh_f64` 报非流形。
  另外现代/旧式变体只靠 `members[0].element_type() == "POLPTL"` 一句话判定，首成员一变就整个走错分支。
  两条都没有真数据兜底——模块 doc 自己写了 ams1112 无 POLYHE/POHE/NPOLYH。
- `transform.rs::matrix_relative_to` 把「descendant 不在 ancestor 子树里」报成
  `DbElementError::NotFound { sesno: 0 }`，是个拼出来的错误，报告里读起来会误导成「元素找不到」。
- `primitive_instance.rs` 三处 `.expect("primitive cache poisoned")`：一个线程 panic 就让整跑批陪葬，
  `unwrap_or_else(|e| e.into_inner())` 可以降级continue。

### clippy 13 条的性质

10 条是 `neg_cmp_op_on_partial_ord`，全部落在 `!(x > 0.0)` / `!(h > f64::EPSILON)` 这个写法上。
**这是故意的**：`!(x > 0.0)` 连 NaN 一起挡掉，改成 clippy 建议的 `x <= 0.0` 就把 NaN 放进去了。
应当加 `#[allow]` + 一行理由钉住，而不是「修」——否则迟早有人照 clippy 提示改出一个 NaN 洞。
余下 2 条 `chunks_exact_to_as_chunks`（mesh.rs:62 / polyhedron.rs:254）、1 条 `type_complexity`（transform.rs:35）是真可以顺手改的。

### 11.2 P2：实例缓存不再白建一遍网格

`instantiate_box` / `instantiate_cylinder` 原先 `let _ = box_solid(x,y,z)?` **完整建出真实尺寸实体再丢掉**，
只为留住那句校验文案，然后才取 canonical 单位网格做变换。等于「缓存命中」比直建还多干一遍活。

改法：把尺寸校验从 `box_solid` / `cylinder_solid` 里抽成 `validate_box_dims` / `validate_cylinder_dims`
（不构造任何几何），两条路共用 `BOX_WHAT` / `CYLINDER_WHAT` 两个常量保证文案逐字一致；
顺带抽出 `cylinder_tilt`，免得直建路和实例路各写一份「+Z 摆到局部 Y」的转角。

**实测**（R=23400 → 484 段圆柱，release，2000 次取均值）：

| | 命中路径 | 直建 | 比值 |
|---|---|---|---|
| 改前 | 1.581 ms | 1.278 ms | **1.24×（比直建还慢）** |
| 改后 | 0.329 ms | 1.420 ms | **0.23×（快 4.3 倍）** |

命中路径本身 1.581 → 0.329 ms，快 4.8 倍。数字写进了 `instantiate_cylinder` 的注释原地。
另外实例路补了 `ensure_solid`——原先那次白建顺带做了非空校验，抽掉校验后要把这个保证接回来，
而它只是查 `is_empty()/num_tri()`，零成本。

### 11.3 P3a：`-0.0` 顶点不再把共享点拆成两个

`polyhedron::intern` 按 f64 位模式去重，而 `(-0.0).to_bits() != (0.0).to_bits()`。
落在坐标面上的 POIN 分量带负号并不稀奇，一张面写 `-0.0`、邻面写 `0.0`，同一个点就落成两个索引，
共享边退化成两条单用边，**闭合的壳被 `from_mesh_f64` 判非流形**。改成入表前先把零收成 `+0.0`。

这条原先被记为「没有真数据兜底」的推测项，现在有了可复现的证据：新加的
`negative_zero_on_one_face_still_shares_vertices_with_the_rest` 拿立方体只把 z=0 那张面的零改成 `-0.0`，
**回退修复后该用例当场红**（`polyhedron_solid` 直接 unwrap 失败）。

### 11.4 P3b：`matrix_relative_to` 不再借 `NotFound` 说话

原先「不在 ancestor 子树里」报的是 `DbElementError::NotFound { sesno: 0 }`——`sesno` 是**凭空编的**，
渲染出来是「db N 会话 0 的索引里没有 refno」，读报告的人会去翻索引，而索引没有任何问题。
新开 `RelativeMatrixError`（`NotADescendant` + `#[from] DbElementError` 透传），文案改成
「X 不在 Y 的 owner 子树里，求不出相对矩阵」。

`DbElementError` 是 e3d-io 的类型，加变体得动邻仓，所以在本 crate 侧开新类型。
`matrix_relative_to` **全仓零调用点**（只有定义处），签名变更不波及任何人。

### 11.5 P3c：缓存锁中毒不再让整场跑批陪葬

三处 `.expect("primitive cache poisoned")` 换成 `unwrap_or_else(PoisonError::into_inner)`，
收进 `read_meshes()` / `write_meshes()` 两个方法。理由写在方法上：表里装的全是
`build_canonical` 一次性建完才插入的纯函数产物，某线程建网格时 panic 只会让它自己那次 `insert` 没发生，
不会留下半张表——为这个把 AMS1112 三万个元素的跑批连坐掉不成比例。

### 13.5 M1 `ImpliedTubes::total_length` 把「没有管」和「没量过」混成同一个 None

`pipeline.rs` 的 merge 语义是 `(Some(a), Some(b)) => Some(a+b)`，**其余一律 None**，
且 `ImpliedTubes::default().total_length == None`。P1 阶段所有报告都是 None，看不出问题。

**P2 一旦开始填长度就会出事**：`gen_ams` 多根合并时，只要有一棵子树不含任何路由容器
（它带的是 default 的 `None`），整个模型的 `total_length` 就塌成 `None`。而「无管子树」
的正确语义是 `Some(0.0)` 而不是「没量过」。

作者写了 `an_unmeasured_total_length_poisons_the_sum_instead_of_counting_as_zero`
把这个行为**钉死**了 —— 钉的方向在 P1 完全正确，在 P2 会变成锁住 bug 的那颗钉。
建议：`count == 0` 时置 `Some(0.0)`，或给 `ImpliedTubes` 加显式的 `measured: bool`
把「量没量过」与「量出来是多少」拆开。

### 13.6 M2 路由容器的成员被枚举两遍

`generate_subtree` 的 `RouteContainer` 分支先调 `implied_tube_count(&el)`，它
`for member in container.members()?` 并对每个成员调一次 `element_type()`；
紧接着 `push_members` 又把同一批成员遍历一遍。BRAN 这种成员多、族又大的（账上 561 条
管身）等于双倍属性读。可以在 `push_members` 那一趟里顺带数出来。纯性能，不影响正确性。

### 13.7 L1 `Category` 三个谓词是白名单式，新变体默认 false 且编译器不报错

`is_negative` / `is_positive_solid` / `consumes_members` 都写成 `matches!(self, A | B | C)`。
这次新增 `RouteContainer` / `RouteMember` 恰好就该三个全 false，而且补了
`route_nouns_neither_build_nor_consume` 钉住 —— 这次是对的。但下一个变体若该是 true，
编译器**不会**提醒，只会静默走 false。与本 crate 别处「宁可 `unreachable!` 也不静默默认」
（`elmodl.rs:506`）的口径不一致。

### 13.8 站得住的部分（本轮复核）
