## 一、核对链路（把「e3d tty 导出 rvm」这条路摸清了）

E3D 侧 TTY 无人值守导出（`scripts/e3d/*.mac` + `run_*_nogfx.bat`）：

```
des.exe ams SYSTEM/XXXXXX <project> < 导出宏.txt      # PDMS_NOGRAPHICS=1
  repre insu off / repre obst off / repre tube on      # 只要实体、要管身
  export implied tube into separate containers
  export system /expdri.so
  export file <out.rvm> ; export <CE> ; export finish
```

产物 `.rvm` → `rvm-rs`（`parse_rvm`）→ 快照 `*.rvm.json`（基线）。
对拍三方（`rvm_compare` 模块文档）：

- **基线**：`test_data/rvm/<name>.rvm.json`（E3D TTY 导出）
- **生成侧**：`gen_ams … --root <refno> --out <dir>` → `elements.json`
- **面片**：`rvm_facets_dump --rvm <name>.rvm --contains "of <owner>"` → facets.json（顶点实算 AABB，
  比快照自带 bbox 可信，见 rvm_compare 模块文档「基准 AABB 必须来自面片顶点」）

判据在元素**局部系**比 AABB：`exact` ≤0.05mm（f32 舍入）/ `chord` ≤ 弦高 / `reference_artifact` / `off`。

## 三、二期管道线：对不上，根因是几何范式不同 [本会话实测]

拿管道 BRAN `C-OR-1R345-C`（refno `24384/23257`, dbnum 8000）对拍：

| | 我方 `gen_ams`（当前 HEAD） | E3D RVM 基线（`C-OR-1R345-C.rvm.json`） |
|---|---|---|
| 出的东西 | **6 根 TUBI 隐式管身圆柱**（直径 50） | **7 个 FTUBE + 2 个 BEND** |
| 几何 kind | Cylinder | FTUBE=Box[len,50,30]、BEND=FacetGroup |
| 属主/noun | `owner=PIPE /1RX-345`, `noun=TUBI` | `owner=BRANCH /C-OR-1R345-C`, `noun=FTUB/BEND` |
| 粒度 | 相邻两构件**之间**一根管 | **每个管件**一个 primitive |

`generate_subtree` 总账：`generated=6 (全 TUBI)`，`route_members=9`（FTUB/BEND 等本体不出几何，
计 `catalog_pending`）。两边主键 noun4 无交集（`TUBI` vs `FTUB`/`BEND`），`both` 必为 0。

**三条坐实，说明这不是导出设置能修的：**

1. **E3D 的管几何范式就是「每件一 primitive」。** `1RX07-LCT.rvm` 是 `repre tube on` +
   `export implied tube into separate containers` 导出的（`scripts/e3d/rvm_export_1rx07_lct.mac`），
   137 个几何仍是 `Box:109 + FacetGroup:28`，**零圆柱**。开了「导管身」E3D 也不给隐式管身圆柱——
   它把 FTUB/BEND/ELBO 各自的目录几何摆出来，管身不是独立圆柱件。
2. **二期目录件几何（FTUB/BEND 本体的 CSG）尚未实现**（`catalog_pending`，里程碑边界，
   见 c03e9977 存档「管件几何走 SPRE→CATR→GMSE，属二期」）。我方现在只出隐式管身圆柱。
3. **`gen_ams` 对 TUBI 的对拍主键有 bug**：`owner_desc` 取到了 BRAN 的父 `PIPE /1RX-345`
   而非 `BRANCH /...`，且 6 根 TUBI 的 `ordinal` 全是 `8`（见生成的 elements.json）——
   `rvm_compare` 当场 `生成侧主键重复：TUBI ordinal 8` 而 bail。即便范式一致，这个键也得先修。

## 四、要用户拍板的（不是改代码能自动决定的）

管道模型要能「确保生成一致」，先决定**拿什么跟什么比**：

- **路线 A：照 E3D 范式，出目录件几何。** 实现二期 FTUB/BEND/ELBO 等的目录 CSG（SPRE→CATR→GMSE
  + CRCATI 基本体），主键用 `BRANCH /xxx` + noun + ordinal，直接与现有 `.rvm.json` 逐件对拍。
  隐式管身圆柱另作我方内部产物，不进这条对拍。工作量大（整个二期目录件线）。
- **路线 B：给隐式管身单独立对拍口径。** E3D 不导独立管身圆柱，所以只能间接验：把我方 TUBI 圆柱的
  轴线/端点/半径 与 E3D 那批 FTUB Box 的中心线/尺寸对齐着比。需要新写一套非 AABB 的对拍器。
- 无论哪条，都要先修 `gen_ams` 的 TUBI 主键（owner 该是 BRAN 不是 PIPE、ordinal 要按管顺序发）。
