# 3.1.1核心功能模块

# (1) 设计手册模块

设计手册模块主要用于各个存储设计专业的材料编码表，并形成项目的专业编码汇总表。作用于设计过程中，通过模型中心抓取模型数据，结合该处材料编码表，按照材料编码进行自动化的汇总统计。

用户通过点击相应专业编码表操作界面的新增，通过Excel导入或者手动录入的形式，开始录入该项目对应的物料编码表。系统支持多次录入，会对录入的数据进行检测，对已有的数据进行更新操作，追加新录入的数据。最终，形成本项目本专业的材料汇总大表。

# 汇总表

目前该功能使用正常，能够正确录入、导入专业的材料编码表，并可以自动汇总形成专业的材料编码表。

# (2) 进度计划模块

进度计划模块用于对接CIMS、数据中台，通过接口集成的方式获取项目的三级计划数据，并在系统中存储。在存储后的三级计划数据的基础上，通过四级计划编制功能，在系统中编制、创建相关的四级计划。

用户在生成后的四级计划数据后，经过系统中的编校审流程后，系统将四级计划数据提取，组装成结构化的数据，推送至CIMS中。

目前该功能使用正常，与数据中台、CIMS的接口均正常运行，能够正确获取三级计划数据和推送四级计划数据。

# (3) 业务提资模块

该模块主要作用于专业平台之间相互提资，即实现不同专业平台之间的数据共享、数据交互。

通过接口集成的方式，通过数据中台接收其它专业平台发布的数据，并在系统中进行存储、分类利用。通过接口集成的方式，发布专业的结构化数据至数据中台，由数据中台进行数据的处理和分发至其它专业平台。

用户通过在电缆敷设模块平台、E3D插件端或者系统的模型中心功能中进行操作后，通过接口服务或内部数据交互的调用方式，将结构化的数据提交至系统中，包括：孔洞数据、埋件数据、其它模型提资数据等。系统接收到此类数据后，会先通过数据中台的验证服务接口，对提交的数据进行结构正确性验证。验证通过后，对提交的数据进行存储和处理。处理完成后，通过系统的流程引擎，进行内部的编校审流程。流程结束后，会将数据推送至数据中台。

# 3.4系统技术架构

3.4系统技术架构系统服务端支持部署在windows系统中，整体采用B/S架构，后端基于.net framework进行开发，采用MVC(Model- View- Controller)体系架构，充分运用WebService的应用技

术，充分考虑身份认证、访问控制、保密性、可用性、完整性、不可否认性等安全因素，为系统的安全运行提供可靠的保障。

- 部署层：Windows Server 操作系统，提供硬件资源调度与系统安全基础；- 服务器层：IIS 服务器，负责 HTTP 请求接收、站点发布与进程管理；- 应用层：基于 .net framework 开发的应用程序，包含 C# 编写的业务逻辑与功能实现；- 数据层：数据库（Mysql），存储站点业务数据与用户信息。

系统采用 MySQL 数据库作为数据库存储软件。MySQL 作为一种流行的关系型数据库管理系统，具有易用性、可扩展性和可靠性高等优点，被广泛应用于各种领域。

系统采用分表和分库等方式来存储和管理数据。根据业务需求，将数据划分为不同的数据表。并且，依据实际的业务场景以及业务需求，根据实际情况进行分库的操作，将数据分库存储到不同的库表中，保证数据库性能、和查询效率。

对查询频率或使用频率较高的表或字段，从数据库层面将会建立一套完整索引体系，提高查询效率。同时，定期监控和分析索引使用情况，进行优化调整。

另外为确保数据的安全性，将采取以下措施：

1) 户身份验证：通过 MySQL 的用户认证功能，确保只有合法用户能够访问数据库。2) 数据加密：对敏感数据进行加密存储，防止数据泄露。3) 网络安全：利用防火墙等安全设备，保护数据库服务器的网络安全。
