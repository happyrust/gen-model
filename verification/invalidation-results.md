## Observations

- `invalidate_cached` for a dbnum the view never opened (synthetic 4242) forks a new store with nothing dropped and no I/O, so the epoch still advances. Harmless; left as is (not a verified bug). `targeted_model_refresh` therefore bumps the HTTP view epoch on every polled change even for databases the HTTP face has not opened.
- "Next `view()` reopens 8000 exactly once" reads, in this design, as: `view()` never opens anything; after the damaged file is restored the reopen happens on the first element read through the view, exactly once. Asserted as such.
- Frozen-read guarantee for older views is shown on records already in the shared cache and on in-memory metadata. Pages an old engine had not yet read would come from the damaged file; that is not the E3D case (SAVEWORK appends, old pages stay valid) and is not claimed here.
- `ams7998_0001` (smallest AMS design database) has a WORL with no members at the copy's latest session, so its WORL record `16190/0` is the element read from it.
